# 文案工坊逐项修复实施记录

实施日期：2026-09-07。依据：同目录《文案工坊前后端业务闭环与客户流程审查报告》。本记录描述当前工作树已经落地的修复、仍需后续开发的边界，以及本轮自动化验证层级。

## 1. 本轮业务结果

本轮先处理会造成客户任务不执行、错用旧稿、丢失人工编辑、异步结果串稿、下游继续使用原片台词等 P0/P1 问题，并同步修正一批能够直接确定的 P2 交互语义。

客户当前可形成以下主链：

1. 工作台上传或从爆款详情导入视频，形成明确的项目与来源资产。
2. 创建持久化提取任务，由 SQLite 或 PostgreSQL Worker 领取，完成音轨提取和 ASR。
3. 离开页面或刷新后，工坊按同一项目和同一来源资产恢复原任务；迟到结果不会覆盖新草稿。
4. 客户可用当前正文和当前人物 IP 发起项目改写；人工已继续编辑时，改写结果进入候选稿，不强制覆盖。
5. 草稿按顺序写云端，页面可见“有未保存修改、正在保存、已保存、保存失败”；云端保存成功后才标记确认终稿。
6. 终稿可带入数字人口播；视频复刻会用工坊已确认终稿重新编译 Prompt，不再静默使用拆解原稿。
7. 历史口播任务可用服务端保存的正文和人物、声音、分身重新创建独立草稿。

## 3. 主要代码落点

前端闭环集中在：

- `client/src/studio/ContentPages.tsx`：爆款详情导入、提取及复刻入口。
- `client/src/studio/CreationPages.tsx`：工坊改写、候选稿、旧稿上下文恢复、限制提示、返回上一步、复刻终稿交接。
- `client/src/studio/StudioWorkspace.tsx`：顺序自动保存、可见保存状态、确认终稿、ASR 上下文保护与任务恢复。
- `client/src/studio/live.ts`：保存稿元数据映射、项目脚本发布状态、ASR 精确任务轮询、复刻终稿编译。
- `client/src/studio/state.ts`、`types.ts`、`MainPages.tsx`：来源切换失效保护、真实任务返工和跨页状态。
- `client/src/api.ts`、`client/src/generated/api.ts`：ASR 来源资产合同收紧，并从最新 OpenAPI 重新生成类型。

后端闭环集中在：

- `server/app/script_from_audio.py`、`asr.py`：入队前配置/媒体校验、任务租约、服务商回执、恢复、状态分类与临时对象处理。
- `server/app/generation_worker.py`：SQLite/PG 两条 Worker 车道消费 ASR，定期补偿清理。
- `server/app/script_rewrite.py`：AI 改写完整性与截断校验。
- `server/app/studio_drafts.py`：我的文案按最近更新时间排序。
- `server/migrations/versions/077_durable_script_from_audio.py`：ASR 回执、重试时间和项目级活跃任务唯一约束。
