## 0. 使用规则

### 0.1 状态

- `[ ]` 未开始
- `[~]` 进行中
- `[x]` 已完成并有证据
- `[!]` 阻塞

### 0.2 开发纪律

1. 新功能先写失败测试，修复先写复现测试。
2. 每项任务一个小分支或一个可独立回滚的提交。
3. 复用现有 FastAPI、React、Worker、Alembic、COS、cryptography；禁止顺手重写。
4. 不新增 Redis、Celery、Temporal、ORM、IAM、完整 billing/license 平台。
5. 每个外部调用必须有超时、错误日志和可测试的失败路径。
6. schema 变更使用 Alembic，必须有 downgrade 或明确可恢复步骤。
7. 每个里程碑必须先通过出口门，才能进入下一里程碑的真实流量。

### 0.3 交付状态

每项完成报告必须区分：

1. **代码已存在**；
2. **自动化已通过**；
3. **真实云端/Provider/签名客户端已验收**。

本地测试或 Fake Provider 只能证明前两项，不能自动升级为第三项。

## 2. M1：云基座、鉴权与激活

### M1-1 锁定现有行为

- [ ] 给项目、资产、人物、任务、上传下载和生成状态写入补回归测试。
- [ ] 列出所有直接写任务终态的入口。
- [ ] 建立 PostgreSQL 集成测试容器和测试夹具。

验收：

- 当前 SQLite 行为测试全绿；
- 可生成“SQLite 专属语法/类型清单”；
- 后续 PG 改造有回归保护。

### M1-2 PostgreSQL + Psycopg 3

- [ ] 引入 Psycopg 3 与连接池。
- [ ] 在 `db.py` 定义最小连接/Row 协议。
- [ ] 逐模块迁移 `sqlite3.Connection`、`sqlite3.Row/Error`。
- [ ] 替换 `?` 占位符和 `BEGIN IMMEDIATE`。
- [ ] 用行锁、约束和部分唯一索引表达并发规则。
- [ ] Alembic upgrade/downgrade 在 PostgreSQL 运行。
- [ ] 提供 SQLite 只读快照到 PostgreSQL 的一次性迁移 CLI，校验行数、关键哈希和抽样下载。

验收：

- 相关服务端测试全部在 PostgreSQL 执行；
- 生产代码不再依赖 SQLite 方言；
- 并发事务测试通过；
- SQLite 只保留为明确的本地迁移来源，不作为云端运行库。

### M1-3 云端存储

- [ ] 让素材、人物、首帧和成片统一走现有 `StorageAdapter`。
- [ ] 生产配置强制 COS，`local` 仅开发环境。
- [ ] 在服务端启动和保存配置时拒绝生产环境使用 `local`，不能只隐藏前端选项。
- [ ] 保留生命周期前缀：人物资产 `users/{owner_user_id}/...`，项目素材 `projects/{project_id}/...`，成片 `generation-results/{project_id}/...`。
- [ ] 下载签发前重新校验租户和 license 读取权限。
- [ ] 修正 Worker、归档重试和媒体路由中“成片固定本地盘”的代码。

验收：

- 云端 Worker 生成结果只写 COS；
- put/head/get/delete 真实 COS 测试通过；
- A 用户无法获得 B 用户对象的预签名 URL；
- EXPIRED 可下载历史，DISABLED 不可下载。

### M1-4 双鉴权域

- [ ] 实现 `DeviceUser`，替换环境变量/开发请求头业务身份。
- [ ] 实现 `ControlUser`、Argon2 密码和 `admin_sessions`。
- [ ] 管理 Cookie 使用 HttpOnly、Secure、SameSite=Strict。
- [ ] 管理写请求校验 CSRF。
- [ ] 新增 PostgreSQL `security_rate_counters`，供登录与公开激活在多 API 实例间共享限流窗口。
- [ ] 设备令牌和管理会话不能互相访问对方路由。
- [ ] 保留开发身份开关时，生产启动必须强制关闭。

验收：

- 双域全接口权限矩阵通过；
- 会话撤销立即生效；
- 密码暴力尝试会限流/锁定并审计；
- 管理角色不能通过业务依赖跨租户读取。

### M1-5 激活码与设备

- [ ] 新增 `plans`、`licenses`、`devices`、`license_events`。
- [ ] 激活码使用 CSPRNG；数据库只存哈希。
- [ ] 激活事务先 `SELECT ... FOR UPDATE` 锁 license。
- [ ] 首次绑定创建唯一用户并只赠送一次。
- [ ] 设备令牌随机 256-bit、只返回一次、数据库只存哈希。
- [ ] Rust 本机生成设备摘要，服务端再用私有密钥 HMAC。
- [ ] 实现心跳、禁用、续期和按自然年计数的换绑。
- [ ] 对公开激活按 IP 与激活码摘要双维度限流；失败写安全审计，错误响应不泄漏激活码是否存在。

验收：

- 并发激活不突破最大设备数；
- 重复激活不重复赠送；
- 激活码爆破/枚举测试触发 429，响应不能区分“不存在”和“不可用”；
- 禁用/换绑后旧令牌立即失效；
- 换绑保留原用户、项目和钱包；
- 不宣称 bearer token 已具备设备私钥证明。

### M1-6 租户隔离

- [ ] 复用 `projects.owner_user_id` 和 `person_identities.owner_user_id`。
- [ ] 给人物身份增加 `is_public_template`。
- [ ] 回填全部存量人物 owner，将 `owner_user_id` 收紧为 NOT NULL；公共模板归专用系统用户。
- [ ] 业务用户只停用不硬删除，避免人物和资产失去 owner。
- [ ] 实现并统一调用 `require_identity_access()`。
- [ ] 修正人物列表全量返回。
- [ ] 所有业务对象越权统一 404。
- [ ] 越权尝试写安全审计。

验收：

- A/B 双租户对项目、资产、人物、批次、任务、下载逐项测试；
- 列表、详情、修改、删除、生成引用均覆盖；
- 不新增重复的 `owner_license_id`。

### M1-7 客户端激活与瘦身

- [ ] 增加首次激活、已激活、到期只读、禁用和网络异常页面。
- [ ] 设备令牌保存到 Keychain/DPAPI。
- [ ] 移除 sidecar 拉起和本地 Provider 配置写入。
- [ ] 客户端设置页只保留只读运行状态、license、余额入口。
- [ ] 实现单实例锁和云端健康提示。

验收：

- 新设备无 token 时不能进入工作台；
- 到期后能查看历史但新建动作被明确阻止；
- 客户端包内和本地配置不含 Provider 密钥。

### M1-8 部署基座

- [ ] Compose 包含 Caddy、API、Worker、Supercronic scheduler 服务壳、PostgreSQL。
- [ ] 管理端静态入口和 API 域名使用 HTTPS。
- [ ] 配置健康检查、结构化日志和 request ID。
- [ ] 写 PostgreSQL 备份与恢复脚本草案。

### M1-9 出口门

- [ ] PostgreSQL 集成测试全绿。
- [ ] 并发激活测试全绿。
- [ ] 公开激活限流与防枚举测试全绿。
- [ ] 双域鉴权矩阵全绿。
- [ ] 双租户隔离矩阵全绿。
- [ ] 云端 COS 成片链路通过。
- [ ] EXPIRED/DISABLED 状态矩阵通过。

## 3. M2：计费、资金与免费配额

### M2-1 账务 schema 与不变量

- [ ] 新增 `wallets`、`wallet_transactions`、`recharge_orders`。
- [ ] 钱包只保存 available/reserved 快照。
- [ ] 流水使用 available/reserved delta。
- [ ] 为 RESERVE 建轮次部分唯一索引。
- [ ] 为 SETTLE/RELEASE 建跨类型终态部分唯一索引。
- [ ] 为 REFUND 的 `source_transaction_id` 建部分唯一索引。
- [ ] REFUND 增加 `source_transaction_id IS NOT NULL` 的 CHECK 约束。
- [ ] 写数据库级追加保护，禁止 UPDATE/DELETE 历史流水。
- [ ] 充值凭证全局唯一 `(payment_channel, external_ref)`。

### M2-2 任务级 RESERVE

- [ ] 批次创建事务中先锁钱包。
- [ ] 创建 N 个任务和 N 条 RESERVE。
- [ ] 一次更新 available/reserved。
- [ ] 余额不足返回稳定业务错误和充值引导。
- [ ] `Idempotency-Key` 防重复创建。

验收：

- 并发创建无法透支；
- 批次、任务、流水、钱包要么全部提交，要么全部回滚。

### M2-3 统一 SETTLE/RELEASE

- [ ] 实现 `finalize_billing_round()`。
- [ ] 统一或覆盖所有任务终态写入入口。
- [ ] 只有 COS 可交付成功才 SETTLE。
- [ ] 失败/取消写 RELEASE。
- [ ] 重复回调幂等返回原终态。
- [ ] 已 RESERVE/RUNNING 后 license 到期时，仍允许原任务归档并 SETTLE/RELEASE，但禁止创建新任务。

验收：

- 当前代码每个 SUCCEEDED/FAILED/CANCELLED 路径都有测试；
- 同一轮不可能同时 SETTLE 和 RELEASE；
- 归档失败不会被错误扣费。

### M2-4 重试、TTL 与对账

- [ ] 重试使用新 `billing_round`。
- [ ] 上一轮终结后才允许新 RESERVE。
- [ ] 实现冻结/租约异常扫描 CLI。
- [ ] 实现日终账本重算 CLI。
- [ ] 把 TTL 与对账 CLI 接入 M1 已建立的 Supercronic scheduler。
- [ ] 不一致时冻结该钱包新扣费并告警，禁止静默调账。

### M2-5 充值、扣费返还与调账

- [ ] 充值录单在一个事务内写订单、CHARGE、钱包和审计。
- [ ] V1 REFUND 只支持对原 SETTLE 全额返还已扣条数。
- [ ] `source_transaction_id` 防止同一 SETTLE 重复返还。
- [ ] 服务层校验来源为同一 license 的 SETTLE 且返还条数完全相等；并发请求由数据库唯一约束拦截。
- [ ] 现金退款明确留在财务线下流程，不与钱包 REFUND 混用。
- [ ] ADJUST 需要管理员、二次认证、原因和幂等键。
- [ ] 负向调账不得产生负余额。

### M2-6 免费配额

- [ ] 新增 `quota_counters`。
- [ ] 本地校验完成、外部 Provider 调用前原子消费。
- [ ] Provider timeout/5xx 仍计入。
- [ ] 本地校验/鉴权/限流失败不计入。
- [ ] 日界线统一 Asia/Shanghai。

### M2-7 客户端余额

- [ ] 增加可用、冻结余额。
- [ ] 增加分页流水。
- [ ] 余额不足、到期、禁用显示不同引导。
- [ ] 不展示或推导账本中不存在的“总资产”。

### M2-8 出口门

- [ ] 账务并发与幂等测试全绿。
- [ ] 所有任务状态路径账务测试全绿。
- [ ] 任务运行中 license 到期的 SETTLE/RELEASE 竞态测试全绿。
- [ ] 从流水重建钱包与快照完全一致。
- [ ] 充值/扣费返还/调账审计完整。
- [ ] 配额并发测试不突破上限。
