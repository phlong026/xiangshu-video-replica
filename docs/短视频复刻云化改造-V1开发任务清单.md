## 0. 使用规则

### 0.1 状态标记

| 标记 | 含义 |
| --- | --- |
| `[x]` | 已完成，且证据路径（测试名 / commit / 截图）已填写 |
| `[~]` | 代码或局部实现已存在，但未达到本任务验收标准 |
| `[ ]` | 未开始或无可验证实现 |
| `[!]` | 依赖外部资源（域名、VPS、真实凭证、运营拍板），代码无法先行 |

### 0.2 开发纪律

继承桌面端清单纪律：

1. 写一个失败的回归/契约测试（先红）；
2. 用最小改动实现（先绿）；
3. 跑目标测试；
4. 跑相关 lint、类型、格式、构建和安全检查；
5. 查看完整 diff，确认没有覆盖他人未提交改动；
6. 一个逻辑变更一个中文提交。

本清单额外两条：

7. **账务任务（M2-*）的测试一律用真实数据库事务跑**，不得用 mock 绕过唯一约束与行锁验证——账务正确性的凭据就是约束本身；
8. **每个任务合并前对照架构方案对应章节逐条核对**，发现方案与本清单验收不一致时，先改架构方案（评审）再改代码，不允许"代码先行、文档补写"。

### 0.3 合规红线（不可违反，来自架构方案 §2.2 / §4.4 / §5.6）

| 红线 | 出处 | 违反后果 |
| --- | --- | --- |
| 密钥永不落地：metaso/apilio/cos/deepseek 密钥只存在云端数据库（加密）与云端进程内存 | §2.2-1 | 密钥随安装包分发即失控，计费无从谈起 |
| 余额真源在云端：扣费校验、冻结、结算全部发生在云端事务内 | §2.2-2 | 客户端可篡改余额，直接资损 |
| 执行在云：所有 Provider 调用由云端 Worker 发起 | §2.2-3 | 破解客户端即可绕过计费闸 |
| `wallet_transactions` 只追加，禁止任何 UPDATE/DELETE | §4.4 | 账务不可审计，对账体系失效 |
| 业务幂等（user/project/key 三元组）与账务幂等（license/key/type）两套命名空间不得共用列或校验分支 | §4.4 B5 | 混用即串账 |
| SETTLE 挂 `status` 转 SUCCEEDED 分支，与 `archive_status` 无关 | §4.5 M15 | 等归档扣费会造成永久占额，扣了不给片会造成客诉 |
| §5.6 隔离测试不得延后到 M4 | §5.6 | 第二个客户上线即泄露 |
| 激活自动创建的 employee 用户 `password_hash` 为 NULL 且登录接口显式拒绝 | §5.3 M13 | 空密码绕过 = 管控面裸奔 |

## 3. 里程碑 M1：云基座 + 激活闭环

### M1-1 数据库 PG 切换与方言清理

- 依赖：D6 拍板。内容：
- [ ] `db.py` 连接层与 alembic `url` 切 PostgreSQL（连接串走 env，不入库不入仓）；
- [ ] 全库 SQLite 方言扫描并清理：领任务 SQL 的 `datetime(locked_until)`（PG 无此函数，改为 timestamp 直接比较）、`PRAGMA`、`ON CONFLICT` 子句、部分索引语法、`||` 与 NULL 语义差异（架构 §5.5 F5）；
- [ ] migration 001-021 在空 PG 库从零可跑通；
- [ ] 领任务 SQL 在 PG 下的执行计划确认仍走租约索引（热路径，架构 §5.4 M18 的前置保护）。

**验收标准**：
1. `server/tests/` 全量测试在 PG 连接下绿色通过（测试库用独立 schema，跑前重建）；
2. `grep -rn "datetime(" server/app --include="*.py"` 在 SQL 字符串上下文零命中（Python 侧 datetime 类型使用除外）；
3. 空 PG 库 `alembic upgrade head` 一次成功；回滚脚本可干净 `downgrade base`；
4. Worker 双实例同跑 10 分钟无孤儿任务、无重复执行（租约语义在 PG 下等价，架构 §1.3-2）。

### M1-2 部署形态与 HTTPS 基座

- 依赖：M1-1、D9（域名与 VPS）。内容：
- [ ] `docker-compose.yml`：caddy（自动 HTTPS）/ api / worker（`--idle-seconds 1`）/ postgres:16 四容器；
- [ ] `VIDEO_REPLICA_SETTINGS_KEY` 经 secret 注入，不写入 compose 文件与镜像；
- [ ] 每日备份任务（复用 `backup.py` 思路）产出 PG dump + 异地副本；**Fernet 主密钥与数据库备份分离存放**（备份只含密文）。

**验收标准**：
1. 全新 VPS 上 `docker compose up -d` + 域名解析后，`https://<域名>/api/health` 返回 200 且证书有效；
2. api 容器内执行任意业务路由可达；worker 容器日志显示正常领任务循环；
3. 备份产物落盘且恢复到临时库后 `alembic current` 与源库一致；
4. 镜像与 compose 文件扫描无任何密钥明文（CI secret 扫描通过）。

### M1-3 双鉴权域与云端安全基线

- 依赖：M1-2。内容（架构 §5.3 M13）：
- [ ] `auth.py` 依赖分层：`get_current_device_user()`（仅 X-Device-Token）挂 `/api/*`；`get_current_admin_user()`（仅管理端会话令牌）挂 `/api/control/*`；`get_current_user()` 废弃为内部实现，不再被路由直接引用；
- [ ] users 表加 `password_hash` 列迁移；登录接口显式拒绝 `password_hash IS NULL`；`POST /api/control/auth/login` 带限流；
- [ ] `main.py` 删 `require_loopback_client`；CORS origins 改云端域名 + Tauri origin，`allow_headers` 增加 `X-Device-Token`；
- [ ] `VIDEO_REPLICA_ALLOW_DEV_IDENTITY_HEADER` 云端排除 + bootstrap 启动自检（非 dev 检出即拒绝启动）。

**验收标准**：
1. 契约测试：无 token 访问 `/api/projects` → 401；
2. 契约测试：管理端令牌访问 `/api/projects` → 401；设备令牌访问 `/api/control/*` → 401（双域互不回退，架构 §5.3）；
3. `password_hash IS NULL` 的账号登录 → 显式业务错误（非 500、非成功）；
4. 容器 env 中注入 `VIDEO_REPLICA_ALLOW_DEV_IDENTITY_HEADER=1` 时 api 启动失败且日志指明原因；
5. 浏览器预检（OPTIONS）响应头包含 `X-Device-Token`；
6. 原 loopback 中间件代码已删除（grep 零命中）。

### M1-4 激活码域与设备接口

- 依赖：M1-3。内容（架构 §3）：
- [ ] §6 DDL 迁移：`plans` / `licenses` / `devices` / `wallets`（空壳，随 license 首次激活幂等创建）/ `wallet_transactions`（M1 只建表不接业务）；
- [ ] `POST /api/public/activate`：校验码有效/未禁用/未过期/槽位未满 → 单事务建 device + wallet + user（`license_<code_hash[:8]>`，role=employee）+ license 转 ACTIVE + 赠送 CHARGE（仅首次激活，F6）；返回 device_token（256 bit，服务端存哈希）；
- [ ] `POST /api/device/heartbeat`：更新 `last_heartbeat_at`；license/device 非 ACTIVE → 403 `LICENSE_DISABLED`；
- [ ] 激活接口限速：每 IP + 每码 10 次/小时；
- [ ] 换绑：旧行翻 DISABLED（tombstone），重激活插新行，`rebind_count` 递增，超 3 次/年拒绝。

**验收标准**：
1. 激活成功后四表（devices/wallets/users/licenses.status）原子一致——人为在事务中段抛错验证全部回滚；
2. 同码第二台设备激活（max_devices=1）→ 409 槽位类业务错误；
3. 重激活（换绑后）不再发放赠送且不报错（gift 幂等静默跳过，F6）；
4. 管理端禁用 license（直接 UPDATE 测试库）后，下一个带 token 请求 → 403 `LICENSE_DISABLED`；
5. 部分唯一索引 `uq_devices_active_fingerprint` 生效：同 license 同指纹两行 ACTIVE 被拒、一行 DISABLED 后可再插；
6. 限速：同 IP 第 11 次激活尝试 → 429；
7. `wallet_transactions` 全表在 M1 结束时仅有 gift 行，无任何业务动账（M2 前不动账）。

### M1-5 客户端激活与瘦身

- 依赖：M1-4。内容（架构 §3.3/§3.4/§5.4）：
- [ ] Tauri Rust 层指纹采集：`machine-uid`（MachineGuid/IOPlatformUUID）+ `sysinfo`（主板序列号），经 Tauri command 暴露，**原始值不进前端 JS**；
- [ ] 激活页 UI（输码 → 激活 → 显示套餐/余额快照）；Rust `keyring` crate 持久化 device_token；
- [ ] `client/src/api.ts` 全请求带 `X-Device-Token`；`VITE_API_BASE_URL` 指向云端；
- [ ] 删除 `client/src-tauri/lib.rs` 的 sidecar 拉起逻辑（TcpStream 探测 + spawn 整块删除）；
- [ ] 断网/云端不可达时提示（不做离线快照，D8）。

**验收标准**：
1. 未激活状态访问任何业务页面 → 全部请求 401，UI 停留在激活页并给出引导文案；
2. 激活成功 → 全流程（项目/人物/生成，Fake Provider）可用；重启应用免重新输码；

5. Windows 与 macOS 各一台真机激活成功（指纹两条路径都验证，OEM 读不到主板序列号的机器走主因子，架构 §3.5）。

## 4. 里程碑 M2：计费闭环

### M2-1 计费域迁移

- 依赖：M1-9。内容（架构 §6）：
- [ ] `generation_tasks` 增列：`license_id`、`billing_round INTEGER NOT NULL DEFAULT 1`、`actual_cost`（现状不存在，B6）；
- [ ] `generation_batches` 增列 `license_id`；`audit_logs` 增列 `license_id` + 索引（F4）；
- [ ] `recharge_orders` 表 + `uq_recharge_orders_ref` 部分唯一索引（F3）；
- [ ] `estimated_cost` 改服务端由 `plans.unit_price_fen` 推导覆写，永不采信客户端传值（B6）。

**验收标准**：
1. 三组唯一约束在 PG 中就位且可拦截违规写入：`UNIQUE(task_id, billing_round, type)`、`UNIQUE(license_id, idempotency_key, type)`、`uq_recharge_orders_ref`；
2. 构造客户端伪造 `estimated_cost_snapshot=0.01` 的重生成请求 → 落库值仍为套餐推导值；
3. 迁移可回滚（`downgrade` 干净）。

### M2-2 批次创建扣费（RESERVE）

- 依赖：M2-1。内容（架构 §4.5 API 层）：
- [ ] `create_generation_batch` 事务内：锁 wallet 行（`SELECT ... FOR UPDATE`）→ `available >= N` 校验 → `available -= N; reserved += N` → 写 1 行聚合 RESERVE（amount=N，挂 batch_id，`batch:` 幂等键）→ 建批次 + N 个 PENDING 任务（billing_round=1，写 license_id）；
- [ ] 余额不足 → 402 `BALANCE_INSUFFICIENT`；
- [ ] 同幂等键重复提交命中现有业务幂等分支返回原批次，不重复冻结。

**验收标准**：
1. 并发 10 个请求同钱包（余额仅够 1 批）：恰好 1 个成功，9 个 402，钱包不透支（事务级测试，非 mock）；
2. 同 idempotency_key 重放 → 返回原批次 ID，`wallet_transactions` 仍只有 1 行 RESERVE；
3. 402 响应体含可引导字段（前端可据此弹充值引导）。

### M2-3 终态钩子（SETTLE / RELEASE）

- 依赖：M2-2。内容（架构 §4.5）：
- [ ] SETTLE 钩子挂 `generation.py::_store_and_finalize_archive` 的 **status 落 SUCCEEDED 分支**（M15：与 archive_status 无关）；
- [ ] FAILED → RELEASE（`mark_task_provider_failed` 落点）；CANCELLED 未提交 → RELEASE（取消能力本身见 D11）；
- [ ] `reconcile_submission_uncertain_task`：判正 → SETTLE；判负 → RELEASE。

**验收标准**：
1. 任务 SUCCEEDED + `archive_status='ARCHIVE_FAILED'` → 照常 SETTLE（不等归档）；随后归档重试成功 → 不再落账（唯一约束拦截验证）；
2. FAILED 任务 → reserved 自动减回 available；
3. 同一任务同轮第二次 SETTLE / RELEASE 写入被 `UNIQUE(task_id, billing_round, type)` 拒绝（直接 SQL 注入式测试）；
4. SUBMISSION_UNCERTAIN 两个 reconcile 分支的账务方向正确（复用现有对账测试基建扩展）。

### M2-4 重试轮次账务

- 依赖：M2-3。内容（架构 §4.5）：
- [ ] RETRY：当轮已 RELEASE → `billing_round+1` + 重新 RESERVE amount=1（余额不足则 402 拒绝重试，防透支）；
- [ ] CONFIRM_NOT_CHARGED：RELEASE + 回 PENDING + round+1 + **立即重新 RESERVE**（F2：禁止裸奔进新轮）；余额不足 → 任务挂起并通知，不得进 Worker；
- [ ] REGENERATE：按新批次走 M2-2 全流程，无减免；`AUDIO_QUALITY_FAILED` 强制走此路径。

**验收标准**：
1. 同一任务 3 轮重试（FAIL→RETRY→FAIL→RETRY→SUCCEEDED）后：恰好 1 行 SETTLE + 2 行 RELEASE + 2 行任务级 RESERVE + 1 行批次级 RESERVE，钱包守恒；
2. CONFIRM_NOT_CHARGED 后任务的新轮在 wallets 有对应冻结（reserved 含该份额），SUCCEEDED 后守恒；
3. 余额 0 时 RETRY → 402，任务不回 PENDING；
4. 音质失败任务走免费 RETRY → 409 `REQUIRES_PAID_REGENERATION`（现有守卫保持，回归确认计费侧不破坏）。

### M2-5 冻结 TTL 与对账任务

- 依赖：M2-3。内容（架构 §4.5 M14 / §4.6）：
- [ ] 日终任务四件套：钱包守恒式重算、批次级三条断言（冻结侧/收尾侧/防多扣，F1）、冻结 TTL 扫描（24h，`plans` 可覆写）、幂等键跨租户抽检；
- [ ] TTL 处置：释放前**必查 Provider 状态**（复用 reconcile）——已出片走 SETTLE，否则 RELEASE + 任务 FAILED（`BILLING_RESERVE_EXPIRED`）+ 批次 NEEDS_ATTENTION + 告警；
- [ ] 漂移/异常 → 管理端通知 + audit_logs。

**验收标准**：
1. 构造卡在 QUEUED 超 TTL 的任务 → 自动 RELEASE 且任务标 `BILLING_RESERVE_EXPIRED`；构造同状态但 Provider 侧已出片 → 走 SETTLE 不误伤；
2. 人为篡改 wallets 余额列制造守恒漂移 → 日终任务告警并给出差额；
3. 构造批次 quantity=3 但只有 2 个任务收尾 → 收尾侧断言捕获并进人工对账队列；
4. 构造两个 license 用同一 idempotency_key 的历史脏数据 → 跨租户抽检告警（该场景正常路径已被 B5 约束阻止，抽检是兜底）；
5. 全部为幂等任务：重跑日终脚本不产生重复告警/重复动账。

### M2-6 资金操作（CHARGE / ADJUST / REFUND / EXPIRE）

- 依赖：M2-1。内容（架构 §4.4）：
- [ ] 充值录单接口：录单 → CHARGE（`recharge:` 幂等键）；
- [ ] ADJUST：正负皆可；负向同事务校验 `available + amount >= 0`，不足返回业务错误 + 可调上限（M23）；必填 reason + audit_logs；
- [ ] REFUND：管理端对 NEEDS_ATTENTION/客诉，每 round 至多 1 次（唯一约束防双退）；
- [ ] EXPIRE：仅预留实现位（V1 永久，D4），定时任务不启用。

**验收标准**：
1. 负向 ADJUST 超额 → 返回 422 类业务错误含"可调最大额度"，**不抛 500**（PG CHECK 兜底前的应用层拦截）；
2. 同一 task 同轮第二次 REFUND 被唯一约束拒绝；
3. 所有资金动作在 audit_logs 有留痕（缺 reason 的 ADJUST 被拒）；
4. 各类型对 wallets 三列的增量符合 §4.4 增量表（参数化测试覆盖 7 种类型）。

### M2-7 余额接口与前端展示

- 依赖：M2-2 / M2-6。内容：
- [ ] `GET /api/wallet/balance` + `GET /api/wallet/transactions`（按当前 license 过滤，分页）；
- [ ] 客户端余额卡片（available / reserved 展示）；402 → 充值引导（联系运营文案，V1 无支付网关）。

**验收标准**：
1. L1 查流水只见本 license 行（并入租户隔离回归）；
2. 扣费后余额快照在批次详情响应中即时反映；
3. 402 引导弹窗出现且可关闭不阻塞其他页面。

### M2-8 M2 出口 Gate

- [ ] §7 M2 行验收逐条演练：并发不透支、多轮不卡死、FAILED 自动释放、守恒零漂移、付费重生成扣费、双 license 撞键互不干扰、负向调账业务错误、ARCHIVE_FAILED 照常 SETTLE、TTL 释放不误伤、批次三断言零误报；

## 6. 里程碑 M4：生产加固

### M4-1 per-license 并发公平配额（M18）

- 依赖：M3-8。内容：领任务 SQL 增加相关子查询（该任务所属 license 在途数 < 配额），保留租约条件；配额值按 M3 报表校准。
