## 一、双轨数据对账 SQL（生产 PG，只读）

镜像关系（`server/app/characters.py` `sync_legacy_character_domain`）：
`characters.id` → `person_identities.id = 'legacy-identity:' || id`、
`character_personas.id = 'legacy-persona:' || id`，并落一条
`provider='legacy-write-through'` 的 `character_versions`。

```sql
-- 1. 旧轨存量规模（为 0 则旧轨本就无历史数据，可直接进第二步）
SELECT count(*) AS legacy_characters FROM characters;

-- 2. 镜像完整性：旧轨行未生成新轨 identity 的（>0 需先补跑镜像再下线）
SELECT c.id, c.name, c.created_at
FROM characters c
LEFT JOIN person_identities pi ON pi.id = 'legacy-identity:' || c.id
WHERE pi.id IS NULL
ORDER BY c.created_at;

-- 3. 镜像一致性抽检：名称/授权范围漂移的行（人工核对是旧轨新还是新轨新）
SELECT c.id, c.name AS legacy_name, pi.display_name AS identity_name,
       c.is_active, pi.status
FROM characters c
JOIN person_identities pi ON pi.id = 'legacy-identity:' || c.id
WHERE c.name IS DISTINCT FROM pi.display_name
   OR (c.is_active AND pi.status <> 'ACTIVE')
ORDER BY c.updated_at DESC
LIMIT 50;

-- 4. 主选表形态分布：character_id 旧形态存量（第二步收敛前必须为 0 或可接受清 NULL）
SELECT
  count(*) AS total,
  count(*) FILTER (WHERE character_id IS NOT NULL) AS legacy_form,
  count(*) FILTER (WHERE character_id IS NULL AND character_version_id IS NOT NULL) AS version_form,
  count(*) FILTER (WHERE character_id IS NULL AND character_version_id IS NULL) AS empty
FROM project_main_characters;

-- 5. 旧形态主选的兼容版本回填是否成功（>0 说明 003 时代兼容查询没找到版本，
--    下线旧分支前需人工为这些项目重选）
SELECT pmc.project_id, pmc.character_id, pmc.character_version_id
FROM project_main_characters pmc
WHERE pmc.character_id IS NOT NULL AND pmc.character_version_id IS NULL;

-- 6. 新轨孤儿确认（预期大量存在，属正常——新轨创建不回写旧轨；
--    记录数量仅作下线后回归基线）
SELECT count(*) AS new_track_personas_without_legacy
FROM character_personas cp
WHERE cp.id NOT LIKE 'legacy-persona:%';
```

**通过标准**：#1=0（直接过）；或 #2=0 且 #4 的 legacy_form 全部满足
`character_version_id IS NOT NULL`（旧形态行已有可迁移落点）且 #3 人工
核对无未决漂移。

## 二、生产流量核查清单（下线写路由前）

1. **旧轨写端点流量**（nginx/access log 或网关日志，近 90 天）：
   - `POST /api/characters`、`PATCH /api/characters/*`、
     `DELETE /api/characters/*` 的非 4xx 请求数 —— 通过标准：**0**。
   - 若日志不可按路径聚合，用 `audit_logs` 旁证：
     `SELECT action, count(*) FROM audit_logs WHERE action LIKE 'character.%' AND created_at > now() - interval '90 days' GROUP BY 1;`
     （旧轨写操作带 character.* 审计动作；新轨是 person_identity.*/character_version.*）
2. **PUT main-character 的旧形态流量**：请求体不落日志，改用表侧证据——
   每周跑一次第一节 #4，`legacy_form` 连续 4 周无新增即为旧形态已无在途
   调用（存量行 `selected_at` 老于 90 天一并确认）。
3. **桌面客户端版本覆盖**：确认 updater 推广率（线上最低版本是否已 ≥
   只发 version 形态的客户端版本）；无法确认时，在第 2 项观察期延长一倍。
