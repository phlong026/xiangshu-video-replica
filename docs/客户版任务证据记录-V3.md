### 验收证据

#### 开发计划结论一致性

- 计划 §1 明确："这不是在现有系统上补几个页面……本轮扫描到当前运行层有 33 个模块直接依赖 `sqlite3`……客户版必须先完成 PostgreSQL 运行迁移，再建设激活码、设备/session、公平队列和多实例"
- 排期模型：95–165 人日基础工程量 → 风险预留后 110–185 人日管理；推荐配置 2 后端 +1 前端/Tauri+1 QA+0.5–1 OPS
- 车道划分：A(DB/账务)/B(设备认证)/C(Worker/队列)/D(客户前端)/E(安全部署)
- 里程碑 M0–M6 定义清晰，尤其 M0/M1 出口门约束后续功能开发顺序

## 证据维护规则

1. **状态同步**: 只在 `docs/客户版任务清单-V3.md` 更新 task status (`[ ]/[~]/[x]/[!]`)
2. **证据登记**: 每个任务对应的详细证据登记在本文件对应 section
3. **SHA 记录**: 每个 Lore 提交的完整 SHA 需记录在任务列表与本文件
4. **阻断标记**: 遇到需外部授权/资源阻塞的任务时，用 `[!]` 并在证据中记录阻塞项
