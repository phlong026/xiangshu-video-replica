## 2. 总体评价

V3 正本的业务口径基本一致：一个客户用户一个主激活码、最多两个当前有效设备、同一时刻一台在线、后续充值进入同一钱包、PostgreSQL 为多实例真源。测试规格也正确区分了 `CODE_PRESENT`、`AUTOMATED_VERIFIED`、`STAGING_VERIFIED`、`REAL_CHAIN_VERIFIED` 和 `PRODUCTION_GO`。

本轮主要问题不是缺少总体方案，而是：执行状态可能分散在多个复选框中、数量和文件名随代码漂移、内部 P0/历史 Provider 证据容易被误读为客户 V3 发布证据、创作主链和桌面发布缺少执行级工作包。上述前三类高风险一致性问题已经修正；详细工作包已写入唯一任务账本。

## 4. 详细评审

### D-H01：唯一任务状态账本

**问题**

任务清单、代码开发清单和执行计划都包含复选框或任务表。如果团队分别勾选，极易出现“代码清单完成、任务清单未完成”或没有证据仍标完成。

**处理**

- `docs/客户版任务清单-V3.md:11` 明确为唯一任务状态账本；
- `docs/客户版代码开发清单-V3.md:7` 明确其复选框只表示文件范围；
- `docs/完整客户版V3开发交付索引.md` 不再把 `.omx/` 运行时任务表列为交付正本。

**后续规则**

只有父任务出口门和子工作包证据都满足，才能在任务清单把 `[ ]` 改为 `[x]`。其他文档不得独立更新完成状态。

### D-H02：SQLite 依赖数量漂移

**问题**

原文多处写 32 个直接依赖模块，但当前 `rg` 扫描得到 33 个。硬编码数量若没有生成证据，会随代码演进快速过期。

**处理**

`docs/客户版代码开发清单-V3.md:181` 等位置统一改为“本轮扫描 33，最终以 T04/DB-02 行级清单为准”。任务关闭时必须保存文件、行号、方言和替代方式，而不是只更新总数。

### D-H03：运行时草稿不能作为 Git 交付正本

**问题**

交付索引原先把 `.omx/plans/` 下三份文件列为业务、测试和执行正本，但 `.gitignore` 明确排除了整个 `.omx/`。因此前一提交虽然能在当前机器阅读这些文件，其他 checkout 实际拿不到它们。

**处理**

测试规格已迁入受跟踪的 `docs/客户版测试与验收规格-V3.md`；业务、架构和实现正本由 `docs/客户版激活码完整开发文档-V3.md` 承接；阶段和执行计划由 `docs/客户版开发计划-V3.md` 承接。索引只引用受 Git 跟踪的交付文件。`.omx/` 可以保留指针或工作草稿，但不得再次成为唯一正本。

### D-H04：验证顺序冲突

**问题**

代码开发清单原先把 E2E、安全扫描、多实例 smoke 和文档同步放在“最后补齐”，与任务清单的测试先行、开发计划从 T03 起引入安全/OPS 相冲突。

**处理**

`docs/客户版代码开发清单-V3.md:146` 已改为“持续并行验证”：失败测试和文档跟随行为变更，安全扫描和专项评审跟随每个高风险任务，多实例 smoke 从 PG 基座后逐步增加。

### D-M01：规格通过与实现阻塞需分开

**问题**

“架构评审已通过”指的是规格曾通过评审，不代表当前代码实现满足 V3。若不拆分，容易把 planning approval 当作 merge approval。

**处理**

`docs/完整客户版V3开发交付索引.md:33` 增加“实现架构评审 `BLOCK`”，并在状态说明中明确材料就绪不等于代码完成。

### D-M02：组件证据与发布证据混用

**问题**

历史文档记录 Apilio Gemini、COS 或 H3 的局部真实调用，但环境、时间和 SHA 不统一；有些记录只验证查询样本或基础 put/head/delete。它们不能拼接成客户 V3 的真实联合链。

**处理**

`docs/真实Provider验收记录模板.md:4` 已明确“历史组件级记录”；任务清单 EXT-03 至 EXT-06 要求在同一候选 SHA 下重新形成联合证据。

### D-M03：Windows 内部 P0 与客户云版本边界

**问题**

现有 Windows 手册围绕 SQLite、桌面身份和本地 sidecar；客户 V3 则要求云端 PostgreSQL、客户 session 和安全凭据。两者安装包和数据边界不同。

**处理**

`docs/Windows内测与运维手册.md:6` 已标记为内部 P0 文档；测试规格 Gate D 增加签名客户构建和实机安装/升级/卸载门。客户版本还需由 DESK-01 至 DESK-03 输出独立证据。

### D-M04：仍缺两份执行期文档

以下文件目前尚未创建：

- `docs/客户版部署与灰度手册.md`；
- `docs/客户版验收证据包模板.md`。

当前不建议在服务器、域名、证书、PG HA 和 COS 策略未冻结时填入假配置。可以先建立结构，但实际命令、拓扑、回滚和证据索引必须在 T36/REL-01 基于真实目标环境完成。

### D-M06：内部整理完成不等于用户确认完成

任务清单原先把 T01 标为 `[x]`，但同一文档状态仍是 `READY_AFTER_USER_CONFIRMATION`。本轮已改为 `[~]`，并把“用户确认 V3 口径”写入验收出口。这样既保留已完成的内部设计与评审证据，也不会在正式确认前把规格冻结误报为已完成。

## 6. 统一任务字段模板

```text
任务/工作包
Owner / Reviewer

改动文件
失败测试或回归锁定
实现结果

证据层级
```
