## 2. 123 网盘 OpenAPI 协议基线（r1 修订：以官方语雀文档为准）

Base `https://open-api.123pan.com`；响应统一 `{code, message, data}`（code=0 成功）。
鉴权头：`Authorization: Bearer {accessToken}` + `Platform: open_platform`。
错误码：401=token 无效、429=限流（各端点 QPS 见官方限流表）、5066=文件不存在、
5113=自用下载流量不足（download_info 每日 1GB 上限）。

**Token 纪律（官方硬限制）**：颁发后有效期 **30 天**；**同一 client_id 同时最多 3 个
token 在用，多次颁发会踢旧 token 下线**。部署形态为多进程（systemd：2 个 API 端口实例 +
4 个独立 worker），进程各自颁发必然超 3 个并互相踢下线 → token 必须**全局共享**（§3.3）。

| 能力 | 接口与流程 | 要点 |
| --- | --- | --- |
| 鉴权 | `POST /api/v1/access_token` | clientID/clientSecret → accessToken（30 天）；QPS 10 |
| 上传域名 | `GET /upload/v2/file/domain` | 返回多个上传域名任选；两个上传路径都需先取 |
| 创建上传任务 | `POST /upload/v2/file/create` | body: parentFileID/filename/size/etag(**文件 md5**)；`reuse=true` 即秒传结束；否则返回 `preuploadID`+`sliceSize`+`servers` |
| 分片上传 | `POST {server}/upload/v2/file/slice` | **multipart/form-data**：preuploadID/sliceNo(从 1)/sliceMD5(分片 md5)/slice(分片流) |
| 完成上传 | `POST /upload/v2/file/upload_complete` | body: preuploadID；`completed=true && fileID≠0` 完成；false 时**轮询同一接口**（间隔 1s，有界） |
| 单步上传 | `POST {server}/upload/v2/file/single/create` | multipart，单文件 ≤1GB；filename ≤255 字符、禁 `"\/:*?|><`、不得全空格；duplicate=1 重名保留两者 |
| 取下载链接 | `GET /api/v1/file/download_info?fileId=` | 返回 `downloadUrl`；**仅用于连接测试探针与诊断，不作为客户下发通道**（自用流量 1GB/日上限，且不承担防盗链时效承诺） |
| 直链空间启用 | `POST /api/v1/direct-link/enable` | body: fileID（文件夹）；目标 folder 需启用一次（配置保存时自动尝试，幂等） |
| 获取直链 | `GET /api/v1/direct-link/url?fileID=` | 返回直链 URL；随后**服务端追加防盗链参数**（下） |

**直链防盗链签名**（官方 `123pan-link` sign 示例口径，`auth_key` 方案，规则直接固化）：

```
expire = 到期时间戳（秒）；rand = 随机串
path   = 直链 URL 的【URL 解码后 pathname】（官方示例对路径先解码再参与摘要）
md5hex = md5("{path}-{expire}-{rand}-{uid}-{sign_secret}")
auth_key = "{expire}-{rand}-{uid}-{md5hex}"
最终直链 = 保留直链 URL 既有 query（先剥离其中旧 auth_key 项），
           再以查询参数追加 auth_key={urlencode(auth_key)}
```

不做任何臆造的 URL 模板：直链一律先取 `/api/v1/direct-link/url` 再签名。签名输入用
**解码后路径**；中文/特殊字符文件名的实际行为由 spike 验证兼容性（远端文件名已做
白名单化清洗，见 §3.2，风险进一步收窄）。

**红线（官方明示）**：禁止调用非 OpenAPI 接口列表中的其余非公开接口，违者封号。客户端只
实现上表接口；任何「网页端抓包接口」一律不接。

**Spike 验证清单**（第 1 步，真实账号、探针文件即传即删、凭据只走环境变量）：

0. **官方文档原文复核**：r2 复审时官方语雀不可访问，上/下载字段与 QPS 表未完成原文
   复核——spike 开始前重取官方原文，逐项核对 §2 表格的路径/参数/QPS 后才动手；
1. access_token 获取、30 天有效期与 401 行为；
2. create/秒传/分片上传/完成轮询全链路（含 etag 不匹配时的报错行为）；
3. `/upload/v2/file/domain` 域名与 slice multipart 细节；
4. direct-link/enable 幂等性 + direct-link/url 返回结构；
5. auth_key 签名拼接（解码后路径、既有 query 保留、旧 auth_key 剥离、中文文件名）与
   **签名负例**：缺失/篡改/过期三种 auth_key 请求必须全部被拒绝，任一负例仍可读取说明
   防盗链未生效，判 spike 失败；
6. 直链 Range 支持（视频拖动）与实际 CDN 域名清单（供 CSP）；
7. download_info 探针可用性（5113 阈值实测）；8. 429 实际行为。

## 3. 架构设计

### 3.1 总体数据流

```
管理端上传（multipart, 四段契约, Idempotency-Key）
  → 流式落临时文件（sha256+md5 单遍计算，大文件不进内存）
  → Pan123Client.upload_file（domain → create → 分片 slice → complete → 有界轮询）
  → 业务事务 INSERT（remote_file_id=123pan fileID）+ 审计
  → 客户播放/下载：POST /api/training-materials/{id}/download-url
      → 服务端取直链（direct-link/url + auth_key 签名，内存 TTL 缓存）
      → 返回 {"url", "expires_at"}（响应形状与现分支兼容）
  → <video>/<audio>/<img>/PDF iframe / Office Online iframe 直接消费直链
```

### 3.2 新模块 `server/app/pan123_client.py`

- **HTTP 纪律**：全部走 `external_calls.recorded_urlopen`（`provider="pan123"`、显式
  timeout、`read_limit`、`endpoint_from_url`），`opener` 参数留测试注入缝隙；分片上传单次
  body ≤ sliceSize（有界，不违反大文件不进内存纪律）。
- **脱敏（r1 P1-1 修订）**：`external_calls._SECRET_KEYS` 新增 `auth_key`（规范化精确匹配，
  与子串掩码不同机制），覆盖 URL 查询参数、JSON 响应（downloadUrl 含 auth_key）、非 JSON
  错误正文三条路径；`time` 类普通到期参数不是凭据、不脱敏。补 URL/JSON/错误正文/持久化
  日志四类测试。
- **凭据**：来自 `SettingsRepository.load_provider_config("pan123")`（Fernet 加密存储）。
- **错误映射**：401 → 清缓存重取一次（受限单次）→ 仍失败 Pan123AuthError；429/5xx/网络 →
  Pan123Unavailable；5066 → Pan123FileMissing（路由映射 404）。

### 3.3 Token 全局共享（r1 P1-4 修订）

- 新表 `provider_runtime_state(provider TEXT, state_key TEXT, encrypted_value TEXT,
  updated_at TIMESTAMPTZ, PK(provider, state_key))`（新迁移，见 §3.5）：值存 Fernet 加密的
  `{"client_id": ..., "access_token": ..., "expires_at": ...}`——**token 与颁发它的
  client_id 绑定存证**。
- 读取顺序：进程内存（缓存项含 client_id，与当前配置不一致即弃用）→ DB 行（未过期
  **且 client_id 与当前配置一致**才可用）→ `pg_advisory_xact_lock`（对 (provider,"token")
  的键哈希）单飞刷新 → 锁内复查 DB（client_id 匹配 + 未过期）→ 颁发（带当前 client_id）
  → 写 DB → 各进程缓存。全局同时只活跃 1 个 token，规避官方 3-token 上限与互踢。
- **配置切换原子失效**：保存 pan123 配置的护栏函数（§3.4，两个入口共用）在同一事务里
  `DELETE FROM provider_runtime_state WHERE provider='pan123'`——旧账号 token 与新配置
  永不并存；进程内存缓存因 client_id 不匹配自行失效；在途旧请求回写带旧 client_id 的
  行，下一次读取即判不匹配重取（自愈，不依赖时序）。
- 401 触发的重取同样走单飞；刷新失败不降级、直接 503。
- **直链缓存**：进程内存 dict，key=`(config_version, file_id)`；config_version 取
  `provider_settings.updated_at`（配置保存即变化）→ 同账号轮换密钥/改 folder 自动失效；
  TTL=auth_key 到期前 5 分钟。多进程各自缓存（直链无一致性要求，可接受）。
- **回归用例**：已有有效 DB token + 空素材库切换 client_id + 多进程继续请求 → 新请求
  必须以新 client_id 重新颁发，旧 token 行已清除、不再被复用（§8 单测/设置行）。

| kind（分组） | 后缀 | content-type | 预览方式 |
| --- | --- | --- | --- |
| video 视频 | .mp4 | video/mp4 | `<video controls preload="metadata">` |
| video 视频 | .mov | video/quicktime | 同上 |
| video 视频 | .webm | video/webm | 同上 |
| audio 音频 | .mp3 | audio/mpeg | `<audio controls>` |
| audio 音频 | .m4a | audio/mp4 | 同上 |
| audio 音频 | .wav | audio/wav | 同上 |
| image 图片 | .jpg/.jpeg | image/jpeg | `<img loading="lazy">` |
| image 图片 | .png | image/png | 同上 |
| image 图片 | .gif | image/gif | 同上 |
| image 图片 | .webp | image/webp | 同上 |
| doc 文档 | .pdf | application/pdf | iframe 原生（桌面壳不支持时降级下载） |
| doc 文档 | .docx | application/vnd.openxmlformats-officedocument.wordprocessingml.document | Office Online |
| doc 文档 | .doc | application/msword | Office Online |
| doc 文档 | .xlsx | application/vnd.openxmlformats-officedocument.spreadsheetml.sheet | Office Online |
| doc 文档 | .xls | application/vnd.ms-excel | Office Online |
| doc 文档 | .pptx | application/vnd.openxmlformats-officedocument.presentationml.presentation | Office Online |
| doc 文档 | .ppt | application/vnd.ms-powerpoint | Office Online |

规则与现状一致：`(后缀, content-type)` **成对登记**防混搭；kind 由 MIME 大类推导、不接受
手填；浏览器不可直接消费的格式（mkv/avi/flac 等）不进白名单。预览承诺口径
（r1 P2-2 修订）：**「支持格式按目标环境尽力预览，失败可下载」**——白名单保证容器类别
可被对应预览通道处理，不承诺任意编码/大小必然成功（Office Viewer 有大小上限、媒体编码
依赖 WebView 解码器），全部预览界面常驻下载按钮兜底。

## 6. 安全与红线对照

1. **凭据**：client_secret/sign_secret 仅存 Fernet 加密 `provider_settings`；运行态 token
   存 Fernet 加密 `provider_runtime_state`；客户端永不可见；管理端回显走 `mask_config`。
2. **日志**：`recorded_urlopen` + `redact_url`/`redact_text` 自动剥离凭据参数（`auth_key`
   纳入 §3.2）；`time` 类普通到期参数不脱敏（非凭据）；禁止打印 accessToken 与直链全文。
3. **封号红线**：只调 OpenAPI 列表内接口（§2 表），不接网页端抓包接口。
4. **直链泄露边界**：直链为「持有即访问」的公开 URL（30 分钟防盗链签名）；客户侧仍走
   download-url 按需签发，管理端直链仅运营复制分享用；用户已拍板接受。
5. **上传纪律**：四段写契约、Idempotency-Key + sha256 内容指纹、审计 `training_material.*`
   全部保持；200MB 流式上限不变；分片单次内存占用 ≤ sliceSize（有界）。

## 7. 风险与既有问题

### 7.1 微软 Office Online 依赖（用户拍板接受）

国内访问 officeapps 服务稳定性一般；文件大小有上限（MB 级）；直链 URL 会暴露给微软服务器。
降级路径：预览失败/超限 → 常驻下载按钮。

### 7.2 直链不可即时撤销

30 分钟有效期内的直链无法踢线撤销（原本地车道 epoch 机制随车道删除而移除）。兜底：短时效
+ 签发需登录 + download-url 逐次重签。

### 7.3 账号单点

123 网盘账号被封/欠费 = 素材全部不可播。用户拍板接受；软删素材对象保留在网盘（可恢复）；
连接测试可随时巡检通道健康度。

### 7.4 ⚠️ 同批修复的既有隐患：yuanbao 不在 provider_settings CHECK

`ProviderName` 含 `yuanbao` 且元宝凭据走 `provider_settings`
（`viral_wechat_link.py:452` load），但 DB CHECK 白名单最后一次放宽是
`20260928T1200_customer_email_password_reset`（+ses），**不含 yuanbao**——元宝功能已合
main 但未上生产，部署后管理端保存元宝配置将撞 CHECK 报 500。本次放宽迁移同批纳入
`yuanbao` 与 `pan123`；downgrade 契约见 §3.5（fail-fast + 受控清理步骤）。

### 7.5 其他

- OpenAPI QPS 限制（官方限流表）：直链服务端缓存 + 运营低频上传；429 → 503 + 日志，
  不做激进重试；
- 孤儿对象：上传成功但业务事务失败时 123pan 留无引用文件（唯一远端名、无污染）。处置
  （r1 P2-3 修订）：路由在存储成功但事务失败路径打 warning 日志（含 fileID），运维口径
  = 按日志人工清理；本期不做自动 GC；
- 图片网格直连 CDN 的流量成本：lazy loading 控制（§5.2）。
