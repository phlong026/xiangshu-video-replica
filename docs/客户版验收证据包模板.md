# 客户版验收证据包模板

> 每份证据包必须绑定一个不可变候选 SHA。截图只作辅证，命令输出、数据库事实、
> 结构化日志和产物哈希才是可复核证据。真实 secret、token、激活码、签名 URL、
> 完整第三方响应和客户个人信息必须脱敏。

## 基本信息

| 字段 | 内容 |
| --- | --- |
| 候选 SHA / PR | `<sha>` / `<url-or-id>` |
| 环境 / 时间窗 | `<environment>` / `<start-end-with-timezone>` |
| Owner / Reviewer | `<owner>` / `<independent-reviewer>` |
| 配置版本 / 迁移 head | `<config-version>` / `<revision>` |
| Web / Windows 产物 SHA256 | `<hashes>` |
| 外部授权记录 | `<none-or-authorizer/scope/time>` |
| 未测试项 | `<explicit-list>` |

## CODE_PRESENT

- [ ] 冻结文件、迁移、部署模板和手册存在。
- [ ] fail-closed、回滚点和 secret 边界有实现或明确阻塞。
- [ ] 变更文件与规格/任务映射已登记。

结论：`PASS / FAIL / NOT_RUN`。此层不能宣称系统已验证。

## AUTOMATED_VERIFIED

- [ ] 失败测试/回归锁定先红后绿，记录命令与通过数。
- [ ] PostgreSQL 集成、前端、Tauri、E2E、lint、format、typecheck 全绿。
- [ ] secret 与依赖安全扫描全绿；跳过项逐项说明。
- [ ] 客户云构建目标使用 `--no-default-features`，并注入已批准的 HTTPS
  `VITE_API_BASE_URL`；产物哈希已记录（`.invalid` 合同产物不得算 staging）。

结论：`PASS / FAIL / NOT_RUN`。本地容器、Fake Provider 和单机进程不能替代
`STAGING_VERIFIED`。

## STAGING_VERIFIED

- [ ] LB 后两个 API 的节点标识、探针与逐节点替换记录。
- [ ] 四 Worker 的唯一 worker id、领取/重启/无重复证据。
- [ ] PostgreSQL 16 HA 拓扑、TLS/私网、failover 记录。
- [ ] 私有 COS 最小权限和 put/head/get/copy/archive/delete 记录。
- [ ] 不同真实客户端 IP 经代理进入不同 PG 限流桶。
- [ ] 激活、双设备、单在线、切换、公平队列和账务不变量通过。

结论：`PASS / FAIL / NOT_RUN`。填写环境资源 ID 的脱敏值、时间线、指标与
失败注入结果；没有真实类生产拓扑时必须填 `NOT_RUN`。

## REAL_CHAIN_VERIFIED

- [ ] 有明确授权，记录授权人、范围、最高金额/调用次数和失效时间。
- [ ] 同一 SHA 完成真实激活首充、最低额 ZPay 与回调对账。
- [ ] 真实 COS 与分析/图像/人物/H3 Provider 成功、失败、限流、超时和
  `SUBMISSION_UNCERTAIN` 路径完成。
- [ ] RESERVE 最终唯一进入 SETTLE 或 RELEASE，钱包与 append-only 账本差额为零。

结论：`PASS / FAIL / NOT_RUN`。历史样本和不同 SHA 的截图不得拼接放行。

## PRODUCTION_GO

- [ ] T37 告警、T38 PITR、T39 故障演练均通过。
- [ ] Windows 签名与安装/升级/卸载实机通过。
- [ ] T41 先 10 码、后 100 码，并完成规定观察窗。
- [ ] 回滚、值班、客服、账务、合规与业务批准齐全。
- [ ] 独立 Verifier 签字并记录最终 Go/No-Go 决议。

结论：`GO / NO-GO`。只有本节为 `GO` 才能称完整客户版正式开放。
