## 二、访问通道

SSH 22 对外不通,两条路:

1. **TAT 自动化助手**(主通道,读写均可):console.cloud.tencent.com/cvm/command → 免密 root、输出在执行详情可展开读取。**注意可能触发短信 MFA(188****1681,触发时机不定)**。
2. **OrcaTerm 网页终端**(应急写入):实例列表 → 登录 → 免密连接;画布输出不可读,只用来应急敲命令,不做结果读取。

**长任务模式**:TAT 命令默认 60 秒超时,创建命令时把超时调大;超过 TAT 时长的部署用 `nohup ... > /tmp/xxx.log 2>&1 &` 后台启动,再用后续 TAT 命令 `tail` 日志轮询。脚本自带 `.status` 状态文件可查阶段(PREFLIGHT/BACKUP/BUILD/MIGRATE/ROLL_API/ROLL_WORKERS/SITE/VERIFY/SUCCESS)。

**TAT 控制台浏览器自动化要点**(供自动化会话复用):

- 创建命令对话框类名 `.sdk-iaas-automation-dialog`,命令内容编辑器是 CodeMirror(`.cm-content`),用 `focus + execCommand('selectAll') + execCommand('insertText', content)` 注入;「创建命令」按钮偶发点击无效,用 `dispatchEvent(new MouseEvent('click', {bubbles:true}))` 重试。
- 执行流:命令行内「执行」→ 跳转执行设置页 → 勾选实例行 checkbox → 「执行命令」→ 跳转执行详情页 → 点 `.sdk-iaas-automation-table__icon-wrap` 展开行读输出。

## 三、标准增量部署流程

前提:目标 commit 已合入 `live`(phlong026/xiangshu-video-replica)main;本地已 `git fetch live` 并核对增量(提交清单 + `git diff --stat`)。

### 第 1 步:部署前核查(TAT 只读命令)

```bash
docker ps --format '{{.Names}} | {{.Image}} | {{.Status}}' | grep video-replica | sort
grep -n 'image:' /opt/video-replica-candidate/compose.yaml
ls -1 /opt/video-replica-candidate/releases/
git -C /opt/video-replica-candidate/releases/<当前sha> log -1 --format='%H'
docker compose -f /opt/video-replica-candidate/compose.yaml exec -T db sh -lc \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Atc "SELECT version_num FROM alembic_version"'
curl -fsS https://video.zszhj.cn/health
df -m /   # rollout 预检要求根分区剩余 > 4GB
```

**迁移前余额快照**(部署后比对):

```sql
SELECT u.username, w.available_credits, w.reserved_credits
FROM wallets w JOIN users u ON u.id=w.user_id WHERE u.username='peihuorong';
SELECT COALESCE(SUM(available_credits),0), COALESCE(SUM(reserved_credits),0), COUNT(*) FROM wallets;
```

### 第 2 步:本地预检(在仓库检出里做,不过网络)

- `server/pyproject.toml`、`server/uv.lock` 与当前生产镜像相比**必须无变化**(rollout 按设计硬门禁,变了要走基础镜像发布流程);
- `scripts/customer_release_preflight.py` 是否变化(有无新增必填环境变量);
- `client/package.json`/`package-lock.json` 变化时,构建期 npm ci 需要外网;
- 新迁移逐个人工过一遍:只允许 DDL(建表/加列/索引/触发器)与向**新表**的种子写入,任何触碰存量资金表的 DML 都要单独评审;
- rollout 脚本内的硬断言(模块 import、openapi 路径)在新代码里逐条确认。

### 第 3 步:把目标 commit 送上服务器(deploy key SSH,约 1 分钟)

服务器 `/root/.ssh/config` 已把 github.com 映射到 `ssh.github.com:443`(IdentityFile `/root/.ssh/deploy_ed25519`,只读 deploy key)。在新 release 目录上:

```bash
SHA=<40位目标sha>
SRC=/opt/video-replica-candidate/releases/$SHA
if [ ! -d "$SRC/.git" ]; then
  mkdir -p "$SRC"
  git -C "$SRC" init -q
  git -C "$SRC" remote add origin git@github.com:phlong026/xiangshu-video-replica.git
fi
git -C "$SRC" config url."git@github.com:".insteadOf "https://github.com/"
git -C "$SRC" config uploadpack.allowAnySHA1InWant true
git -C "$SRC" fetch --depth=1 origin $SHA
git -C "$SRC" checkout -q --detach --force FETCH_HEAD
git -C "$SRC" update-ref refs/heads/deploy-pin $SHA   # 让 SHA 成为可广告的 ref
```

> HTTPS 直连 GitHub 会 GnuTLS 断连/hang,不要用;SSH-443 全树快照约 45 秒。

### 第 4 步:执行 rollout(后台 + 轮询)

```bash
cd /opt/video-replica-candidate
CUSTOMER_COMPOSE=/opt/video-replica-candidate/compose.yaml \
VIDEO_REPLICA_GIT_REPO_URL='git@github.com:phlong026/xiangshu-video-replica.git' \
nohup bash /opt/video-replica-candidate/uploads/customer-direct-rollout.sh \
  --commit $SHA > /tmp/rollout-<短sha>.log 2>&1 &
```

**三处必须一致**(见踩坑 #1):release 目录 `remote get-url origin` 的显示值、环境变量 `VIDEO_REPLICA_GIT_REPO_URL`、若配了 insteadOf 改写则存储 URL 也要换成改写后的形式。

脚本自动完成:预检 → 备份(compose/静态站/管理站/**pg_dump -Fc 全库**)→ compose 旧→新镜像 tag 替换 → `alembic upgrade head` → api 逐个滚动 → worker 逐个滚动 → 前台/管理站发布 → VERIFY(容器镜像标签、bundle hash、health、openapi 路径断言)。

### 第 5 步:补滚 worker-publish + 部署后验证

rollout 脚本的 SERVICES 清单**不含 worker-publish**,成功后手动补:

```bash
docker compose -f /opt/video-replica-candidate/compose.yaml up -d --no-deps worker-publish
```

> 必须传**服务名** `worker-publish`,传容器名 `worker-publish-1` 会报 no such service。

验证清单:

```bash
docker ps --format '{{.Names}} | {{.Image}} | {{.Status}}' | grep video-replica | sort   # 全部新 tag
docker exec -w /opt/video-replica/server -e PYTHONPATH=/opt/video-replica/server \
  $(docker ps -q --filter name=video-replica-candidate-api-1) \
  python -c "from app.main import app; print(app.version)"                                # 版本串
curl -fsS https://video.zszhj.cn/health
curl -fsS https://video.zszhj.cn/customer | grep -oE 'assets/index-[^"]+\.js'            # 新 bundle
curl -fsS https://video.zszhj.cn/admin/ | grep -oE 'assets/admin-[^"]+\.js'              # 新 admin bundle
```

外部(本机)再独立 curl 一遍 health + bundle hash,排除服务器本机缓存因素。

**资金对账三查**(结果必须全 0):

```sql
-- 钱包余额 vs 流水重放
SELECT count(*) FROM wallets w LEFT JOIN (
  SELECT user_id, SUM(available_delta) a, SUM(reserved_delta) r
  FROM wallet_transactions GROUP BY user_id) l ON l.user_id=w.user_id
WHERE w.available_credits <> COALESCE(l.a,0) OR w.reserved_credits <> COALESCE(l.r,0);
-- PAID 订单必须有 CHARGE 流水
SELECT count(*) FROM recharge_orders o WHERE o.status='PAID' AND NOT EXISTS
  (SELECT 1 FROM wallet_transactions wt WHERE wt.recharge_order_id=o.id AND wt.type='CHARGE');
-- CHARGE 流水必须对应 PAID 订单
SELECT count(*) FROM wallet_transactions wt WHERE wt.type='CHARGE' AND NOT EXISTS
  (SELECT 1 FROM recharge_orders o WHERE o.id=wt.recharge_order_id AND o.status='PAID');
```

## 四、踩坑清单(每条都付出过代价)

1. **`git remote get-url` 会应用 insteadOf 改写**:显示的是改写后地址。rollout 的 `origin == REPO_URL` 校验按显示值比较——origin 存储值、`VIDEO_REPLICA_GIT_REPO_URL`、insteadOf 改写三者必须一致,否则脚本在校验点直接退出(失败发生在备份/迁移之前,干净无副作用)。
2. **必须带 `CUSTOMER_COMPOSE=/opt/video-replica-candidate/compose.yaml`**:否则 release 自带 compose 的 `${APP_IMAGE:?}` 预检直接退出。
3. **compose 端口是 8001/8002**:曾被改成 18001/18002 导致 recreate 后 502,已修回;改动 compose 端口行前先看这条。
4. **rollout 脚本不滚 worker-publish**,成功后必须手动补滚(传服务名)。
5. **服务器连 GitHub 只走 SSH-443 deploy key**,HTTPS 会 GnuTLS 断连;不要让 rollout 直接在线 fetch。
6. **Python 依赖变更 = 禁止增量 rollout**(哈希门禁),需走基础镜像发布。
7. **TAT 命令默认 60 秒超时**,长命令记得调大;长任务一律 nohup + 日志轮询。
8. **rollout 会清空站点根目录**：SITE 阶段 `find $SITE -mindepth 1 -maxdepth 1 -exec rm -rf` 会删掉 `/www/wwwroot/video.zszhj.cn/` 下所有非部署产物。桌面更新通道（stable.json + 版本目录）必须放 `/opt/video-replica/app/desktop-releases/customer-cloud/`（nginx 别名已指向此处），放站点根内会随每次发版消失（2026-10-15 实际发生）。
9. 回滚材料约定:`/opt/video-replica-candidate/backups/git-<短sha>-<时间戳>/`(compose-before.yaml、site-before.tar.gz、admin-site-before.tar.gz、database-before.dump、BACKUP-SHA256SUMS)。

## 五、回滚

增量失败时脚本自动回滚(恢复 compose、静态站、管理站;worker-viral 停机保平安)。**数据库迁移不可自动回滚**——迁移头按 forward-compatible 纪律维护(老代码能跑新库),所以回滚 = 把 compose 镜像 tag 换回旧值 `docker compose up -d`,库不动:

```bash
sed -i 's/video-replica-rehearsal-app:<新短sha>-git/video-replica-rehearsal-app:<旧短sha>-git/' \
  /opt/video-replica-candidate/compose.yaml
docker compose -f /opt/video-replica-candidate/compose.yaml up -d
```
