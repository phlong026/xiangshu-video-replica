# PostgreSQL 唯一数据库实施与验收规范

版本：V1，2026-09-08。用户已确认数据库全面统一为 PostgreSQL。本文件定义实施目标和验收边界；本轮文档更新不代表代码改造、实际数据迁移或生产切换已经完成。

任务状态以[客户版任务清单 V3](客户版任务清单-V3.md)为唯一真源；详细工作定义见[收敛任务清单 V2](../outputs/customer-cloud-convergence-analysis-2026-09-08/客户版收敛详细任务清单与验收完工标准.md)。本规范是本次 PostgreSQL 全面统一的增量合同，覆盖旧文档中“仅客户生产要求 PG”“本地开发默认 SQLite”“SQLite 业务测试可作为验收”等旧口径；原始历史测试记录保持原文。

## 1. 已确认的数据库边界

| 对象 | 目标规则 | 通过依据 |
| --- | --- | --- |
| 开发 API、Worker、管理与维护命令 | 显式连接隔离 PostgreSQL 16；开发身份和外部服务替身不能改变数据库类型 | 启动配置、连接记录、实际读写及故障验证 |
| 业务持久化、API、Worker、SQL 与并发自动化测试 | 全部使用真实 PostgreSQL 16；禁止文件 SQLite 和内存 SQLite 替代 | 逐用例映射、PG 连接/约束/事务证据、无跳过硬门 |
| CI | 真实 PG 业务门必跑；无 PG 则失败，不允许以 SQLite 成绩通过 | PG preflight、完整测试结果、禁止规则 |
| staging、生产 | 各自独立 PG 环境；API、Worker、管理、队列、钱包、配置与审计共享所属环境的唯一数据真源 | 实际节点、数据库版本、schema 与一致性证据 |
| 客户桌面 | 只经后端 API 读写业务数据，不安装 PG、不给客户端 PG DSN、不持有服务端数据库凭据 | 制品、进程、网络与用户流程验收 |
| 纯逻辑测试、前端组件与外部 Provider 替身 | 可以不连接数据库；一旦需要证明持久化/约束/事务，必须进入 PG 测试 | 测试分类与断言边界 |
| 历史 SQLite 原始数据 | 只读保护、哈希固定；按 A/B/C 决策归档或导入 PG | 来源/归属/完整性与处置签收 |
| 历史 SQLite 迁移工作副本 | 仅在独立迁移工具中做必要的离线 schema 规范化，之后生成新的只读输入快照；不承载业务写入 | 原件不变、副本演化和只读输入证据 |
| 视频图片、临时文件、系统凭据 | 持久媒体依既有 COS/DIRECT 合同；临时文件可重建；DPAPI/Keychain继续保护桌面凭据 | 不把文件或操作系统凭据存储误认为应用业务数据库 |

“全部 PostgreSQL”指本产品全部业务数据库和数据库行为测试；不要求同一数据库混放开发、测试和生产，也不要求把媒体二进制、操作系统凭据或 WebView 自身缓存塞入 PG。WebView 缓存不得被借用为业务数据真源。

## 2. 测试分类与历史例外

每个测试函数、参数化场景和公共 fixture 按以下规则分类，当前库的扫描数量只作基线，不能替代逐项映射。

| 类别 | 允许资源 | 禁止用途 | 最小证据 |
| --- | --- | --- | --- |
| TEST-LOGIC 纯逻辑 | 内存对象、mock 接口，不连接业务数据库 | 用mock证明数据库约束、行锁或提交 | 场景及依赖说明 |
| TEST-PG 当前业务数据库 | 独立真实 PG；合法客户/管理身份；外部服务可受控替代 | sqlite3.connect、SQLiteBackend、DB_PATH、SQLite :memory: | 旧用例→PG用例、实际SQL与结果、PG版本/head/隔离ID |
| TEST-IMPORT 一次性导入 | 受保护 SQLite 历史输入、PG目标和对账库 | SQLite充当目标或在线回退 | 只读原件、规范化副本、重放/失败恢复/对账 |
| TEST-HISTORY 已发布历史兼容 | 隔离历史样本；仅在TEST-IMPORT所需或已发布迁移保护范围内 | 新增当前业务的SQLite测试 | 明确历史版本、用途、责任人及保留期限 |

例外允许清单精确到文件/符号/测试，写清类别、来源版本、负责人、用途、入口隔离、保留期限或退役条件。不得把整个 server/app、server/tests 或 migration 目录设为无限制例外。已发布 revision 中的历史方言代码逐文件登记，原字节不可为清理而改写。

被删除或迁移的旧测试必须对应 PG 替代用例、已退出内部行为或 TEST-IMPORT/TEST-HISTORY 例外；未分类、无替代断言或无退出依据的条目均为 0。不以测试总数减少、把用例改成skip或把fixture替换为mock证明数据库统一。

1. CW-001/002/053固定源码、环境和全部数据库消费者；CW-005只选择历史数据处置，不能选择继续用SQLite运行。
2. CW-006登记正本/文件/任务；CW-007建立PG业务测试基座；CW-009/010用TEST-PG真实数据库与多连接锁定权限、账务和并发，外部Provider可受控替代。

## 5. 数据与schema的可判定完工条件

### 5.1 所有路线的共同要求

- 实际现有PG版本、alembic head、来源/目标、owner和数据批次已盘点；源SQLite原件哈希不变。必要规范化只能写隔离副本，新输入快照再次只读固定。
- PG副本从物理备份+WAL或批准的逻辑快照实际restore到隔离PG，记录方式、时间点/LSN/timeline（适用时）、schema/head、校验及关键业务事实。逻辑恢复不冒称PITR或HA验收。
- 带代表数据的旧PG→新head与PG空库→head均通过；已发布revision哈希不变，新增迁移只追加；不得通过改写旧migration或伪造alembic_version跳过执行。
- 导入涉及的FK以及应用实际读取的JSON/text内嵌ID全部登记。映射后owner一致、旧ID残留及孤儿数均为0；有意保留的来源标识仅进入专用血缘字段，不作为当前业务外键。
- 钱包由流水重算差额0；订单/CHARGE双向来源闭合；已确认资金事实、账单号、幂等键、任务计费轮次保留；原有序列或新映射序列均不冲突。
- serial/identity及账务序列用实际下一次写入验证新值不碰撞；检查序列值时同时考虑is_called等定义，不能把last_value必须大于MAX当作唯一判据。序列测试消耗值不等同写入业务事实，编号间隙不得被误判为资金缺失。
- 冻结额度、运行/排队/提交不确定任务有唯一处置和负责人；成功、失败及人工接管都有证据。未知付费不能自动重复POST或伪标成功。

### 5.2 A/B/C的区别

| 路线 | 目标及通过条件 | 不允许的完成声明 |
| --- | --- | --- |
| A 保留现有客户PG | 客户PG保留，必要时追加兼容schema；内部SQLite只读归档，客户与业务确认内部数据无需合入；旧内部写入口在切换窗口关闭 | 把归档写成“SQLite数据全部已导入” |
| B 导入空PG | 原件保护，受控副本规范化，PG空目标导入/重放/失败回滚通过；逐表主键集合和账务一致 | 把现有工具用于不一致的非空客户库 |
| C 合并已有客户PG | 专用映射/冲突规则；已有客户不覆盖；全部引用/序列/支付和幂等域正确重映射；目标wallet_ledger_sequence由目标PG分配，源库/源交易/源序列（包括NULL）保存不可变血缘，不能调用者指定目标流水序列或伪造未知源顺序 | 按同名自动合户、直接累加余额或照搬冲突序列 |

无历史数据时仍须有盘点与不适用记录，PG业务和schema门不能跳过。COS与DIRECT资产合同保持；SQLite行导入不代替媒体对象复制和逐对象size/hash/授权读取检查。

如果经实际盘点确认从未部署PG，可将“旧PG升级”子场景登记不适用并附依据；空PG全链和代表数据验证始终必需。不能因无法连接或缺少旧版本信息而跳过已有客户PG升级。

### 5.3 回滚

正式切换后业务数据库持续为PG。优先回退兼容代码/流量并保留前向schema；RPO/RTO按冻结目标验证。已确认支付和流水不能被旧快照覆盖或通过恢复SQLite继续经营来抹去。切换前的隔离演练可以丢弃失败副本重建；原始数据库和对象继续保护。真实库非空降级可能被审计保护拒绝，这种拒绝是预期行为，不能为追求downgrade绿灯删除资金事实。

## 7. 外部合同依据

PG批量执行可用既有psycopg3的Cursor.executemany；适配层不能把PG批量写入吞成空操作。具体RETURNING遍历方式必须按项目锁定版本验证，不因在线文档更新而引入新依赖。[Psycopg Cursor官方文档](https://www.psycopg.org/psycopg3/docs/api/cursors.html)

序列验收同时考虑increment、is_called与缓存；序列值不保证连续，setval并不随行事务回滚。受控无并发测试应验证下一次合法分配和实际插入无冲突，不能仅比较last_value和MAX。[PostgreSQL 16序列函数](https://www.postgresql.org/docs/16/functions-sequence.html)、[CREATE SEQUENCE](https://www.postgresql.org/docs/16/sql-createsequence.html)
