### 0.1 两个根决策（先定，其余随之展开）

- **R1 服务器地域**：境内（域名必须 ICP 备案；支付回调与访问稳定；备案路径与法务结论自然衔接）vs 境外（免备案，但对外销售的合规义务并未消失，只是把问题推迟到放量阶段，且 ZPay 回调稳定性变差；**人脸等敏感个人信息存储于境外服务器还需另走 PIPL 出境合规路径**——标准合同备案或安全评估，是境外选项最主要的增量合规成本）→ **建议：境内**。若选境内，域名 ICP 备案应立即启动（流程 1–3 周，是周期最长的行政项之一）。
- **R2 签名证书档位**：OV（省，但新发布者 SmartScreen 信誉需积累）vs EV（即时 SmartScreen 信誉，价格约为 OV 的 2.5–3 倍）→ **建议：灰度 10 码阶段用 OV 云签名，放量（REL-03 100 码）前评估是否升级 EV**。

## 1. LEGAL-01：对外销售合规确认材料

### 1.1 阻塞关系

- 账本红线：无用户协议 / 隐私政策或未做 AI 内容标识时，**不得开放公网客户注册**。
- 影响任务：LEGAL-01（T40/T41）→ REL-02 灰度 → REL-03 扩量。

### 1.2 适用法规义务清单（2026-08 现行有效）

### 1.3 三份协议文本框架（供律所起草 / 审校的基线大纲）

**用户服务协议**：服务内容与账号规则（激活码绑定、两设备上限、单在线会话）；AI 生成服务说明与局限性免责；用户行为规范（禁止上传侵权 / 违法参考视频）；知识产权归属（用户输入素材归用户，生成物使用权的授权范围待定）；服务变更、中止与终止；争议解决。

**隐私政策**：收集清单（账号、设备指纹、充值与消费记录、上传视频与人物照片、生成任务数据）；敏感个人信息（人脸 / 声纹若涉及）单独同意机制；存储地点与期限；第三方共享清单（支付通道、云存储、AI Provider——需列明接收方与数据范围）；用户权利（查询 / 更正 / 删除 / 注销 / 撤回同意）与响应时限。

**支付与充值说明**：激活码面值与有效期、钱包余额性质（预付值，非存款、不计息）；续充渠道与到账时效；退款规则（未消费部分退款政策——需与 BILL-04 决议一致）；发票申请流程；异常扣款处理承诺时限。

### 1.4 AI 生成内容标识——实现方案（工程侧，需排任务卡）

> 这是六项中唯一需要写代码的部分。建议在账本新增工作包（随 LEGAL-01 决议一并落账），以下为方案基线：

- **显式标识**：视频交付（下载 / 播放页）叠加角标水印「本内容由 AI 生成」+ 任务详情页文字提示；图片交付同理。实现点：归档前的后处理步骤（ffmpeg drawtext 滤镜）或播放端叠加（二选一，倾向归档前处理——保证下载传播后标识仍在）。
- **隐式标识**：按国标在文件元数据写入标识字段 + 服务提供者编码（编码需按网安秘字〔2025〕29 号指南登记后取得）。实现点：归档管线在 COS put 前注入（视频 container metadata / 图片 EXIF 或 XMP）。
- **桌面端**：客户端「关于」页声明 AI 生成服务性质；生成记录界面提供标识说明。
- **验收形式**：抽样产物用国标方法核验显式 / 隐式标识存在且不易被普通操作移除；演示记录进 LEGAL-01 证据。
- **依赖**：服务提供者编码登记（用户侧动作，见 §1.6 问题 8）。

### 1.5 备案路径决策树（给法务确认的主干问题）

```text
服务器在境内？（建议是）
 ├─ 是 → 域名 ICP 备案（必须）
 │        经营性（销售激活码收费）？
 │         ├─ 判定为经营性 → ICP 许可证（增值电信 B25，省通信管理局审批）
 │         └─ 判定为非经营性 → 仅备案 + 说明
 └─ 否 → 无 ICP 备案义务，但对外销售的其他义务不变（本决策树其余分支照走）

对外提供 AI 生成能力（是）→ 是否具有舆论属性或社会动员能力？（法务判定）
                          ├─ 是 → 深度合成算法备案（网信，服务提供者角色）
                          │        + 生成式 AI：调用已备案模型 API 的应用 → 属地网信登记（2026 口径）
                          └─ 否 → 留档「不落入」的评估结论（仍建议同步完成 AI 标识义务，见 §1.2）
```

### 1.6 委托外部法务的确认问题清单（可直接发给律所）

1. 销售「激活码（预付费，含首充面值）+ 钱包余额扣费」模式，是否构成经营性互联网信息服务？是否需要 ICP 许可证，还是 ICP 备案即可？
2. 钱包预充值余额是否落入《单用途商业预付卡管理办法》监管范围？如落入，备案与资金存管要求是什么？
3. 通过 ZPay（聚合支付平台 zpayz.cn，非持牌机构）代收用户充值款，是否构成「二清」？资金合规风险等级与整改路径？（联动 §3）
4. 用户协议中 AI 生成内容的使用权、知识产权条款应如何设计？平台对用户上传的侵权参考视频的避风港义务边界？
5. 人物照片（含人脸）作为生成参考属于敏感个人信息吗？单独同意文案与最小化存储方案？
6. 退款义务边界：数字内容（已生成视频）是否适用七日无理由退货？未消费余额的退款时限承诺建议值？
7. 用户协议 / 隐私政策 / 支付说明三份文本的起草或审校报价与周期（可附 §1.3 大纲）。
8. 「服务提供者编码」按网安秘字〔2025〕29 号指南如何登记？由律所代办还是企业自办？
9. 深度合成算法备案 + 生成式 AI 属地登记的代办报价与周期；两者是否可并行？
10. 平台内容审核义务（用户上传参考视频）的最低配置建议：机审接口（如内容安全 API）+ 人审的边界？
11. 若灰度期仅面向受邀企业客户（不开放公网注册），上述义务中哪些可延后到放量前？哪些必须灰度前完成？
12. 发票义务与开票流程合规要点（联动 BILL-04：退款、开票与税务口径）。
13. 广告 / 官网宣传文案的红线词（「AI 复刻」「一键换脸」类表述的合规风险）。
14. 本产品（B 端企业客户视频复刻工具，非公众内容分发平台）是否落入「具有舆论属性或者社会动员能力」的深度合成备案 / 生成式 AI 安全评估适用范围？若不落入，是否仍建议主动属地登记留档？

## 2. DESK-04：Windows 代码签名证书采购材料

### 2.1 阻塞关系

- 账本红线：无证书时 DESK-03 只能标 `UNSIGNED_INTERNAL_TEST`，Gate D 无法通过。
- 影响任务：DESK-03（T34/T41）→ REL-02 灰度。

### 2.2 证书类型对比（企业主体，2026-08 调研价）

| 方案 | 参考价 | 私钥载体 | SmartScreen | 适用判断 |
| --- | --- | --- | --- | --- |
| Certum OV（云签名） | 约 1,200 元/年 | 云端合规 HSM（无需邮寄 UKey） | 需积累信誉 | 预算敏感、要快：**推荐起步** |
| Sectigo / GlobalSign OV | 约 2,000–2,500 元/年 | USB 令牌（国际物流 1–2 周） | 需积累信誉 | 传统路径，交付慢于云签名 |
| GlobalSign EV | 约 3,300–4,300 元/年 | USB 令牌 / HSM | **即时信誉** | 放量阶段升级候选 |
| DigiCert EV | 6,000+ 元/年 | USB 令牌 / HSM | 即时信誉 | 大厂品牌溢价，本阶段非必需 |

背景：2023-06 起 CA/B Forum 强制所有代码签名证书（含 OV）私钥存放硬件令牌或合规云签名，纯文件私钥不再签发——「云签名」即满足该要求的托管方案。

### 2.3 企业主体所需申请材料

营业执照（彩色扫描）、企业邮箱（域名邮箱优先，部分 CA 拒绝免费邮箱）、企业电话（可接听验证）、经办人身份证；部分 CA 需要 D-U-N-S 编码（邓白氏码，免费申请约 1–2 周，可提前办）。

### 2.4 建议方案与采购流程

**建议：Certum OV 云签名（约 1,200 元/年）起步。** 理由：灰度期装机量小，SmartScreen 信誉积累压力低；云签名无需国际物流，签发快；放量前若「未知发布者」警告影响转化，再评估升级 EV（EV 与 OV 可并存过渡）。

流程：① 在 Certum 官网 / 授权经销商下单 → ② 提交企业材料 + 电话验证 → ③ 云签名账户开通（3–10 个工作日）→ ④ 产出 signtool 签名脚本（DESK-03 落地时：证书 + 时间戳服务器，时间戳验证通过即 Gate D 证书项就绪）。

### 2.5 需要用户提供的输入

- [ ] 预算确认（OV ≈ 1,200 元/年 or 直上 EV）
- [ ] 签发主体名称（须与营业执照一致；建议与域名备案主体一致）
- [ ] 经办人联系方式与企业邮箱（域名邮箱需先有域名——联动 §4）

## 3. BILL-01 前置：ZPay 商户资质与费率确认材料

### 3.1 阻塞关系

- 真实 ZPay 下单 / 支付 / 回调验证属**必须人工授权**动作（账本 §15）；资质与费率书面确认是授权的前置。
- 影响任务：BILL-01（T13/T22）→ T40 真实链路验收。

### 3.2 项目现状（工程事实）

- 网关：`zpayz.cn/submit.php`；渠道：alipay / wxpay；notify / return 两个公网回调路径已在 nginx 配置样例中预留。
- 账务侧：ZPAY order → CHARGE 入账链路已实现并有内部回归；T22 将在客户 session 下复用。

### 3.3 需要向 ZPay 书面确认的问题清单

1. 企业商户开户所需材料（营业执照、法人身份证、对公账户？）与审核周期。
2. 完整费率结构：平台手续费 + 支付宝 / 微信渠道费各自多少？月交易量阶梯折扣？
3. 结算规则：结算周期（T+1？）、结算账户（对公？）、提现手续费、最低结算额。
4. 资金安全：什么条件触发风控冻结？冻结后的申诉与解冻流程和最长时限？
5. 退款：是否支持 API 发起退款？退款到账时限？退款手续费？
6. 商户发票：平台是否向商户开具服务费发票（联动 BILL-04 税务口径）？
7. 回调可靠性：notify 重试策略（次数 / 间隔）；商户侧幂等要求已具备（工程侧就绪）。
8. 平台资质：是否持有支付业务许可或仅为技术聚合？资金由谁托管？（**给律所联评二清问题的核心事实**）
9. 对外销售场景（面向不特定公众收款）与内部测试场景的商户政策差异；是否要求网站备案完成才能开通。

### 3.4 风险提示与备选路径

- **风险（须法务联评，§1.6 问题 3）**：聚合支付平台若非持牌收单机构，商户资金先归集平台再结算存在「二清」合规风险；极端情况（平台停服 / 跑路）资金敞口 = 未结算余额。缓释：控制结算周期（如 T+1 自动结算）、设置余额上限与告警、放量前完成法务结论。
- **备选路径**（若法务结论为不可用）：支付宝 / 微信官方服务商模式或持牌收单机构直连（费率约 0.6% 且合规，但开户周期 2–4 周且需 ICP 备案主体——再次联动 R1 境内决策）。
- 工程侧影响：账务层与网关解耦（order→CHARGE 链路不依赖具体网关）。**白名单内**网关切换（zpayz.cn ↔ z-pay.cn）仅改 `ZPAY_GATEWAY_URL` 配置；但 `ALLOWED_ZPAY_GATEWAYS` 白名单为源码硬编码，**转持牌 / 官方直连**（协议栈不同：RSA 签名、JSON 异步回调、新查询接口）需另排一个支付适配器工程任务（中小规模，账务层无需重构）——做「ZPay 继续 / 转持牌」决策时请把该开发排期计入。

### 3.5 需要用户提供的输入

- [ ] 向 ZPay 客服 / 商务发送 §3.3 清单并留存书面答复
- [ ] 律所对平台资质结论（联动 §1）
- [ ] 通道最终决策（ZPay 继续 / 转持牌；若转持牌请预留支付适配器开发排期，见 §3.4）与真实支付联测的授权时间窗（T40 前）

## 4. OPS-01 前置：生产资源冻结清单（单机起步形态）

### 4.1 阻塞关系

- 影响任务：OPS-01（T36 类生产 staging）→ T37 / T38 / T39 / T40。
- **形态边界（PR #53 评审 P1 修正）**：账本依赖链为 T41（REL-02 十码灰度）← T40 ← T39 ← T36，而 OPS-01/T36 的验收出口要求 LB / 双 API / 四 Worker / PG HA 的完整拓扑。因此本清单的单机形态**仅限 T36 之前的内部联调与预验收环境**；**REL-02 十码灰度的目标形态必须是 OPS-01 完整拓扑**，在 REL-02 启动前须按 §4.7 硬性前置升级并重新冻结资源清单——单机形态不得被描述为 REL-02 的目标环境。
