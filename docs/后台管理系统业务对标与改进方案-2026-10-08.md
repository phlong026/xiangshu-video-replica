## 1. 业务模型 → 管理端应扮演的角色

### 1.1 业务本质

本产品是"总部 → 加盟商客户"的 AI 短视频生产赋能 SaaS：客户（乡墅/合家美宅加盟商）用积分购买 AI 生产能力（链接解析/文案/口播/复刻/图生视频），总部通过爆款采集给客户供内容。管理端的用户是**我们自己**（运营 + 技术 + 老板），它实际承担四个角色：

| 角色 | 职责 | 对应现状页面 |
|---|---|---|
| ① 账本 | 每一笔积分收、支、退、调都准确，成本可核对，毛利可算 | 资金中心 / 成本核对 / 经营看板 |
| ② 内容供应链 | 采集 → 准备 → 上首页 → 客户使用 → 需求洞察 → 补货 | 内容板块 5 页 |
| ③ 客户成功 | 客户从开户到激活、留存、扩费的全程运营 | 客户列表 / 登录与设备 |
| ④ 平台运维 | 供应商、任务队列、资金通道、安全的健康与补偿 | 生成记录 / 失败诊断 / 审计 / 系统设置 |

### 1.2 运营现状快照（2026-10-08 实测）

- 有效客户 **80**；预收积分余额 **34.5 万积分（折合 ¥3.45 万）**；本月充值实收 **¥100.10**（微信 2 笔）+ ¥5 万线下充值补偿审批 1 笔；本月**确认收入仅 ¥2.10**，已确认成本 ¥99.21。
- 生成 728 次，成功率 **82.7%**，失败 78（服务商故障为主）；失败原因"未归类"39–41 条。
- 内容池 92 条、素材就绪 45、首页展示 5、封面缺失 25；采集转化漏斗五阶段恒 0；客户搜索洞察自起计为空。
- 成本待核对 59 项 + 3 个对客业务未配成本单价 → **全站毛利"待核对"**；低余额阈值、首页容量、5 项通知投递渠道均未配置。

**核心判断**：账本和内容供应链的"骨架"已经搭得相当专业，但当前最大的业务矛盾是——**80 个客户几乎没在花钱（确认收入 ¥2.10/月）**。管理端下一阶段的重心必须从"记账准确"扩展到"驱动客户激活与消耗"，否则成本核对做得再精，分子上不来。

## 2. 做得好的地方（对标后的相对优势）

1. **经营分析的口径纪律**：每个指标带 ⓘ 口径说明，"未知金额不当作零、证据缺失保留待核对"——这是财务级的数据诚实性，多数早期 SaaS 做不到（对标：成熟 FinOps 后台）。
2. **成本侧记账闭环**：供应商调用记录与客户计费双口径对照、待核对/待结算/历史三队列、逐条"核对账单"证据链。对标同行普遍只有"收入报表"，我们有成本毛利视角。
3. **内容运营供应链是差异化亮点**：采集计划/关键词/平台探针 → 素材准备 → 首页编排（排序+定时上下线+客户预览）→ 客户使用追踪 → 需求洞察 → 补货建议，链路完整，且"定时采集停用、转人工搜索推送"的拍板有配置留痕。
4. **待办驱动的运营设计**：总览待办（失败任务/对账不一致/成本待配置）+ 告警总览（成本未配置、失败率阈值）+ 待办直达链接，exception-driven 而非翻菜单。
5. **资金异常专项监控**：钱包不一致 / 已支付未入账 / 入账但订单未支付三类对账异常专页 + 充值单 reconcile 按钮。
6. **运维补偿有 UI**：首帧 reconcile、生成 retry、充值单补单、billing verify 都有界面入口（很多团队停在命令行/script）。
7. **审计与安全基线**：全操作审计（登录、调账、配置、导出）、会话绑定浏览器、管理员/审计员分角色、支付密钥"已配置留空保留"不明文回显。
8. **计费横切的完整性**：预扣→SETTLE/RELEASE→SUBMISSION_UNCERTAIN 冻结→reconcile 的状态机在管理端有完整的观测面（积分流水含冻结变动双列）。
9. **桌面端配套**：设备绑定/解绑审批/强制下线有管理面，配合 Tauri 客户发放链路。
10. **中性化文案纪律**：客户侧与管理端数据均不出现供应商真名（红线测试锁定），降低供应商暴露风险。

## 4. 对标差距矩阵

对标参照系：成熟 SaaS 运营后台（有赞/微盟类电商 SaaS 的客户与营销中台、HeyGen/Synthesia 类 AI SaaS 的企业席位与用量管理、连锁加盟赋能系统的总部内容下发）。

| 模块域 | 成熟后台标准能力 | 我们现状 | 差距 |
|---|---|---|---|
| 账务 | 收支退全闭环、对账、发票/账单、多渠道支付 | 收支强、**退缺失**、账单缺、单渠道 | ★★★ |
| 客户运营 | 分层/标签/健康分/批量触达/生命周期自动化 | 单点卡片，无分层无触达 | ★★★（最大） |
| 内容运营 | 采产配审全链、质检、效果回流 | 链路全但**漏斗失真、无质检、无回流** | ★★ |
| 任务运维 | 队列可视化、SLA、供应商面板、自动补偿+人工兜底 | 人工兜底强、**观测面缺** | ★★ |
| 数据决策 | 漏斗/留存/队列/目标对比/统一口径 | 今日+7日、口径分裂 | ★★ |
| 安全合规 | RBAC 矩阵、双人复核、审计语义准确 | 二分角色+全审计，语义待修 | ★ |
| 平台配置 | 功能开关、配额限流、灰度 | queue-mode/扩展模式开关有，配额 UI 缺 | ★ |
| 工程质量 | 无 P1 视觉缺陷、报错干净 | 4 个 P1 + favicon 噪音 | ★（易修） |

## A.2 业务逻辑排查（根因结论）

**A2-1 漏斗恒 0 的根因 = cohort 来源覆盖缺口（设计缺口，非查询 bug）。**
漏斗唯一判据是 `viral_content_sources.collected_at` 落入区间（`viral_content_cohort.py:18-40`）。但该表**只有两个写入方**：关键词批次采集（`viral_collection.py:485-493`，source_kind='collection'）和管理端实时搜索（`admin_runtime_routes.py:1458-1468`，source_kind='admin_search'）。**客户链接导入**（`viral_import_routes.py:561` 只 upsert viral_videos）、**单条/批量转存**（只 `record_content_stage`，是 UPDATE 不 INSERT，`viral_content_observations.py:46-57`）都进不了 cohort。10-04 起计以来的库存恰恰全部来自导入/转存路径 → "本期采集"=0，四阶段连锁全 0。
**修法（ADM-C01）**：在导入与转存提交点补写 sources（新增 source_kind='customer_import' 等并保留区分）；产品决策项——是否全来源进同一个漏斗（推荐：全量进 cohort + 管理端按 source_kind 过滤，页面口径说明同步改）。

**A2-2 客户需求洞察恒空的根因 = 客户端搜索从未接线。**
`POST /api/viral/search` 后端完备（资费 fail-closed 守卫 `viral_search_routes.py:56-84`、写 viral_search_events + viral_search_discoveries、搜索页次计费），但 `searchViralVideos`（`client/src/api.ts:8027`）**全仓库无任何 UI 调用方**，客户爆款页也没有搜索框（grep 证实仅素材库搜索存在）。洞察页自起计为空不是"客户没搜"，是**功能不存在于客户侧**。
**修法（ADM-C05）**：决策二选一——① 上线客户付费搜索入口（前置：viral_search 科目资费已按 runbook 配齐），洞察/补货链路随之激活；② 短期明确下线，从总览待办摘除"查看客户搜索需求"入口，避免运营对着空页困惑。

**A2-3 "起计 2026/10/4 12:18:59" 是迁移时间戳**，即 `20261001T1840` 首次执行 `INSERT ... DEFAULT now()` 的时刻，不是业务起点。页文案"起计"应改为"记录始于"，避免误解。

**A2-4 封面缺口存在双口径漏计。** "缺少归档封面 25 条"只统计 cover_url 非空而 cover_key 为 NULL（`admin_runtime_routes.py:2774-2775`）；客户链接导入不跑 CoverEnricher，抖音解析不带 cover 字段时 cover_url 直接 NULL——这批视频在列表里显示"封面待补齐"却**不进待办计数**，真实缺口大于 25。且封面缺失会直接压制 ready 判定（`ready_sql` 要求 cover 条件），放大"待准备 66 条"。
**修法（ADM-C04）**：导入路径接入 CoverEnricher（导入完成后异步补抓）；统计口径改为"无 cover_key 即缺"，两口径合并展示。

**A2-5 定时上下线无消费者、首页容量恒无上限。** 排期只靠查询期 `live_homepage_sql`（DB now() 比较）惰性生效，worker 只回填观察时间；capacity 硬编码 None（`admin_runtime_routes.py:2606`）。功能正确但两点要补：容量配置化（ADM-C07）；管理端列表应展示"当前是否实际在线"（starts/ends 生效中）而非仅"未展示"。

**A2-6 效果归因重复计数。** sources 主键含 (batch_id, keyword)，同一视频被多关键词命中时逐行插入；漏斗靠 GROUP BY 救回，但 bestKeywords 的 collected 口径会把同视频在不同关键词下重复统计（`viral_content_overview.py:85-93`）。修法：关键词效果按"视频首次命中关键词"归因。

## A.5 页面布局与显示效果（实测 + 代码级）

1. **【根因更正】详情抽屉金色遮罩**：代码与线上 CSS 均为暗色 `#09090894`（rgba(9,9,8,.58)），**真正的凶手是全局裸按钮规则** `button{background:var(--accent)}` + `button:not(:disabled):hover{background:var(--accent-strong)}`——hover 规则特异度 (0,1,1) 压过类规则 (0,1,0)，而用户点「详情」后鼠标恰好停在遮罩上，hover 态即呈不透明金色（#F0BC5E，实测 computed rgb(240,188,94) 完全吻合）。**修复只需一处**：scrim 规则提高特异度（如 `.admin-viral-drawer-layer .admin-viral-drawer__scrim`）或补 `:hover` 同值覆盖；顺手把 scrim 从 `<button>` 改 `div role="presentation"`（顺带解决可聚焦空按钮的 a11y 问题）。
