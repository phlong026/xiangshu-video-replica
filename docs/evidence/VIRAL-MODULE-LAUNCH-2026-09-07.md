## 2. 实现范围

### 浏览与精选

- 爆款列表改为数据库优先读取，支持平台、分类、排序、最近七天、可用性过滤和不透明游标分页。
- 游标携带数据版本，版本变化时要求客户端重新加载，避免跨刷新分页混入不同快照。
- 修复滚动观察节点和键盘“加载更多”；切换平台、分类、排序时，旧请求结果不会混入新列表。
- 详情地址可恢复平台和视频 ID，刷新、前进后退及特殊字符 ID 均从数据库读取正确条目。
- 工作台展示 5 个 9:16 爆款视频卡片；“正在进行”优先使用 9:16 视频缩略图；统计数字居中；左下角与右上角头像统一。

### 收藏与个人状态

- 收藏关系持久化到服务端，按当前用户隔离，支持幂等收藏、取消、分页和“我的收藏”。
- 来源过期或下架时保留收藏关系，但禁止新的导入操作，并返回明确不可用原因。

### 导入、提取文案与复刻

- 新增持久化导入任务：公共爆款缓存复制到当前用户的私有项目命名空间，校验大小、SHA256、媒体类型和项目归属。
- `copy` 与 `replica` 分支返回真实 `projectId`、`sourceAssetId`、`canTranscribe`、`canAnalyze`，不再把平台视频 ID 当项目素材 ID。
- 首页、列表、详情复用同一交接逻辑；更换来源会清理不兼容的旧草稿字段，迟到响应不能覆盖新来源。
- ASR 支持 `reference_audio` 与 `reference_video`，按准确 task ID 轮询；任务刷新后可恢复，任务完成不会覆盖用户已编辑的文案。
- 复刻分支只接受可分析的视频资产，并继续进入既有分析、分镜和 Prompt 链路。

### 媒体、并发和管理能力

- 存储层支持流式复制和分块读取；本地签名媒体接口支持 Range、206 和 416。
- 媒体准备、数据刷新和导入任务均持久化，使用租约、fencing 和幂等键约束多 Worker 重复执行。
- 下载器逐跳复核重定向目标，拦截私网、元数据地址和不允许的协议。
- 管理端增加爆款数据源配置状态、最近成功/错误、刷新状态、停采、停导入及单条可见性控制，并记录审计信息。
- OpenAPI 客户端已按新增接口重新生成。

## 5. 代码评审记录

### 已发现并修复

1. 分页竞态：加载第二页时切换平台，旧平台响应可能混入新平台。修复为请求代次校验，并用同步 `loadingMoreRef` 阻止同游标重复提交；先补失败回归测试，再修复至通过。
2. 文案任务恢复：页面刷新后只依赖内存状态，可能丢失正在运行的准确 ASR 任务。修复为读取当前项目的持久任务，核对 `sourceAssetId` 和草稿来源后恢复轮询。
3. 用户编辑保护：后台 ASR 完成时不能覆盖用户在等待期间编辑的文案。恢复逻辑只在目标字段未被用户修改时自动填入。
4. 刷新租约丢失：旧 Worker 不能把新租约结果发布为成功或失败，已补 fencing 保护。
5. 字段语义：`sourceDescription` 不再写入标题或转写全文字段。

### 评审结论

- 未发现仍未解决的 Critical/High 级代码问题。
- 没有新增依赖，没有硬编码密钥，没有把公共缓存 URI 直接登记为个人项目资产。
- 热路径检查未发现新增 N+1、无界列表渲染或在数据库事务内等待外部 Provider 的实现。
- 剩余风险集中在外部环境：真实 Provider 返回差异、私有 COS Range/CORS、大文件峰值内存、多实例故障恢复、告警接收和发布灰度。
