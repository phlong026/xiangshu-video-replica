## 一、交付概述

全自动复刻链路已全部落地并合并 main（PR #117，merge commit `8dd500c`，2026-11-12）。
用户在工作台发起后，系统自动完成 **导入 → 拆解 → 文案版本 → 首帧 → 合成 Prompt →
确认点（单次扣费授权）→ 生成 → 交付** 的编排推进；既有手动链路完全保留，两条车道并存。

- **总开关**：`runtime_settings.replica_pipeline_enabled`，**默认 false**。
  生产启用前必须完成 §五 的 M6b 三项前置验收，在此之前禁止开启。
- **确认点**：自动推进到 `AWAIT_CONFIRM` 后暂停，用户确认报价（72h 期限）即扣费授权并继续生成；
  不确认则 `EXPIRED`，可随时取消。
- **交付口径**：交付名额 = 原始生成任务数；可交付谓词 = `SUCCEEDED` 且
  `archive_status ∈ {DIRECT, ARCHIVED}`；部分交付可 `NEEDS_REVIEW_SETTLED` 后
  重生成（付费原语）/ 接受部分 / 转手动。

## 四、CI 过程发现并修复的问题（3 项，均已入库）

1. **分片清单 staging 顺序**（`17ad1a1`）：合并冲突解决时 `git add` 早于清单重生成，
   提交内仍是 main 版清单，5 个新测试文件未入库——CI fail-closed 覆盖断言抓到。
2. **迁移链头常量遗漏**（`5939344`）：7 个 schema/迁移测试模块硬编码 `_HEAD_REVISION`
   仍指旧头 `20261102T0900`，CI 抓到 16 项失败；全部更新至 `20261112T1100`。
   教训：新增迁移时除 CW056 外须全量 grep `_HEAD_REVISION`。
3. **oral 域既存 TOCTOU**（`ce0a0f6`，非本链路引入）：`delete_avatar_clone` /
   `delete_voice_clone` 的活动任务守卫是非锁定 COUNT、随后 UPDATE 才取行锁，而
   `create_oral_task` 对克隆行 `FOR UPDATE`——创建方先取锁并提交时 delete 的 UPDATE
   被放行，出现「用已删分身建任务」双成功。修复为删除首读即 `FOR UPDATE`、守卫在行锁内
   求值，双方严格串行。

## 五、生产启用前置（M6b，阻塞开启总开关）

总开关默认 false。**以下三项验收完成前，禁止在生产开启 `replica_pipeline_enabled`**：

1. **已入队子任务的供应商调用点 fencing**：发送意图先落库，防止止付开关关闭后
   在途子任务仍向模型网关发起付费调用。
2. **项目删除保护**：在途 pipeline 引用的项目不可被删除（否则编排状态悬空）。
3. **挂起产物纳回版本链**：挂起期间产生的半成品产物纳入版本链，恢复后不产生孤儿引用。
