# 首帧等待反馈与五步生成流程开发说明

## 真实需求

本次解决三个相互关联的问题：

1. 人物置换首帧通常需要等待 1–3 分钟，页面只有“正在生成”按钮，用户不知道是否仍在工作、能否离开页面，也容易重复提交。
2. “首帧与文案”混在同一步，AI 二创入口增加选择成本；实际需要的是带入原文后允许直接修改的自定义文案。
3. 首帧会照抄源图中的标题、字幕、门店招牌或水印，但首帧应当只保留纯画面，封面文字由后期添加。

## 当前实现结论

### 首帧不是持久化后台任务

`POST /api/projects/{project_id}/first-frames/generate` 会在同一个 HTTP 请求内直接调用图片 Provider，得到图片后才写入素材与版本并返回。它没有首帧任务表、任务 ID、Worker 消费或断点恢复机制。

因此边界必须说清楚：

- 在桌面应用仍运行、本地服务未重启的前提下，可以让请求脱离页面组件继续执行；用户离开当前页面不会主动取消生成。
- 返回同一项目时，页面应重新接入同一个进行中请求；若请求已完成，则从最新首帧版本读取结果。
- 关闭应用、本地服务重启或进程崩溃时，未完成首帧不会自动恢复。若要覆盖这个边界，需要后续单独建设“首帧任务表 + Worker + 状态查询 + 幂等恢复”，不在本次小改动中假装已经具备。

### 自定义文案可以进入最终 H3 请求

当前链路是：

`自定义文案 → ScriptVersion.full_text → 编译 H3 Prompt → 锁定 Prompt 快照 → 创建 GenerationBatch → Worker 读取 prompt_text → H3 API content[0].text`

所以用户直接修改带入的原文后，文本可以正确进入最终视频 API。需要额外修正一个冲突边界：如果用户同时保存过第一步的手工 Prompt，又修改了自定义文案，旧手工 Prompt 不能覆盖新文案；提交时应优先根据当前自定义文案重新编译。

## 本次实现

### 1. 首帧等待反馈

- 首帧生成期间显示不伪造百分比的动态进度条、已等待秒数和“通常需要 1–3 分钟”的说明。
- 明确提示“可以离开当前页面；只要本地服务未关闭，生成会继续，返回后自动显示结果”。
- 以项目 ID 缓存同一个进行中 Promise，避免双击或返回页面后重复调用付费图片接口。
- 返回页面时若任务仍在进行，重新接入现有 Promise；若已完成，由最新版本接口恢复结果。
- 若用户离页期间请求失败，失败结果保留到用户返回并展示，之后允许重新发起。
- 首帧生成不再锁死项目返回按钮和侧边导航；确认首帧与提交生成仍保持原有校验。
- 为避免生成期间修改输入导致图片调用浪费，当前源画面与人物步骤会暂时锁定，生成结束后恢复。

### 2. 五步流程与文案

流程调整为：

1. 解析提示词
2. 源画面与人物
3. 人物置换首帧
4. 自定义文案
5. 提交生成

第四步的文本框默认带入拆解原文。用户不修改时沿用原文；直接编辑后按 `custom` 保存。隐藏“使用原文案”“AI 二创改写”“AI 二创中”等入口，后端改写能力保留但本页不再触发。

### 3. 首帧禁止文字

- “无任何文字”作为服务端不可绕过的硬约束，追加到每一次首帧 Provider 请求。
- 即使前端或调用方传入自定义首帧提示词，也不能覆盖该约束。
- 约束明确要求移除源图中的标题、字幕、话题词、标签、招牌、门联、水印与 Logo，并用自然背景补全；封面文字留给后期设置。
- 图片模型仍是概率模型。本次能保证 API Prompt 始终携带硬约束，但没有新增 OCR/视觉质检依赖，因此不能宣称像素级 100% 无字；若仍偶发违规，需要另建生成后 OCR/视觉门禁。

## 验收标准

1. 首帧生成时出现进度条、耗时与安心提示，且不展示虚假的实际百分比。
2. 生成期间可返回项目列表或切换页面；返回项目后不会重复发起同一首帧请求，并能接回进行中结果。
3. 五个步骤的编号、标题和顶部流程摘要一致。
4. 页面不存在“AI 二创文案”“AI 二创改写”“使用原文案”入口；自定义文案框预填原文并允许直接修改。
5. 自定义文案保存为 ScriptVersion，并进入编译、锁定、Batch 快照和 H3 文本请求链路。
6. 所有首帧 Provider Prompt 都包含不可覆盖的无文字约束，包括调用方传入非空 Prompt 的情况。
7. 前后端回归测试、类型检查、格式检查与静态检查全部通过。

## 暂不处理

- 不新增首帧任务表、迁移、独立 Worker 或跨服务重启恢复。
- 不删除后端 AI 文案改写 API，仅隐藏当前项目详情页入口。
- 不新增 OCR、视觉模型或第三方依赖。
