# 内部运营 P0 单机部署与验收记录

版本：P0.4
适用范围：内部运营，不对外销售
当前结论：内部单机部署代码和资产已达到本地候选版标准；工作区未提供目标主机、SSH 入口、正式域名和证书路径，因此真实服务器、ZPay、COS 和 Provider 联合验收仍未执行

## 1. 状态分层

| 范围 | 当前状态 | 能证明什么 |
| --- | --- | --- |
| API、Worker、静态页、SQLite 的 systemd/Nginx 样例 | `LOCALLY_VERIFIED` | 文件存在且部署合同测试通过 |
| Fake ZPay 与内部账务闭环 | `LOCALLY_VERIFIED` | 固定签名、幂等入账、冻结、结算和返还通过自动化 |
| FakeProvider 纵向 Gate 1 | `LOCALLY_VERIFIED` | 人物、项目、生成、重启恢复、异常分流和管理端紧凑布局通过 |
| 真实云服务器 HTTPS | `NOT_DEPLOYED` | 尚未提供目标主机、域名和证书权限 |
| 真实 ZPay 最低充值 | `NOT_RUN_REQUIRES_AUTHORIZATION` | 未发起任何真实支付 |
| 真实 COS 归档与签名下载 | `NOT_RUN_REQUIRES_AUTHORIZATION` | 自动化只证明规则，不能替代真实桶验收 |
| 真实 Provider 生成与归档 | `NOT_RUN_REQUIRES_AUTHORIZATION` | 未产生第三方计费调用 |

最终发布状态只能是上述各层证据的交集。Fake、提交记录或本地测试不能把真实链路提升为 `PROVIDER_VERIFIED`。

## 2. 上线前必备输入

实际部署前要把下表固定在运维工单中。任何一项缺失都不应猜测或复用其他项目的服务器。

| 输入 | 要求 | 当前状态 |
| --- | --- | --- |
| 目标服务器 | 公网 IP 或 SSH Host 别名、SSH 端口、可 `sudo` 用户 | `MISSING` |
| 正式域名 | 专用 HTTPS 域名，DNS A/AAAA 记录已指向目标服务器 | `MISSING` |
| TLS 证书 | 证书链和私钥路径，或明确由 Certbot/云证书服务签发 | `MISSING` |
| 管理入口 | VPN/内网网段或管理员出口 IP，用于替换 Nginx 样例白名单 | `MISSING` |
| 发布版本 | 已审核的 Git 提交 SHA 和对应压缩包 SHA-256 | 发布时填写 |
| 外部配置 | COS 私有桶、ZPay 商户、Provider 账号的负责人与验收窗口 | 凭据已有部分，未进行真实验收 |

服务器建议使用 Ubuntu 24.04 LTS，Python 需 `>=3.12`，Node.js 需 `>=24`。建议起步配置为 4 vCPU、8 GB 内存和 100 GB 持久盘，这只是内部试运行起点，不是已压测的容量承诺。安全组/防火墙只对外开放 SSH 管理端口和 `80/443`，不开放 `8000`。

## 3. 最小拓扑与固定路径

单机只运行一个 API 和一个 Worker。Nginx 是唯一公网入口，FastAPI 固定监听 `127.0.0.1:8000`。

| 对象 | 固定路径或地址 |
| --- | --- |
| 发布目录 | `/opt/video-replica/releases/<commit-sha>` |
| 当前版本链接 | `/opt/video-replica/app` |
| Python 环境 | `/opt/video-replica/app/server/.venv` |
| 前端静态文件 | `/opt/video-replica/app/client/dist` |
| 环境文件 | `/etc/video-replica/internal-p0.env` |
| SQLite | `/var/lib/video-replica/app.db` |
| 本地运行目录 | `/var/lib/video-replica/storage` |
| SQLite 备份 | `/var/backups/video-replica` |
| API | `127.0.0.1:8000` |

SQLite 必须位于云服务器本机持久盘，不得放入 COS、NAS、网盘同步目录或网络共享盘。扩成多台服务器、多个 API 实例或公开客户流量前，先迁移 PostgreSQL；P0 不做多实例。

## 4. 制作发布包与服务器安装

以下命令假定服务器已安装 Python、`uv`、Node.js、Nginx、`htpasswd`、OpenSSL 和 CA 证书。先在开发机对已审核提交制作不含 `.git`、本地环境文件和未提交代码的发布包：

```bash
git status --short
git rev-parse HEAD
git archive --format=tar.gz --output=/tmp/video-replica-<AUDITED_COMMIT>.tar.gz <AUDITED_COMMIT>
shasum -a 256 /tmp/video-replica-<AUDITED_COMMIT>.tar.gz
scp -P <SSH_PORT> /tmp/video-replica-<AUDITED_COMMIT>.tar.gz <SSH_USER>@<SSH_HOST>:/tmp/
```

`git status --short` 必须无输出。把提交 SHA 和压缩包 SHA-256 写入发布工单，服务器端再次校验 SHA-256，不一致就停止。

首次创建发布、数据和备份目录：

```bash
sudo useradd --system --home /var/lib/video-replica --shell /usr/sbin/nologin video-replica
sudo install -d -o video-replica -g video-replica -m 0755 /opt/video-replica/releases
sudo install -d -o video-replica -g video-replica -m 0700 /var/lib/video-replica
sudo install -d -o video-replica -g video-replica -m 0700 /var/lib/video-replica/storage
sudo install -d -o video-replica -g video-replica -m 0700 /var/backups/video-replica
sudo install -d -o root -g video-replica -m 0750 /etc/video-replica
```

展开到唯一发布目录，安装锁定依赖并构建静态页。明确设置 `VITE_API_BASE_URL` 最容易审计；若遗漏，HTTPS Web 生产构建也会回退到当前页面同源，不会误连访问者的 `127.0.0.1`。

```bash
sha256sum /tmp/video-replica-<AUDITED_COMMIT>.tar.gz
sudo install -d -o video-replica -g video-replica -m 0755 \
  /opt/video-replica/releases/<AUDITED_COMMIT>
sudo tar -xzf /tmp/video-replica-<AUDITED_COMMIT>.tar.gz \
  -C /opt/video-replica/releases/<AUDITED_COMMIT>
sudo chown -R video-replica:video-replica \
  /opt/video-replica/releases/<AUDITED_COMMIT>
cd /opt/video-replica/releases/<AUDITED_COMMIT>
sudo -u video-replica uv sync --project server --locked --no-dev
sudo -u video-replica npm ci
sudo -u video-replica env VITE_API_BASE_URL=https://internal.example.com npm run build
sudo ln -sfn /opt/video-replica/releases/<AUDITED_COMMIT> /opt/video-replica/app
```

生产域名必须替换示例值，并保持与 `PUBLIC_BASE_URL` 同源 HTTPS。首次部署此时只建立链接，还不启动业务流量。`/opt/video-replica/releases` 和单个发布目录使用 `0755` 是为了让 Nginx Worker 能穿过目录读取 `client/dist`；真实环境文件、数据库、备份和密钥全部位于目录外并保持 `0600/0700`，不得放入发布包。

## 5. 环境与身份

复制模板并只在服务器填写真实值：

```bash
sudo install -o root -g root -m 0600 deploy/internal-p0.env.example /etc/video-replica/internal-p0.env
```

必须满足：

- `VIDEO_REPLICA_AUTH_MODE=internal`；
- `VIDEO_REPLICA_ALLOW_DEV_IDENTITY_HEADER=0`；
- `VIDEO_REPLICA_DESKTOP_USER_ID` 留空；
- `VIDEO_REPLICA_DISABLE_LOCAL_KEYSTORE=1`；
- `VIDEO_REPLICA_SETTINGS_KEY` 使用独立 Fernet key，丢失后已加密设置无法恢复；
- `CONTROL_PROXY_TOKEN_DIGEST` 只保存 Nginx 原始控制令牌的 SHA-256；
- 原始控制令牌只写入 Nginx 配置，不写环境文件、不进入浏览器；
- `CONTROL_ADMIN_USER_ID` 指向一个启用中的内部管理员账号；
- `PUBLIC_BASE_URL` 是无路径、查询参数和片段的 HTTPS origin；
- `ZPAY_GATEWAY_URL` 只能使用代码白名单中的官方地址。

生成 Fernet key；输出只写入受限环境文件，不记入工单或聊天：

```bash
/opt/video-replica/app/server/.venv/bin/python -c \
  'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode("ascii"))'
```

另生成至少 32 字节随机控制代理令牌。原文先写入 root-only 临时文件，再人工替换到 Nginx 样例；把 SHA-256 写入 `CONTROL_PROXY_TOKEN_DIGEST`。不要把原文、完整摘要或命令输出记入仓库和工单：

```bash
sudo sh -c 'umask 077; openssl rand -hex 32 | tr -d "\n" > /root/video-replica-control-token'
sudo sha256sum /root/video-replica-control-token
```

把 `CONTROL_ADMIN_USER_ID` 固定为下方创建的 `internal-control-admin`。

分别创建固定管理审计身份和业务管理员；控制审计身份不签发业务令牌：

```bash
sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.internal_accounts \
  --db-path /var/lib/video-replica/app.db create-user \
  --user-id internal-control-admin --username internal-control-admin \
  --display-name "内部控制审计身份" --role admin

sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.internal_accounts \
  --db-path /var/lib/video-replica/app.db create-user \
  --user-id internal-operator-admin --username internal-operator-admin \
  --display-name "内部运营管理员" --role admin

sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.internal_accounts \
  --db-path /var/lib/video-replica/app.db issue-token --user-id internal-operator-admin
```

令牌只在签发输出中出现一次，应交给授权运营人员并从终端记录中移除。固定控制审计身份用于 `/api/control/*` 审计，禁止为其签发业务 Bearer Token；项目、任务和普通设置操作只使用独立业务账号。

`internal_accounts` 和 API 的 `ExecStartPre` 都会先执行 Alembic 升级；本候选版升级后的数据库版本应为 `024_wallet_backfill`。该迁移只为旧账号补零余额钱包，不赠送余额、不伪造充值流水。已有数据库升级前必须先按第 10 节留存在线备份；升级后若业务账号仍为零余额，应通过真实 ZPay 充值进入唯一 `CHARGE` 入账路径，禁止直接改表。

## 6. systemd、Nginx 与 HTTPS

```bash
sudo install -o root -g root -m 0644 /opt/video-replica/app/deploy/systemd/video-replica-api.service /etc/systemd/system/
sudo install -o root -g root -m 0644 /opt/video-replica/app/deploy/systemd/video-replica-worker.service /etc/systemd/system/
sudo install -o root -g root -m 0644 /opt/video-replica/app/deploy/systemd/video-replica-backup.service /etc/systemd/system/
sudo install -o root -g root -m 0644 /opt/video-replica/app/deploy/systemd/video-replica-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now video-replica-api.service video-replica-worker.service
sudo systemctl enable --now video-replica-backup.timer
```

以 root-only 权限复制 `deploy/nginx/internal-p0.conf.example`，再替换域名、证书路径、Basic Auth 文件和高熵控制代理令牌。Nginx 配置包含原始控制令牌，不能对普通本机用户可读。`/admin` 与 `/api/control/*` 同时受 IP/VPN 白名单和 Basic Auth 保护；`notify_url`、`return_url` 与 `/health` 不要求 Basic Auth。若 Nginx 前还有 CDN 或负载均衡，必须先只信任明确代理网段并正确恢复真实客户端 IP。

```bash
sudo install -o root -g root -m 0600 /opt/video-replica/app/deploy/nginx/internal-p0.conf.example \
  /etc/nginx/conf.d/video-replica-internal-p0.conf
sudo htpasswd -c /etc/nginx/video-replica-admin.htpasswd internal-operator
sudo chown root:www-data /etc/nginx/video-replica-admin.htpasswd
sudo chmod 0640 /etc/nginx/video-replica-admin.htpasswd
sudo nginx -t
sudo systemctl reload nginx
```

Ubuntu 的 Nginx Worker 以 `www-data` 运行，因此 Basic Auth 文件必须允许该组只读；`root:www-data 0640` 不允许普通用户读取，也避免因 `0600 root:root` 导致所有 `/admin` 请求返回服务器错误。若目标系统的 Nginx Worker 用户不是 `www-data`，部署前必须读取 Nginx 主配置中的 `user` 指令，并把上述组名替换为实际主组。

服务检查：

```bash
curl --fail --silent --show-error http://127.0.0.1:8000/health
curl --fail --silent --show-error https://internal.example.com/health
systemctl --no-pager --full status video-replica-api.service video-replica-worker.service
systemctl --no-pager --full status video-replica-backup.timer
```

ZPay 商户 PID、密钥和渠道在受保护的 `/admin` 设置；COS 与其他 Provider 在普通业务工作台的管理员设置页保存。所有密钥经 `SettingsRepository` 加密进入 SQLite，页面只显示掩码。

## 7. SQLite 检查、备份与恢复

独立一致性检查：

```bash
sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.backup \
  check /var/lib/video-replica/app.db
```

手工在线备份不需要停止 API 或 Worker，内部使用 SQLite Online Backup API，写入前后都执行 `PRAGMA integrity_check`：

```bash
sudo systemctl start video-replica-backup.service
sudo journalctl -u video-replica-backup.service --since today --no-pager
```

恢复必须停机，避免进程继续持有被替换前的数据库文件：

```bash
sudo systemctl stop video-replica-worker.service video-replica-api.service
sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.backup \
  check /var/backups/video-replica/app-YYYYMMDDHHMM.db
sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.backup \
  backup /var/lib/video-replica/app.db /var/backups/video-replica/app-before-restore.db
sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.backup \
  restore /var/backups/video-replica/app-YYYYMMDDHHMM.db /var/lib/video-replica/app.db
sudo systemctl start video-replica-api.service video-replica-worker.service
curl --fail --silent --show-error http://127.0.0.1:8000/health
```

恢复后还应核对项目、任务、版本、充值订单、钱包流水和审计记录的数量。定时任务默认保留最近 30 份在线备份；异机备份复制属于正式运维后续项。

## 8. Fake 验收证据

在开发机运行：

```bash
uv --cache-dir .uv-cache run --project server --locked python \
  scripts/p0_acceptance_evidence.py
```

证据写入 `output/internal-p0-acceptance/<UTC 时间>/`：

- `manifest.json`：分支、提交、测试列表、状态和未验收项；
- `P0-6-Fake验收证据.md`：可审阅摘要；
- `pytest.log`：固定测试的原始输出。

2026-08-20 本地运行结果为 22 项通过，结论 `LOCALLY_VERIFIED`。证据不保存商户密钥、完整签名或完整回调查询串，覆盖：固定签名、服务端下单、重复/并发通知幂等、return 只展示、主动查单、钱包入账、任务冻结、COS/可下载结算前提、成功结算和失败返还。

再运行纵向 Gate 1：

```bash
npm run test:gate1

# 仅当本机 8000 已被其他项目占用时，选择一个空闲的非特权端口：
GATE1_API_PORT=18000 npm run test:gate1
```

正式运行会自行创建隔离 SQLite、隔离本地存储和合成授权素材，强制使用 `fake_h3`，不会调用真实 Provider 或支付链路。`GATE1_API_PORT` 仅影响本地 Gate 1，值必须为 1024–65535、不能与 Web 端口 5173 相同；本地媒体 origin 仍被限制为桌面认证模式的 loopback HTTP，不改变服务器必须使用 HTTPS 的规则。2026-08-20 的正式结果为 2 项 Playwright 用例通过；证据位于 `output/playwright/gate1/<run_id>/`。发布工单只能引用 `run.json.commit_sha` 与候选提交完全一致且 `sha256-manifest.json` 状态为 `passed` 的运行，并检查其中包含：

- 3 个结果视频和重启后恢复结果的实际 MP4 下载；
- 浏览器 console error、warning 和真实 network failure 的空日志；
- Provider 失败、归档失败和提交结果不确定三类恢复摘要；
- 归档安全重试保持原 Provider 尾号、任务尝试次数不增加、`archive_retry_count=0`；
- 1024×768 下 `scrollWidth=clientWidth` 的布局证据和全页截图。

结果切换时 Chromium 主动取消旧本地 `<video>` 字节流的 `ERR_ABORTED` 会单独写入 `*-network-cancellations.json`，不混入真实网络失败；每个结果仍必须通过 `readyState` 和完整 MP4 下载双重验证。

## 9. 上线验收与真实链路门禁

先完成不产生外部费用的基础验收：

1. `curl -I http://<FORMAL_DOMAIN>/health` 必须跳转 HTTPS；
2. `curl https://<FORMAL_DOMAIN>/health` 必须返回 `status=ok`，响应含 HSTS、`nosniff` 和 `DENY` 安全头；
3. 服务器外部不得访问 `<SERVER_IP>:8000`；
4. 未带 Bearer Token 请求 `/api/auth/me` 必须返回 `401`，有效业务令牌才能进入工作台；
5. 非白名单网络无法访问 `/admin`；白名单内仍必须通过 Basic Auth；
6. `/api/control/*` 外部伪造的 `X-Control-Proxy-Token` 被 Nginx 覆盖，浏览器不能读到原始令牌；
7. `video-replica-api`、`video-replica-worker`、备份 timer 都是 active，最近日志无循环重启、解密错误或数据库锁错误；
8. 执行一次手工备份和 `integrity_check`，记录备份文件名与大小；
9. 在管理页配置 COS 为业务存储并通过诊断，未通过前不开放真实生成任务；
10. 使用授权素材走一次不调用付费 Provider 的项目创建、上传、人物库查看和管理页查询冒烟。

基础验收的建议命令：

```bash
curl --head http://<FORMAL_DOMAIN>/health
curl --fail --silent --show-error https://<FORMAL_DOMAIN>/health
curl --head https://<FORMAL_DOMAIN>/health
sudo systemctl --no-pager --full status \
  video-replica-api.service video-replica-worker.service video-replica-backup.timer
sudo journalctl -u video-replica-api.service -u video-replica-worker.service \
  --since "30 minutes ago" --no-pager
sudo -u video-replica /opt/video-replica/app/server/.venv/bin/python -m app.backup \
  check /var/lib/video-replica/app.db
```

未获得真实支付授权、目标服务器、COS 权限和 Provider 账号前，以下项目保持未完成：

1. 在真实域名创建一笔最低 100 元充值订单；
2. 使用授权付款账号完成支付，记录订单号尾号、金额、支付时间和 ZPay 交易号尾号；
3. 验证同步返回页只提示确认，异步通知后本地订单变为 `PAID`；
4. 验证钱包只增加 10 条且只有一条 `CHARGE`，重复通知不重复入账；
5. 创建一条真实任务，记录 `RESERVE`；
6. 验证真实结果进入当前 COS 私有桶，可重新签发下载 URL 后才写 `SETTLE`；
7. 验证 Provider 终态失败路径写 `RELEASE`；不要为了测试失败而无必要发起额外付费调用；
8. 将真实 ZPay、COS 和 Provider 证据分别写入验收记录，隐去密钥、完整签名、完整临时 URL 和个人付款信息。

真实支付是外部资金动作，必须由授权人员明确批准后执行。本地 Fake 证据、自动化通过、代码提交或部署文件均不能替代这一步。

## 10. 回滚流程

每次发布前记录当前链接和数据库备份：

```bash
readlink -f /opt/video-replica/app
sudo systemctl start video-replica-backup.service
sudo journalctl -u video-replica-backup.service -n 50 --no-pager
```

已有部署升级时，还要把当前环境、systemd、Nginx 和 Basic Auth 文件备份到 root-only 目录；`<PREVIOUS_COMMIT>` 必须与上方 `readlink` 结果一致：

```bash
sudo install -d -o root -g root -m 0700 \
  /etc/video-replica/history/<PREVIOUS_COMMIT>
sudo cp -p /etc/video-replica/internal-p0.env \
  /etc/systemd/system/video-replica-api.service \
  /etc/systemd/system/video-replica-worker.service \
  /etc/systemd/system/video-replica-backup.service \
  /etc/systemd/system/video-replica-backup.timer \
  /etc/nginx/conf.d/video-replica-internal-p0.conf \
  /etc/nginx/video-replica-admin.htpasswd \
  /etc/video-replica/history/<PREVIOUS_COMMIT>/
```

代码回滚使用上一个已验收 release，不删除新 release，方便事后审计：

```bash
sudo systemctl stop video-replica-worker.service video-replica-api.service
sudo ln -sfn /opt/video-replica/releases/<PREVIOUS_COMMIT> /opt/video-replica/app
```

若本次发布替换过环境、systemd 或 Nginx 文件，代码链接回退后还要从上述 root-only 备份恢复对应文件：

```bash
sudo cp -p /etc/video-replica/history/<PREVIOUS_COMMIT>/internal-p0.env \
  /etc/video-replica/internal-p0.env
sudo cp -p /etc/video-replica/history/<PREVIOUS_COMMIT>/video-replica-*.service \
  /etc/video-replica/history/<PREVIOUS_COMMIT>/video-replica-backup.timer \
  /etc/systemd/system/
sudo cp -p /etc/video-replica/history/<PREVIOUS_COMMIT>/video-replica-internal-p0.conf \
  /etc/nginx/conf.d/video-replica-internal-p0.conf
sudo cp -p /etc/video-replica/history/<PREVIOUS_COMMIT>/video-replica-admin.htpasswd \
  /etc/nginx/video-replica-admin.htpasswd
```

完成代码和可选配置恢复后，统一重载并启动：

```bash
sudo systemctl daemon-reload
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl start video-replica-api.service video-replica-worker.service
curl --fail --silent --show-error http://127.0.0.1:8000/health
```

若新版已写入不兼容数据，还要按第 7 节从发布前备份恢复 SQLite，然后检查项目、任务、账务流水和审计记录。未验证新版应用能读取旧数据前，不单独回滚数据库。
