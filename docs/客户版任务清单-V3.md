## 0. 使用规则

- `[ ]` 未开始；`[~]` 进行中；`[x]` 已完成并有证据；`[!]` 阻塞。
- S = 0.5–1 人日；M = 1.5–3 人日；L = 3–5 人日；XL = 5–8 人日。
- 每个任务先写失败测试或锁定回归，再实现；一个任务可以有多个小提交，但一个提交不能混入多个无关任务。
- 规模是熟悉当前仓库的工程投入，不含等待服务器、外部平台、付费授权和灰度观察的自然时间。
- 任务完成不等于生产完成；必须分别记录 `CODE_PRESENT`、`AUTOMATED_VERIFIED`、`STAGING_VERIFIED`、`REAL_CHAIN_VERIFIED`、`PRODUCTION_GO`。

## 9. 任务卡最小字段

每个实际开发任务必须补齐：

- 任务 ID、owner、reviewer、分支名；
- 上游规格段落和目标文件；
- 先失败的测试或回归证据；
- 数据迁移、API、前端、部署影响；
- 可观测字段和安全边界；
- 完成命令及输出摘要；
- 回滚方式和未测试项；
- 中文 Lore 提交 SHA。

## 10. 单任务 Definition of Done

- 测试先红后绿，相关全量测试无回归；
- Ruff/format/mypy 与 Biome/TypeScript/Vitest 按影响面通过；
- 数据库约束、并发竞态和失败路径有自动化证据；
- 无真实 secret、明文激活码、设备 token、session token；
- API/OpenAPI、配置样例、运维和用户文档同步；
- 认证、账务、并发任务经过独立 reviewer；
- 可回滚或明确记录不可逆迁移与恢复步骤；
- 未通过真实链路时不得标记 `PRODUCTION_GO`。
