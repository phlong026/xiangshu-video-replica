# 本地服务状态与人物图片缓存开发说明

## 目标

本次只解决两个已确认的小问题：

1. 工作台右上角不再显示“本地服务已连接”等可见文字，改成手机信号式图标；已连接为绿色，异常为红色，连接中为黄色。
2. 人物库预览图首次从对象存储读取后持久化到本机，后续打开人物库优先读取本机缓存，不再为同一资产重复下载云端文件。

## 实现边界

### 服务状态图标

- 继续复用现有 `ServiceState` 和健康检查轮询，不改变连接判定逻辑。
- 图标由四根递增高度的信号柱组成，不引入图片或第三方图标库。
- 可见区域只显示图形；`role="status"`、`aria-label` 和 `title` 保留完整中文状态，保证读屏和悬停提示可用。

### 人物图片本地缓存

- 缓存对象仅限人物库会展示的 `character_contact_sheet` 与 `character_generated_image`。
- 前端通过新的“人物缓存地址”接口取得预览 URL；首次请求时，本地服务从原存储读取并原子写入本机缓存，之后直接复用缓存文件。
- 缓存文件以“资产 ID + 内容哈希/存储 URI”的摘要命名。人物重新生成会产生新资产 ID，因此自然获得新缓存，不覆盖旧版本。
- 缓存默认写入：
  - 配置了 `VIDEO_REPLICA_HOME`：`$VIDEO_REPLICA_HOME/storage-cache/character-images/`
  - 否则：`$VIDEO_REPLICA_STORAGE_ROOT/.cache/character-images/`
- 浏览器只拿到短时 HMAC 签名的本机地址，不能用路径参数读取缓存目录外的文件。
- 手动下载人物图片也复用该缓存地址，避免预览已缓存后再次访问云端。

## 异常与降级

- 不支持的资产类型返回明确的 `409 CHARACTER_CACHE_UNSUPPORTED`。
- 云存储读取失败或本机缓存写入失败返回 `503 CHARACTER_CACHE_UNAVAILABLE`，并记录不含密钥和签名 URL 的错误日志。
- 缓存签名缺失、过期或错误返回 `403 CHARACTER_CACHE_FORBIDDEN`。
- 缓存文件不存在返回 `404 CHARACTER_CACHE_NOT_FOUND`。

## 验收标准

1. 连接成功时右上角只有绿色信号图，无可见状态文字；断开时为红色，连接中为黄色。
2. 状态图仍可通过 `role=status` 和中文可访问名称被测试与读屏识别。
3. 同一人物资产连续请求两次缓存地址时，底层云存储 `get_object` 只调用一次。
4. 第二次请求返回的地址能从本机读取到与云端一致的图片字节和 Content-Type。
5. 人物库预览与下载均调用缓存地址接口，原有人物创建、改名、删除、重新生成行为不变。
6. 前端单元测试、后端相关测试、类型检查、格式与静态检查全部通过。

## 暂不处理

- 不增加缓存容量上限或自动清理策略；人物图片按当前长期保留策略持久化。
- 不缓存参考视频、首帧、生成成片等非人物库资产。
- 不改变 COS 生命周期或对象删除策略。
