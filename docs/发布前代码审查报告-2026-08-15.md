## 一、发布阻断项（CRITICAL + HIGH，按优先级）

### CRITICAL-1 Windows 打包桌面端无法端到端运行（无后端自动拉起）
- 位置：`client/src-tauri/src/lib.rs`、`client/src/api.ts:3`
- 问题：Tauri 应用是纯空壳，无 shell/spawn 插件，不拉起 FastAPI/Worker；NSIS 只装前端壳，不装 Python 3.12/uvicorn。
- 失败场景：员工安装后 `/health` 无监听 → 全线不可用。
- 修复：先做服务端分发架构决策（PyInstaller sidecar / 内嵌 Python / NSIS 后置），Tauri 侧用 `std::process::Command` 或 `tauri-plugin-shell` 拉起并健康检查，Windows 实机验证。

### HIGH-1 Tauri 打包版 CSP 拦截全部预览图片与云端上传（dev 正常、打包后不可用，极易漏检）
- 位置：`client/src-tauri/tauri.conf.json:23`
- 问题：`img-src`/`connect-src` 未含 `http://127.0.0.1:8000` 与 COS/OSS 域名。
- 修复：CSP 加入本地后端与存储域名，或后端做同源图片代理；**打包版实机验证**。

### HIGH-2 全局 5 秒超时过紧，AbortError 英文消息泄漏给用户
- 位置：`client/src/api.ts:4, 738-741, 807-810`
- 问题：所有 API 统一 5s 超时；云端操作（诊断、预检、签名 URL）冷启动超 5s；abort 后显示英文错误。
- 修复：AbortError 归一化为中文"请求超时，请重试"；云端操作用更长超时（30-60s）。

### HIGH-3 batch 轮询无限退避 + localStorage 自动恢复
- 位置：`client/src/App.tsx:133-181, 91-101`
- 问题：404/故障都进退避循环，无重试上限；每次进项目页自动恢复历史 batch id 触发无限轮询。
- 修复：404 视为硬错误停止轮询 + 提供清除入口；网络错误设最大重试次数；恢复前校验 batch 存在性。

### HIGH-4 dev 认证 X-Dev-User-Id 完全可伪造（发布硬阻塞）
- 位置：`server/app/auth.py:47-86`
- 问题：一个自定义 header 直接映射任意用户；任何本地进程可伪造 admin；一旦绑定非回环或多用户即裸奔。
- 修复：生产化前引入真实签名会话（服务端签发随机 token，`Authorization: Bearer`），或至少收紧回环绑定 + 启动检查。

### HIGH-5 ARCHIVE_FAILED 无任何重试路径，付费结果永久丢失
- 位置：`server/app/generation.py:874-877, 907-939`
- 问题：归档失败任务永不被重新拾起（租约只捞 PENDING/QUEUED），批次进度永久停 100% 以下；迁移 005 已删 result_url 无处重下。
- 修复：为 ARCHIVE_FAILED 加可重拾状态 + 结果暂存（记录 provider_result_url/字节位置）+ 管理员重试归档接口。

### HIGH-6 SUBMISSION_UNCERTAIN 只有停靠没有恢复/对账路径
- 位置：`server/app/generation.py:1052-1074`
- 问题：付费保护方向正确，但无重新查询对账、人工确认后安全重提、续轮询的接口；create 响应丢失时无法找回。
- 修复：补对账/恢复端点（按 provider_task_id 重新查询补归档；provider_task_id 为空时人工确认未计费后重提）。

### HIGH-7 幂等键未按 project 隔离，并发重复提交返回误导性 409
- 位置：`server/app/generation.py:581-597`、迁移 `001_core.py:111`
- 问题：幂等查重不含 project_id，跨项目复用 key 会静默返回他项目批次；并发冲突抛 PROMPT_ALREADY_USED 409 误导。
- 修复：幂等作用域纳入 project_id（需迁移唯一约束），并发冲突时回查既有批次而非抛 409。

### HIGH-8 local 存储下载链路断裂（只有上传代理，没有下载代理）
- 位置：`server/app/rbac_routes.py:388-427`、`server/app/media_routes.py:141`
- 问题：local 模式 `create_download_url` 返回 `local://...`，前端直接当 `<img src>` 用 → 预览/下载全断。
- 修复：加 `GET /api/assets/local-objects/{key}` 下载代理（复用 put 的鉴权/校验），local 下载 URL 返回服务端地址。

### HIGH-9 依赖漏洞：cryptography 46.0.5 有 11 个已知漏洞
- 位置：`server/pyproject.toml`（`cryptography==46.0.5`）
- 问题：uv audit 报 11 个漏洞（OpenSSL 轮、Bleichenbacher oracle、DNS 约束等），修复版本 46.0.6~50.0.0 不等。
- 修复：升级 cryptography 到 >=49（或 50），`uv lock` 更新 + 全量测试验证 Fernet 兼容。
