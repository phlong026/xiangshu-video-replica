## 三、Phase 0 实测核心结论（决策依据）

完整数据与证据：`E:\工作文件夹\phase0-harness\`（仓库外）；结论级摘要见方案文档附录 C。要点：

1. **网关换行注入**：响应体被周期性注入 `\r\n`（4-carbon 路线 18/18，3.8-flash 1/18）——T15 兜底是 4-carbon 可用性的硬前置，已实施。
2. **4-carbon 分段召回由候选密度驱动**：稀疏候选下严重欠分割（6 段 vs 真值 13–14）；加密候选后命中真值，但延迟/成本与 3.8-flash 同档——"4-carbon 更快更省"是浅输出假象。
3. **断连集中在长视频链路的 3.8-flash**：180s 素材两次网关断连（332s/570s）；4-carbon 零断连且 15–58s。
4. **网关存在跨模型缓存/同源返回**：同素材重分析可能命中缓存，不影响正确性。
5. **Phase 2 lint 实战命中**：3.8-flash 长视频 2 次缺时长要素软警告生效。

→ 由此形成 **D9 按链路路由**：分镜主链路 `gemini-3.8-flash`（分段命中真值、短素材零失败）+ 备选 4-carbon；长视频一段式 `gemini-4-carbon`（快 3–6 倍、零断连、无分段需求）+ 备选 3.8-flash；优化器钉死 3.8-flash；可选设置键 `replica_prompt_model(_fallbacks)` 独立覆盖。

### P1 — T12 生产灰度复测（方案附录 C 口径）
1. 每支素材 ≥3 次：耗时 / 一次通过率 / usage / 拆解质量；
2. **扩充真值样本**：现分段真值仅一支动画 CG 预告片——需从真实爆款素材库挑 1–2 支实拍快切视频（实拍硬切与动画软切的切点可检测性不同，这是目前结论的最大样本局限）；
3. 复测数字记内部系统，结论摘要回填方案文档附录（T13 尾项）。

### P2 — Phase 0 未完成的开奖项：Gemini 原生格式验证
中转网关文档证实原生格式 `generateContent` 全模型可用且暴露 `thinkingConfig`，但**视频是否可经 `fileData` 透传未验证**（Phase 0 只验证了 OpenAI 兼容路线）。若透传成立，可解锁：`videoMetadata.fps` 采样控制、`responseSchema` 枚举白名单下沉（把 T2 的运行时校验前移到 API 层）、`mediaResolution` 成本档位。验证成本约一次调用；成立与否只影响后续协议演进，不阻塞现网。
