# 30 秒 AI 视频生成实现说明（2026-11-01）

> 性质：功能实现说明。范围：独立创作「AI 视频」入口时长契约从 4–15 秒放开到
> 4–30 秒，16–30 秒为独立计费长档（后台可设单价，档位默认关闭）。
> 复刻流与全部上传门禁（media / analysis / viral 的 15 秒边界）零改动。

## 一、机制调研结论（技术前提）

- 上游产品页（metaso.cn/minimax-h3）官方确认：H3 时长可选 **4–30 秒**；
  **16–30 秒按基础费用的 2 倍计费**（其官方称「长视频规则」，价格表按
  「15 秒及以内 / 16–30 秒」分档，768P 10.20 → 20.40 积分/秒，恰为 2 倍）；
  **480p / 768P / 1080p 最长 30 秒，2K 最长 15 秒**；参考素材约束不变
  （图 ≤9、视频 ≤15s、音频 ≤15s）。
- MiniMax 官方 API 单次仍 4–15 秒：30 秒是上游平台层扩展（内部链式生成 +
  拼接），对调用方是**一次请求、一条成片直链**。因此本系统无需自建片段链
  编排/拼接，成片仍走 DIRECT 直链交付，「不下载、不转存」原则不破。
- **付费探针已实证（2026-11-01，脚本 `server/scripts/probe_video_long_tier.py`）**：
  v2 直通端点对 `duration=16-30` 放行，「首帧图生 + 30 秒」组合同样放行。
  实测：16 秒文生任务受理并成功（成片 16.0 秒）、30 秒首帧图生任务受理并成功
  （成片 30.0 秒），`usage.output_seconds` 精确回传成片秒数、成片直链正常交付
  ——按秒结算与 DIRECT 交付链路对长档零改动成立。无需加「首帧限制」门禁。

## 二、计费档位（客户售价与平台成本按档分离）

- 新科目 `video_768p_long`「视频生成 · 768P · 16-30秒」（unit=second），
  与 `video_768p` / `video_2k` 同构（先例：按分辨率分科目）。
- 迁移 `20261101T1000_video_long_tier`（PG-only）：种子一行，
  `unit_credits`/`unit_cost_fen` = 768P 现值 ×2（对齐上游 2 倍成本结构），
  **enabled=false 默认关闭**——档位是否放开是经营决策。
- **运营开启步骤**：管理端 → 系统设置 → 费率管理（BillingRatesManager）→
  找到「视频生成 · 768P · 16-30秒」行 → 核对/修改售价与成本 → 启用。
  开关即档位上线闸，客户侧时长选项与报价随之放开。
- 选档唯一入口 `generation_service_for(resolution, seconds)`（billing_catalog），
  报价、validate_quote、预留、重试补偿四处共用——accept_operation 强校验
  快照科目与预留科目一致，任何一处绕开都会当场暴露。
- 卡单对账（billing_reconciliation）、补时长证据（billing_evidence）、
  对账终态分支（usage_billing）、子账号功能准入（sub_account_permissions）
  均已登记长档科目。

## 三、契约与闸门（分层防御）

| 层 | 位置 | 行为 |
| --- | --- | --- |
| 请求契约 | `independent.py` `output_duration_seconds` | ge=4, le=30 |
| 建单闸 | `independent.py` create_independent_batch | >15 时：2K → 422 `DURATION_RESOLUTION_UNSUPPORTED`；768P 长档价目未启用 → 422 `LONG_DURATION_TIER_DISABLED`（fail-closed：没有启用的价目就绝不让长任务按 0 积分放行）。闸在幂等回放之后，档位中途关闭不影响已建任务取回 |
| 报价闸 | `generation.py` generation_price_quote | 同上两闸前置——不给出无法成交的报价；返回体新增 `price_tier: "4-15s" / "16-30s"` |
| 客户档位 | `generation.py` CUSTOMER_DURATION_OPTIONS | range(4, 31)；复刻流 batch 契约保持 le=15 |
| Provider 硬闸 | `_validate_h3_duration`（build / I2V / R2V 三处共用） | 4–30 整数 + 2K 超档本地拒绝（不烧一次不确定的调用） |
| 能力下发 | `GET /api/independent/capabilities` | `max_output_duration_seconds`：读长档价目启用态，15 或 30 |

## 四、前端（页面备注口径）

- 时长下拉按 capabilities 渲染 4–N 档，长档选项带「（长档）」后缀；上限收窄
  （切 2K / 后台关档）时草稿自动钳回，选择器显示值与提交值恒一致。
- **页面备注（产品口径，须明示）**：长档开放时时长选择器常驻提示
  「16–30 秒为长视频档：单价为 15 秒及以内的 2 倍——选择 30 秒时总价即
  15 秒成片的 2 倍」；确认弹窗费用行随 `price_tier` 再标注一次。
- `normalizeCustomerDuration(seconds, max=15)`：默认上限 15，复刻流等
  调用方零改动；AI 视频链路（报价/提交/提示词优化）同源传 capabilities 上限。
