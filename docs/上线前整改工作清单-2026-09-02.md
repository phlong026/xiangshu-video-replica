## 评估登记（本轮评估后处置结论）

1. **R1（COS I/O 在 fenced 事务内）**：业务流程分析报告定级 P2 可用性。复核确认媒体预检发生在客户 fenced 写事务内（连接池占用上限 ~8，50MB 下载 + ffprobe 可达数十秒）。整改涉及事务边界重排（预检移出围栏、写回时二次校验），属高风险重构；按"上线冻结期不大动"原则登记延后，缓解措施：池上限 64 ceiling + 超时 30s 兜底、后续单独任务实施。
2. **Tauri 孤儿进程/版本协商/无更新器**：内部版 `start-backend.bat` 拉起的 API/Worker 在应用退出后残留（客户云构建无 sidecar，不受影响）。修复需重排进程树管理（PID 跟踪 + Job 对象），无法在 CI 内验证运行时行为；登记延后至 DESK-03 实机任务一并处理。缓解：安装器钩子升级时清理旧版；`/health` 5s 徽章轮询可暴露异常。无自动更新器 → 发布流程明确"手动发版 + NSIS 升级钩子防双装"（见 T45 发布说明）。
3. **`locked_until` 应用时钟 vs DB 时钟混用**：租约时长受主机漂移影响（≤120s 步进、600s 上限内偏差有限，且过期判定统一 DB 时钟）。改动触及公平队列热路径（10k 压测基准），冻结期内登记延后。
4. **任务级 attempt 全局上限**：现行语义为 provider-failed 终态兜底 + 归档重试上限 5；产品语义需确认后再加上限，登记待产品输入。
5. **AuditEventsPage 过滤输入会触发重复请求**：输入操作人 ID 时 useEffect 即加载一次，点击"筛选"再发一次同参请求（功能正确，浪费一次请求）。后续可做防抖或改为仅提交时加载。
6. **SettingsPanel 保存失败用 `role="status"` 而非 `role="alert"`**：屏幕阅读器不会即时播报错误；属可访问性增强，随下次设置面板改动一并处理。
