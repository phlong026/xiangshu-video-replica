## 1. P0 任务卡

### MATERIAL-UX-01 分组与批量（方案 P0-1 + P0-2）

**目标**：分组从"逐条自由文本"升级为"可导航、可批量维护的轻实体"；列表支持多选批量操作。解决"改 20 个素材分组要点 20 次"。

**改动范围**

- 后端（`materials.py` / `material_routes.py`）：
  - 新增 `GET /api/studio/materials/groups` → `[{name, count}]`（对当前用户可见素材按 `COALESCE(NULLIF(group_override,''), base_group)` 聚合）；
  - 列表 API 增加 `group` 精确筛选参数（含"未分组"语义），不改 5 分支 UNION 结构；
  - 新增 `PATCH /api/studio/materials/bulk`：`{material_ids: [≤100], update: {group?, hidden?}}`，逐条 owner 校验，返回 `{updated, skipped}`；
  - 分组"重命名/删除"由前端组合批量接口实现（批量改文本），不建 `material_groups` 实体表。
- 前端（`ContentPages.tsx` / `live.ts`）：
  - 分组导航：全部 / 未分组 / 各分组 + 计数；
  - 详情面板分组编辑改为选择器（已有分组下拉 + "新建分组"输入），消灭自由文本碎片；
  - 上传流程支持选择目标分组（默认"我的上传"）；
  - "整理"模式：卡片可勾选、全选本页、跨页选中用 Set 累积；批量条：移入分组 / 移入回收侧（先做隐藏）/ 批量下载（Web 端连续触发或提示；桌面端 ZIP 列为待定，不在本任务）。

**文件边界**：`server/app/materials.py`、`server/app/material_routes.py`、`client/src/studio/ContentPages.tsx`、`client/src/studio/live.ts`、`client/src/generated/api`、对应测试。

**依赖与并行**：无前置。开工前完成信息架构布局确认（§0.2）；合并前与 02/03/04 串行。

**验收标准**

1. 能创建分组（经选择器新建）、上传时选分组、按分组筛选；
2. 批量移动 24 条素材 ≤3 次操作；分组改名一处生效（批量）；
3. 本页全选后一次移组 / 移除成功；跨页选择不丢失；
4. 越权素材（他人）在批量接口逐条跳过且有审计记录；`material_ids > 100` 被拒。

**测试要点**

- 后端：分组聚合计数正确性（含 hidden 素材不计入）、`group` 筛选边界（空值/未分组/中文）、批量接口越权逐条跳过、上限拒绝、direct 素材（generation 来源）hide 语义与资产类不同的既有用例保持（`materials.py:634-637`）；
- 前端：整理模式选择集跨页一致性、批量条动作调用、分组导航计数刷新；
- 契约：新端点与参数进 OpenAPI 并有 e2e 覆盖。

**风险与注意**

- `PATCH bulk` 复用 `studio_material_preferences` upsert 语义（`materials.py:848-973` 先例）；批量隐藏走 `preserve_overrides` 路径时不得覆盖 title/group（`materials.py:1383-1398`）；
- 上传选分组依赖分组列表接口，注意空分组的第一条创建路径。

### MATERIAL-UX-02 卡片尺寸修复与图片缩略图（方案 §6 P0）

**目标**：网格卡片不再裁切竖屏主体（当前 9:16 框被 140px 视窗裁掉，竖屏只显示中段约 37%）；图片走派生缩略图；视频/音频时长常显。

**改动范围**

- 前端：
  - 给 `fitContainer` 模式加独立类（如 `.video-preview--fit`）：不再应用 `aspect-ratio: 9/16`，改为填满视窗 + 前景 `contain` + 模糊背景兜底（复用现有 backdrop 能力，`video-preview.css:36-42`）；不写内联比例的分支逻辑不动（`VideoPreview.tsx:175-186`）；
  - 卡片媒体区高度 140 → 160px（`content.css:341` 网格行高与 `.content-asset .studio-media` 同步）；
  - 时长角标常显：视频/音频瓦片不再与"有无封面"互斥（`ui.tsx:370-375`）。**此项与方案 §4.2 P0-3 中"时长常显"合并到本任务，避免两个任务重复改 Media 组件**。
- 后端（`material_thumbs.py` / `materials.py`）：
  - 扩展为 image 派生 `<object_key>.thumb.jpg`（PNG/JPEG/WebP → 缩放到 ≤480 高），复用确定性派生键与 7 天签名模式；素材上传 complete 处接线 + `ensure_thumbnail_object` 按需派生兜底；存量素材不批量迁移（按需派生）；
  - 保持视频链路三个写入点行为不变（`materials.py:1162-1195`）。

**文件边界**：`client/src/video-preview.css`、`client/src/studio/content.css`、`client/src/studio/ui.tsx`、`client/src/studio/ContentPages.tsx`（媒体区调用点）、`server/app/material_thumbs.py`、`server/app/materials.py`（complete 接线）、对应测试。

**依赖与并行**：无前置；与 01/03/04 共享 `ContentPages.tsx`/`ui.tsx`，按 §0.2 串行。

**验收标准**

1. 竖屏视频/图卡片主体完整可见、无核心内容裁切；横竖混排各自比例正确；
2. 图片网格走缩略图（单卡数百 KB 级），首屏加载明显改善；详情仍用原图；
3. 视频/音频瓦片常显时长角标（同款多视频可快速区分）；
4. 既有缩略图与预览链路无回归。

**测试要点**

- 前端：媒体区快照 / 类名断言（fit 模式无 9:16）；时长角标条件变更用例；
- 后端：图片缩略图派生（多格式、失败不阻塞原链路）、签名与鉴权沿用、视频缩略图既有用例不动；
- 视觉校验：竖屏 / 横屏 / 方形 / 音频四类卡片截图。

**风险与注意**

- 缩放实现复用现有媒体处理设施，不引入新的重依赖（实现方式在方案评审时确定）；
- 图片格式探测失败时按"无缩略图"降级（沿用视频的失败不阻塞语义）。

### MATERIAL-UX-03 浏览与信息补全（方案 P0-3 + P0-5）

**目标**：找得到的最后一公里——排序、卡片信息、对象（人物/项目）筛选与归属显示。

**改动范围**

  - `MaterialItem` 增加 `person_name` / `project_title`（从既有 CTE 的 `display_name` / `project.name` 派生，`materials.py:309,327`）。
- 前端：
  - 排序下拉（"最新上传"等，设计稿已画）；
  - 卡片 meta 行补创建时间（相对时间，复用 `formatTaskTime` 风格，`ui.tsx:386-407`）；
  - 详情面板补"上传时间 / 文件大小 / 时长"三行（数据均已返回）；
  - "归属"显示"张工（人物库）/ 某某别墅项目"并可点击跳转；
  - 来源筛选下拉增加"按人物 / 按项目"二级选择（数据源复用已加载的人物列表 / 项目列表）。

**文件边界**：`server/app/materials.py`、`server/app/material_routes.py`、`client/src/studio/ContentPages.tsx`、`client/src/studio/live.ts`、`client/src/generated/api`、对应测试。

**测试要点**

### MATERIAL-UX-04 上传增强（方案 P0-4）

**目标**：从"单文件、无拖拽、不可取消"升级为多文件队列 + 拖拽 + 预校验 + 去重提示。

**改动范围（前端为主）**

- `<input multiple>` + 顺序上传队列（显示"2/5 上传中"），逐文件独立成败与重试；进度不可取消的现状在队列中保持"逐个进行"即可（取消能力列为待定）；
- 页面级拖拽上传（拖动高亮整个列表区）；
- 上传前选择目标分组（与 01 联动，默认"我的上传"）；
- 去重提示：消费 `upload_required=false` + `reused_from_asset_id`（`materials.py:176-181`），toast"检测到相同文件，已复用已有素材"；
- 客户端大小预校验：图片 ≤10MB / 视频音频 ≤50MB（与 `materials.py:61-92` 常量对齐，声音克隆 20MB 特例单独判断），超限在客户端拦截并给明确提示。

**文件边界**：`client/src/studio/ContentPages.tsx`（上传区）、api client、对应测试。

**依赖与并行**：与 01 联动（选分组）；建议 01 合并后开工。

**验收标准**

1. 多文件顺序上传有进度与独立失败态，单个失败可重试不影响其余；
2. 拖拽上传可用；上传前可选目标分组；
3. 重复文件上传有"已复用"提示；
4. 超限文件在客户端即被拦截，不再等待后端 413。

**测试要点**

- 前端：队列顺序与失败隔离用例、预校验边界（10MB/20MB/50MB）、去重响应的 toast 分支、拖拽事件处理；
- 回归：上传三步链（intent→PUT→complete）既有用例不回归。

**风险与注意**

- 顺序队列（不并发），避免打爆 COS 与 PG 写连接；
- 桌面端（Tauri）拖拽与浏览器事件差异需覆盖基础用例。

### MATERIAL-UX-05 标签底座（方案 P1-1）

**目标**：为多维度组织（项目 × 场景 × 用途）提供标签体系，是 AI 标引与智能分组的前置。

**改动范围**

- 迁移：`studio_material_preferences` 新增 `tags_json`（JSONB，默认 `[]`）；命名挂在当时最新 head 后（参照 `071_studio_material_preferences`，不改历史 revision）；
- 后端：`MaterialItem.tags`；PATCH 支持 tags（与 01 的 bulk 复用同一偏好 upsert）；列表 API 增加 `tag` 过滤（JSONB 包含）；新增 `GET /api/studio/materials/tags` 聚合（标签 + 计数）；

### MATERIAL-UX-10 使用记录（方案 P2-4）

**目标**：素材详情显示"被 N 个任务引用"，可跳任务详情，缓解"不敢删、重复传"。

### MATERIAL-UX-12 智能分组 / 保存筛选（方案 P2-2）

**目标**：Eagle 式"智能文件夹"——把"人物=张工 + 类型=视频 + 标签=庭院"保存为命名视图。

### MATERIAL-UX-13 AI 智能标引（方案 P2-1）
