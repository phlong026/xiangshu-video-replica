## 0. 使用规则

### 0.1 状态标记

| 标记 | 含义 |
| --- | --- |
| `[x]` | 已完成，且证据路径已填写 |
| `[~]` | 代码或局部 UI 已存在，但未达到本任务验收标准 |
| `[ ]` | 未开始或无可验证实现 |
| `[!]` | 依赖真实账号、外部资料、Windows 机器、证书或业务签字 |

不得只因接口、组件、测试文件或打包配置存在就勾选任务。每项必须满足本清单中的退出标准。

### 0.2 开发纪律

每个子任务按以下顺序执行：

1. 写一个失败的回归/契约测试；
2. 用最小改动实现；
3. 跑目标测试；
4. 跑相关 lint、类型、格式、构建和安全检查；
5. 查看完整 diff，确认没有覆盖他人未提交改动；
6. 一个逻辑变更一个中文 Lore 提交。

数据库迁移必须可逆；人物历史版本、项目快照和资产引用不得通过破坏性迁移重写。

### 0.3 当前工作树提醒

任务 09 从审计基线 `main@7b0f2a2` 创建，该基线已完成任务 00–08 合并与工作树收口：

- V1.3 执行账本、质量绿线、CI 门禁、人物域、桌面身份/RBAC、角色版本 API、Fake 七视角生成、审核发布与人物参考匹配均已通过 PR 合并；
- `.omc/` 已作为本地运行状态加入 `.gitignore`；
- 审计开始时 `main` 与 `origin/main` 一致且工作树干净；
- 后续每个逻辑任务必须从最新干净 `main` 创建独立 `feat/*` 或 `fix/*` 分支，不在 `main` 直接开发。

禁止用重置、检出或覆盖方式清理来源不明的改动；发现混合工作树时先停在当前分支完成归属审计。

## 14. 推荐实施顺序

第一开发增量只做人物资产纵向切片，不同时重构现有 H3 后端：

1. P0-00-01：保护当前工作树并建立功能分支；
2. P0-00-02：先写人物领域 API/迁移失败测试；
3. P0-01：完成四层人物模型和旧数据兼容迁移；
4. P0-02：打通真人源图上传、授权、人设和版本；
5. P0-03：FakeCharacterImageProvider、7 视角、审核、发布、匹配；
6. P0-04：人物库桌面端；
7. P0-05/P0-06：复用现有后端完成项目、Prompt、批次和结果 UI；
8. P0-07：桌面 FakeProvider E2E；
9. P0-08：真实 Provider；
10. P0-09/P0-10：Windows 和内部发布。

可并行但不得越过依赖：

- 后端人物模型与前端五入口 Shell 可并行；
- CharacterImageProvider 真实选型可与 FakeProvider 实现并行；
- Windows 构建环境准备可提前，但实机验收必须使用通过 Gate 1/2 的同一提交；
- Provider 证据收集不能替代本地契约测试，反之亦然。

## 15. 本轮不开发

- Electron 或 PostgreSQL 重写；
- LoRA/身份适配器训练；
- 跨项目批量生产；
- 文生视频和 H3 多对象参考；
- 独立 TTS、声音克隆、混音和口型同步；
- 自动剪辑、自动发布和社交矩阵；
- 对外注册、支付、会员和积分；
- Prompt 模板可视化 CMS；
- 未经真实验证的 Provider 别名、接口和价格常量。

任何上述内容都不能以“顺便优化”为由进入 P0 提交。
