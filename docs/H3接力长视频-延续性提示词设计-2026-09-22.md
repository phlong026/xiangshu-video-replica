# H3 接力长视频：延续性提示词设计（2026-09-22）

> 定位：`docs/H3接力长视频-社区工作流分析与实现设计-2026-09-22.md` 的专题细化。回答一个问题：**尾帧接力时，"从上一段继续"这个提示词到底该怎么写？**
> 结论先行：不需要发明新语法——H3 官方 I2VA 的原生推荐结构就是"从首帧向前发展"，本项目 `opening_action`（开场衔接）字段已就位；真正要做的是**把"继续"写成模型能用的三件事：状态锚定、动量延续、首动作推进**。

---

## 一、结论速览

1. **官方依据**（`docs/reference/minimax-h3-prompt-guide/`）：I2VA 推荐结构 = **first-frame anchor → action onset → continuous development → result or reaction**（首帧锚定 → 动作起势 → 连续发展 → 结果/反应）；官方 Tips 明确要求"clearly state how the first and/or last frame connects to the timeline"。**"从尾帧继续"正是 I2VA 的原生用法**，只是我们每段的首帧换成了上一段的产物。
2. **项目落点已就位**：`opening_action` 的输入 → 门禁 → 编译 → 持久化全链路现成（`h3_prompts.py:143,255-258`、`generation.py:242`）。设计工作不在"加字段"，在"写对话"。
3. **承接语三件事**：① 状态锚定（尾帧里能看见什么）→ ② 动量延续（正在进行的运动、方向和速度）→ ③ 首动作推进（本段第一个动作从该状态出发）。缺任何一件，模型都会"重新起势"或"误读状态"。
4. **一个必须知道的编译器行为**：写了 `opening_action` 后，首镜头的原"动作"行**不再输出**（`index == 0` 时走 `if` 分支，`else` 的动作行被跳过）——所以承接语是**复合职责**：既要"接住上一段"，也要承担"首镜头动作"。这是全篇设计的硬约束。
5. **六种写坏的方式**（§六）：静止式、矛盾式、重置式、过载式、风格式、抽象式——每一句反例都对应一个可检查的规则。

---

## 二、为什么必须配（原理）

### 2.1 不给承接语时，模型的两类偏差

尾帧接力时，模型收到的是一个**孤立的图像**，没有"这张图来自一段运动的中途"的知识。默认真空会被两类偏差填充：

| 偏差 | 表现 | 拼接后果 |
| --- | --- | --- |
| **静止起势偏差** | 把尾帧当"开拍前的静帧"：人物先停一下、再起势；镜头从静止启动 | 段间节奏断裂——上段末尾有速度，下段从零加速，接缝处"卡顿感" |
| **状态误读偏差** | 不读画面中的中途状态：手里的物体、半转身、说话的嘴型被当作"初始状态"重新演绎 | 动作矛盾——上段刚举杯，下段重演"拿杯"；上段转身一半，下段转回去从头转 |

这两类偏差正是社区在 latent 空间解决的问题（Motion Context 的"连续帧锚定"）；我们 API 路线只能在**提示词层**把等价信息补上——这就是承接语的全部职责。

### 2.2 官方怎么说的（三条原文依据）

- **结构**（base-en.txt §3.1）：I2VA "should first **establish the style, subjects, composition, and scene anchors** in the image, **then describe the next action**"，身份/服装/颜色/关键物体/空间关系保持一致；
- **句式示范**（Case 2，最能代表"继续"的写法）：
  - `the young woman shown in <Picture 1> **remains beside** the rain-covered train window, **preserving** her appearance, clothing, seat position, and the carriage layout`（状态锚定）
  - `she **lifts her gaze from** the folded letter toward the passing city lights`（从中途状态出发的动作）
  - `She folds the letter **along its existing crease**`（**尊重画面中已有的中途状态**——"existing crease"是本设计最重要的一个词）
- **项目规则**（`server/app/prompt_rules/I2VA.txt`）："不得写开场人物站立而实际首帧人物坐着，除非先描述起身过程"——这是**姿态**维度的状态矛盾规则；承接语把它扩展到**运动相位**维度（不止"坐着还是站着"，还有"动作进行到哪一步"）。

### 2.3 Runway 口径的补充

Runway 把尾帧接力（last-frame technique）称为"收益最大的一招"，但强调必须配 continuation prompt——下一段不重写全新描述，而是**描述上一段结束在哪里**。我们的三件事模型（§三）就是它的可执行版本。

## 三、承接语的内容模型（五要素）

| # | 要素 | 从哪里读 | 写法要点 | 例（尾帧显示：人物在楼梯口半转身，右手扶栏） |
| --- | --- | --- | --- | --- |
| 1 | **状态锚定** | 尾帧图（生成的产物） | 位置、朝向、姿态、服装、关键物体与空间关系；"对着图能核实"才算数 | "首帧中的主讲人保持半转身姿态，右手搭在楼梯扶手上，服装与首帧一致" |
| 2 | **动量延续** | 尾帧图 + 段计划 | 正在进行的动作、方向、速度感；明确"不重置、不回到静止" | "转身动作继续完成，方向不变，速度与上一段结尾一致，不回到正面站姿" |
| 3 | **首动作推进** | 段计划（本段第一个叙事节拍） | 承接语是复合职责：首镜头动作由它承担（§1.4 编译器行为） | "转身上楼的同时开口说出本段第一句内容" |
| 4 | **运镜衔接** | 段计划 | 上段结束运镜 → 本段起步运镜，用官方三要素（类型+幅度+速度） | "镜头保持缓推速度不变，继续随人物上移（Pedestal Up，小幅度）" |
| 5 | **环境/音频锁定** | 场结构 | 同场：陈设、光线、环境声与首帧一致；跨场：不锁，走场边界规则 | "场景、陈设与光线与首帧一致；环境声保持室内混响" |

**要素 5 的适用边界**：只在"场内接力"用。场边界段（3–5 段换场）**不接尾帧**，也不该写"与上一段一致"——那会阻止模型换景。

## 四、按段类型分四种模板

### 4.1 首段（开场段）：无承接，维持现状

`opening_action` 留空；走现有编译路径（`opening_action` 为空时正常输出首镜头"动作"行）。**无需任何改动。**

### 4.2 中间段（场内接力）：五要素模板（主力）

```
本段直接承接首帧画面（上一段结尾）的运动中途状态，不重置、不回到静止。
状态锚定：首帧中的主讲人保持<位置/朝向/姿态>，<关键物体>保持首帧中的状态与位置不变，服装与外观与首帧一致。
动量延续：<正在进行的动作>继续沿相同方向以相同速度推进并完成<结果>。
首动作推进：完成后立即<本段第一个动作>，从该状态自然继续。
运镜衔接：镜头保持<上段结束运镜>、节奏不变，延续为<本段运镜（类型+幅度+速度）>。
环境锁定：场景、陈设、光线与首帧一致；环境声保持<同一描述>。
```

填好的实例（复刻"乡墅讲解"类视频，尾帧=人物在客厅边走边说，手指向沙发）：

```
本段直接承接首帧画面（上一段结尾）的运动中途状态，不重置、不回到静止。
状态锚定：首帧中的主讲人保持侧身行走姿态与朝向沙发的视线方向，抬起的右手指向不变，服装与外观与首帧一致。
动量延续：行走与手势保持原方向、原速度继续，说完上一段未完成的话尾，不回到站定姿势。
首动作推进：手势自然落回后继续前行两步，转向镜头说出本段内容。
运镜衔接：镜头保持跟随移动（Tracking Shot）、小幅度、慢速，节奏不变。
环境锁定：场景、陈设、光线与首帧一致；环境声保持室内混响与远处环境音。
```

### 4.3 场边界段（换场）：不接尾帧，走自然新开头

**不填承接语**（或填"本段为新场景开始，与前段不要求画面连续"）；首镜头动作交回 shot 的"动作"行。切点即剪辑点——分段计划的场结构决定（"场"= 3–5 个连续单元）。

### 4.4 收尾段：FL2VA 收敛（可选）

若最后一段要精确落在指定结束画面（如品牌定格/封面帧），走 FL2VA（首帧=上段尾帧，尾帧=结束画面），承接语改为官方 FL2VA 的"路径"措辞：**从首帧状态 → 可见的中间变化 → 逐步收窄差异 → 落在结束画面**。注意官方提醒：FL2VA 优先单镜头。

## 五、与其他提示词元素的关系（防冲突）

| 相邻元素 | 规则 |
| --- | --- |
| `style_keys`（visual_style / color_tone / pace / camera_language） | 风格恒定靠这些键**逐段重复**，承接语**不写风格词**（反例：电影感、高级感） |
| 分镜动作（`shot.action`） | 承接语替代首镜头 action 行（编译器行为）——必须做"**动作对齐**"：把分镜里"本段第一个动作"与尾帧实际状态对照，矛盾时以**尾帧**为准改写（尾帧是事实） |
| 台词（`<d>`） | 跨段台词尽量在分镜切分时落在自然停顿；确需跨段时，承接语写"继续说完上一段未完成的句子"（段内跨镜头有 `<scenetrans>`，段间无此机制，只能靠措辞） |
| `overall_soundscape` | 场内各段用同一环境声描述（收敛），降低段间声场跳变；场边界自然切换 |
| 时长词 | 不出现（既有规则：成片时长由 API `duration` 参数承载） |
| 首帧对齐首行 | 不改：`For the target video, at 0.00 seconds... <Picture 1> (from [Shot 1]) is fully referenced.`（I2VA 官方固定句式，项目已实现） |

## 六、反例清单（六种写坏的方式）

| # | 反例 | 为什么坏 | 正确写法方向 |
| --- | --- | --- | --- |
| 1 | **静止式**："画面中有一位女士站在客厅里" | 只有场景没有状态和动量，等于没写，模型自由发挥 | 补姿态细节 + 正在进行什么动作 |
| 2 | **矛盾式**："双手自然垂下"（但尾帧里手举着） | 与事实画面冲突，模型要么忽略承接语、要么生成扭曲动作；违反 I2VA.txt 的状态矛盾规则 | 对着尾帧图核对每一句 |
| 3 | **重置式**："镜头缓缓推进，人物开始讲解" | "开始"= 重新起势，接缝卡顿 | "继续……不回到静止" |
| 4 | **过载式**：把本段全部叙事都塞进承接语 | 提示词过载（六种断裂模式之一），首镜头塞多个节拍 | 承接语只管"入轨"；后续节拍交给后续镜头 |
| 5 | **风格式**："电影感的画面继续推进" | 风格不是承接语职责；官方明确反对抽象词（"Prefer concrete visual and audio details over abstract words"） | 风格词进 style_keys，承接语写具体状态 |
| 6 | **抽象式**："自然衔接，流畅过渡" | 没有可执行信息；模型读不出任何状态 | 写具体：谁、什么姿态、什么动作、什么方向速度 |

**五问自检**（发布前对每条承接语过一遍）：
1. 第一句能不能对着尾帧图核实？（能→过）
2. 有没有"动量"（正在进行的动作/方向/速度）？
3. 首动作从状态出发，还是重新起势？
4. 运镜是延续还是重置？
5. 有没有风格词、抽象词、时长词、与画面矛盾的内容？

## 七、承接语怎么生产（三档演进，与实现设计 §3.5 对齐）

| 档 | 方式 | 时效性风险 | 成本 |
| --- | --- | --- | --- |
| **P0 人工** | 序列页逐段填写，用 §4.2 模板 + 五问自检 | 低（人对着尾帧写） | 0 |
| **P1 半自动** | 段计划增 `end_state` 结构化字段（五个要素各一段），系统拼模板 → 用户确认 | **中：用的是"计划状态"，可能与实际生成的尾帧不符**（生成有随机性） | 0 |
| **P2 智能** | 抽尾帧后交给 H3-Context-IR 或视频分析（看实际尾帧图）生成客观承接语 → 用户确认 | 低（图是事实） | Context-IR ¥0.05/次（`056_operation_cost_rates`） |

**关键判断**：承接语的**可靠来源是"实际生成的尾帧"，不是"计划中的结束状态"**——所以 P1 只是过渡，P2（看图写字）才是终态；P0 人工之所以可靠，正因为人是在看尾帧图后写的。

## 八、与编译器的集成（已核实的行为，供实施引用）

1. **字段链路（现成）**：`GenerationBatchRequest.opening_action`（`generation.py:242`，max 1000 字）→ `compile_replica_final_text(opening_action=…)`（`generation.py:1372`）→ 写入第 1 个镜头 `用户确认的开场衔接：…`（`h3_prompts.py:255-258`）→ 随 payload 持久化（`generation.py:1409`）。
2. **替代语义（现成，需设计侧记住）**：`index == 0` 且有 `opening_action` 时，首镜头的"动作"行不输出——承接语必须覆盖"首动作推进"（§1.4）。
3. **门禁扩展（待实施）**：首帧来源 = 上游段尾帧时必填承接语（现门禁只覆盖 `source_frame_time > 0.25`，`h3_prompts.py:156-159`）。
4. **不做的事**：不新增字段、不改首行对齐句式、不改三段落结构（`integrated_multimodal_description / overall_soundscape / non_diegetic_music`）。

## 九、验证方案（探针，付费需授权）

**对照实验**（同一尾帧、同一段计划，唯一变量 = 承接语有无）：

| 组 | 内容 | 条数 |
| --- | --- | --- |
| A | 无承接语（opening_action 空） | 3 条 × 15s 768P |
| B | 有承接语（§4.2 模板填好） | 3 条 × 15s 768P |

- 成本：$0.08/s × 15s × 6 条 = **$7.2（≈¥52）**；如需 2K 复验 ×1.625。
- 盲评维度（1–5 分）：接缝动作连续性 / 镜头连续性 / 人物稳定性 / 节奏断裂感（反向）。
- **判定标准**：B 组"接缝动作连续性"均值比 A 组高 ≥1 分且无一条劣于 A 组中位，即认定承接语有效；否则回到 §三 检查五要素是否写全。
- 无 seed：每组 3 条取分布，不看单条运气（既有结论：H3 无 seed 是架构级约束）。
