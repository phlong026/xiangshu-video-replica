| 步骤 | 做法 | 结论 |

| 路由契约机械比对 | 用 `app.openapi()` 导出后端 476 条 `METHOD path`，与前端非测试代码中全部 `/api/...` 字面量（含模板参数归一化）比对路径与方法 | 前端 227 个路径全部命中后端路由；方法不一致的疑似项逐一人工复核，均为脚本误报（方法写在 400 字符之外或经变量传入）。**不存在断链接口** |

## 1. 已核实无问题的关键链路（避免重复排查）

- **充值关单后仍付款**：客户「删除订单」只在本地置 `CLOSED`（`recharge_routes.py:787`），但回调对 `PENDING/CLOSED` 都会入账（`zpay_payments.py:458,472`），不会出现付了钱不到账。
- **口播取消**：前端只对 `backendStatus === "QUEUED"` 展示取消（`MainPages.tsx:1428`），与后端 `cancel` 仅允许 `QUEUED`（`oral.py:1133`）一致。
- **生成批次取消**：前端「排队中」映射 `PENDING/QUEUED`，后端所有创建通道都以 `QUEUED` 落库（`generation.py:2687,2883`），并在事务内校验全部子任务仍为 `PENDING` 后统一 RELEASE。
- **AI 拆解取消/接回**：前端换源、重来时取消旧任务（`CreationPages.tsx:1635`），后端把取消落为 `FAILED + ANALYSIS_TASK_CANCELLED`（`analysis_routes.py:1319-1332`），前端轮询以 `FAILED` 终止，口径一致。
- **视频报价与提交同源**：报价与提交都经 `normalizeCustomerDuration` 归一（`StudioWorkspace.tsx:210-216, 887-896`），提交前 `quoteMatchesInput` 复核。
- **发布定时**：前端 `toISOString()` 带时区，后端拒绝无时区时间并统一换算 UTC（`publish_records.py:238-248`）。
- **爆款文案正文下发**：任务接口对爆款任务返回 `result.text = null` 但 `result` 对象非空（`script_from_audio.py:118-128`），前端轮询 `task.status === "SUCCEEDED" && task.result` 能正常终止并转去 claim。
- **公告部分更新**：前端未填字段传空串，后端以「非空才覆盖」实现部分更新（`announcement_routes.py:265-302`），语义一致。

## 2. 前端业务模块梳理（前端逻辑 → 后端对照）

### 2.1 客户入口与会话（`RootApp.tsx`、`customer/useCustomerSession.ts`）

- 状态机：`checking → login / workspace`；登录、注册、找回密码三视图由 URL（`/login` `/register` `/forgot`）驱动；「记住密码」只在登录成功后写入凭据金库。
- 会话保持：工作台期间每 30 秒心跳（`useCustomerSession.ts:117,540`），窗口隐藏不暂停，恢复可见/聚焦时立即补一次。
- 后端：租约 `SESSION_LEASE_SECONDS = 90`，心跳只续租未过期的会话；租约一旦过期即终态，不可复活（`customer_session_service.py:395-440`）。→ 见问题 **P2-06**。

### 2.2 工作台（`studio/MainPages.tsx` `WorkbenchPage`）

- **上传视频**：只收 MP4/MOV；先读本地时长，>15.1 秒且为桌面端时本地抽音轨只传 `.m4a`，否则整片上传；统一以 `purpose="script"` 调 `uploadWorkbenchSourceVideo`（新建项目 → 上传意图 → 预签名 PUT → complete；失败删空项目）。
- **贴链接/爆款卡片**：`beginViralCreation` → 导入任务（`/api/viral/videos/import-tasks`）→ 每秒轮询，最多 120 秒（`ContentPages.tsx:1918-1935`）。
- 后端：上传意图带 sha256 时先尝试「同账号同文件」去重复用（`media.py:306-405`）；`script` 用途放开 15 秒上限、允许音频；`complete` 仅对 `replica` 用途自动排队 AI 拆解（`media.py:631-660`）。→ 见 **P2-04、P3-02**。

### 2.3 爆款视频库与详情（`studio/ContentPages.tsx` `ViralPage / ViralDetailPage`）

- 列表：抖音、视频号各取 `featuredOnly` 热门（`live.ts loadViralVideos`）。
- 详情：**进入详情页即 `POST /api/viral/videos/detail`**，服务端对「可用 + 未购买」的视频按 `viral_detail` 科目扣费，页面事后展示「本次查看详情扣除 N 积分」（`ContentPages.tsx:2069-2100, 2371`）。
- 提取文案：桌面端 claim-first（命中共享缓存即付「获取文案」费并秒回）→ 未命中本地抽音轨上传 → ASR 任务 → 完成后再 claim（生产者免费）。
- 去复刻：只允许 4–15 秒。→ 见 **P1-03、P2-05、P3-05**。

### 2.4 文案工坊（`CreationPages.tsx` `CopyPage`、`studio/scriptRewrite.ts`）

- 提取：`createScriptFromAudioTask` → 每 2 秒轮询，最多 5 分钟；`FAILED / SUBMISSION_UNCERTAIN` 视为失败。
- 二创：`rewriteProjectScript` → `waitForScriptRewriteTask`；`SCRIPT_REWRITE_SUBMISSION_UNCERTAIN` 不允许自动重试。
- 确认终稿 → 保存版本 → 可进入口播。

### 2.5 视频复刻（`CreationPages.tsx` `ReplicaPage` + `ReplicaFirstFrameSection` + `PromptEditor.tsx`）

- ① 上传参考视频（本地先卡 4–15 秒）或选择已有项目 → `purpose="replica"` 上传后自动拆解；会话号机制（`analysisSessionRef`）保证换源/重来时旧轮询作废，并取消旧拆解任务释放预扣。
- 拆解完成后读取 `analysis/latest` 与 `shot-cards/latest`，要求分镜版本的 `source_analysis_version_id` 与最新拆解一致，否则提示刷新。
- ② 首帧置换：主角人物 → 源画面选择 → 自动匹配人物参考 → 首帧生成与人工确认。
- ③ 文案确认 + 合成最终提示词 → 交接到 AI 视频页（独立任务通道）提交；旧的「复刻一键生成」后端仍在、前端无入口。

### 2.6 AI 视频生成（`StudioWorkspace.tsx submitVideoTask`，后端 `independent.py`）

- 前端：模式由首帧/尾帧/页面推导（`l2v` 前端硬禁用）；报价 → 指纹化幂等键 → `POST /api/independent/video-tasks`。
- 后端：幂等回放 → 数量上限 → 资产归属与类型校验 → R2V 参考素材累计时长 ≤15 秒 → 提示词结构门禁 → 建批 + 按秒预扣 + 入公平队列。能力接口目前**全部模式都返回开放**（`independent.py:104-113`），与旧文档中「扩展模式总开关」描述已不一致。→ 见 **P3-01**。

### 2.7 数字人口播（`StudioWorkspace.tsx submitOralTask`，后端 `oral_routes.py` / `oral.py`）

- 前端：必须先取得有效报价（`POST /api/oral/quote`，随文案变化重取）；当前**强制 `mode: "TTS"`**，素材库「用于音频口播」入口仍是断头（与 2026-09-21 文档一致，未修复）。
- 后端状态机：`QUEUED → SUBMITTING → RUNNING → ARCHIVING → SUCCEEDED`，旁路 `SUBMISSION_UNCERTAIN / ARCHIVE_FAILED / FAILED / CANCELLED`；前端映射：`ARCHIVE_FAILED` 显示「待核对」并提供归档重试。

### 2.8 人物库（`studio/PeoplePages.tsx`、`CharacterLibrary.tsx` 等）

- 人物列表分页 8 条，每个人物再并发拉头像、五视图与口播分身/声音（`live.ts:745-800`，**按人物串行 await**）。
- 声音克隆：前端校验 20MB、5–180 秒与扩展名白名单；后端 `VOICE_CLONE_UPLOAD_LIMIT = 20MB`、时长 5–180 秒，content-type 由前端按扩展名映射，两侧一致。

### 2.9 素材库（`ContentPages.tsx MaterialsPage`，后端 `materials.py` 虚拟视图）

- 五类来源（上传/项目/人物/口播成片/生成结果）；预览、下载、重命名、隐藏全部按后端下发的 `allowed_actions` 显示，前后端口径一致。

### 2.10 任务中心（`MainPages.tsx TasksPage / TaskDetailPage`、`TaskRecordsPanel.tsx`、`VideoResultStage.tsx`）

- 列表：首屏取生成批次 20 条 + 口播 20 条，之后每 20 秒静默轮询同样的「第一页」并与旧列表合并（`StudioWorkspace.tsx` 轮询 effect）。
- 状态映射（`live.ts:809-822`）：`NEEDS_ATTENTION / COMPLETED_WITH_FAILURES / FAILED` 一律为「失败」；只有「已完成」可预览/下载/保存/发布。
- 详情页预览只取批次中「首个可用结果」。→ 见 **P1-01、P2-03**。

### 2.11 发布管理（`ContentPages.tsx PublishPage`、`PublishRecordsPanel.tsx`，后端 `publish_records.py`）

- 选成片（必须已保存到素材库，`delivery == "stored"`）+ 封面 + 账号 + 立即/定时；记录状态 `queued → publishing → published / failed / cancelled`。
- 后端：同账号同视频在 `queued/publishing` 时拒绝重复；失败可重试（重置为立即发布）。→ 见 **P3-06**。

### 2.12 钱包、充值、个人中心、子账号（`customer/CustomerWalletPanel.tsx`、`CustomerCenterPage.tsx`、`SubAccountManagementPage.tsx`）

- 充值：创建订单 → 拉取支付码 → 订单轮询（2s 起指数退避、封顶 32s、窗口 5 分钟）。
- 余额不足（402 `INSUFFICIENT_CREDITS`）时，各创作入口统一打开钱包侧栏。
- 子账号共享母账号钱包（后端 `resolve_wallet_owner`），但**充值仅限母账号**（`recharge_routes.py:495-506`）。→ 见 **P1-04**。

### 2.13 管理端（`AdminApp.tsx`、`admin/*`、`api.admin.ts`）

- 独立构建、per-operator 会话 + CSRF；写接口统一走 `adminWrite`（理由 + 幂等键）。抽查公告、资费、激活码、退款、客户权益等写接口的字段语义，未发现与后端不一致之处。

## 3. 问题清单

严重度：**P1** = 影响付费交付或资金，用户可感知且难自救；**P2** = 业务流程出错或数据不一致，有绕行办法；**P3** = 体验、性能、边界或代码与注释不一致。

### P1-01 任务中心把「部分成功 / 待核对」的生成批次显示为「失败」，且详情页不出成片

- **证据**
  - `client/src/studio/live.ts:809-822` `studioTaskStatus`：`needs_attention_count > 0`、`COMPLETED_WITH_FAILURES`、`NEEDS_ATTENTION` 全部映射为 `"failed"`；`"uncertain"` 分支只判断批次状态 `SUBMISSION_UNCERTAIN`，但后端 `batch_status()`（`server/app/generation.py:7944-7967`）**从不**在批次层返回该值（子任务 `SUBMISSION_UNCERTAIN` 会被汇总成 `NEEDS_ATTENTION`），这个分支对生成批次永远不会命中。
  - `client/src/studio/MainPages.tsx:1701`：详情页只在 `task.status === "completed"` 时加载预览；下载、保存、发布按钮同样要求 `completed`（`MainPages.tsx:2013-2033`）。
  - `live.ts:882-910` `studioTaskFromBatch`（详情口径）把 `FAILED` 子任务（含已被付费重生成替代的旧任务）也算作「需关注」，而列表口径用后端的 `needs_attention_count`（不含 `FAILED`），**同一批次在列表与详情可能显示不同状态**。
- **触发**：一次生成 4 条，3 条成功 1 条失败 → 后端 `COMPLETED_WITH_FAILURES` → 任务中心显示「失败」，详情页显示「任务处理中或待核对，尚无可预览成片」。或某条子任务提交结果不确定（积分冻结待对账）→ 显示「失败」。
- **影响**：用户以为整批失败，看不到已付费的 3 条成片；冻结待核对的任务显示成「失败」，容易诱导用户重复提交并再次预扣。

### P1-02 成片「直链交付」没有有效期管理，直链失效后预览/下载/存素材库全部失败（需确认供应商直链有效期）

- **证据**
  - `server/app/generation_routes.py:801-845` `preview-url`：把数据库里的 `provider_result_url` **原样**返回给客户端，没有记录或校验过期时间。
  - `generation_routes.py:848-950` 归档（「保存到素材库」）同样依赖这个直链下载；下载失败统一返回 503「成片保存暂时失败，请重试；不会重新生成或扣费」。
  - 发布要求素材 `delivery == "stored"`（`publish_records.py:251-268`），也就是必须先保存成功。
- **触发**：成片完成后用户超过供应商直链有效期才去预览、下载或保存。
- **影响**：已扣费的成片永久不可得，而界面一直提示「请重试」，重试必然失败。另外直链域名会暴露数据源供应商，违反 AGENTS.md「对外响应保持中性」红线。

### P1-03 「查看爆款详情」计费口径冲突：前端按免费设计，后端进入即扣费，资费为 0 时直接 503

- **证据**
  - 前端注释写「详情免费后这里的失败只剩网络/下架」（`client/src/studio/ContentPages.tsx:2092`），但页面一进入就调 `openViralVideoDetail`（`ContentPages.tsx:2069`），扣费前没有确认，只在事后显示「本次查看详情扣除 N 积分」（`ContentPages.tsx:2371`）。
  - 后端 `POST /api/viral/videos/detail`（`server/app/viral_routes.py:1137-1243`）对「可用且未购买」的视频按 `viral_detail` 扣费，并调用 `require_priced_viral_service`：资费**未配置、停用或单价为 0 时一律 503**（`viral_search_routes.py:60-88`）。
  - 失败分支只设置错误文案，402 余额不足时不会打开钱包（`ContentPages.tsx:2087-2096`）。
- **触发**：运营按「详情免费」把 `viral_detail` 资费停用或设为 0。
- **影响**：所有首次查看的爆款详情页报「服务资费单价为 0，请联系管理员」；如果资费有效，用户点开卡片就被扣费，没有任何确认。

### P1-04 子账号余额不足时被引导去充值，但子账号无权充值

- **证据**：`isInsufficientCredits → openLive("wallet")` 出现在口播、视频、拆解等所有付费入口；`CustomerWalletPanel.tsx` 没有按 `account_type` 区分，子账号同样能看到「确认充值」。后端 `create_customer_recharge_order` 先执行 `_require_master_for_recharge`，返回 403 `MASTER_ACCOUNT_REQUIRED`（`server/app/recharge_routes.py:495-506`）。
- **影响**：子账号一路被引导到一个必然失败的操作，正确做法（联系母账号充值或提额）没有任何提示。

### P2-01 工作台超过 15 秒的视频本地抽音轨后，项目在服务端「没有来源」

- **证据**
  - `MainPages.tsx:624-643`：桌面端对超过 15.1 秒的视频只上传 `.m4a`，后端将其落为 `reference_audio`（`media.py:740-745`）。
  - `live.ts:1018-1040`：前端乐观地把它构造成 `reference_upload_status: "READY"`、`kind: "video"` 的项目来源。
  - 后端项目列表只认 `reference_video` 或项目上传目录下的 `video`（`server/app/rbac_routes.py:491-505` 以及客户分支的同一段 SQL），**音频来源不会成为 `reference_asset_id`**。
- **影响**：刷新或重进后，该项目在复刻页「选择已有项目」、项目素材里显示为无来源的空壳；如果草稿丢失，就无法再从项目重新发起「提取文案」。前端本地状态与服务端口径不一致。

### P2-02 草稿里的来源标识混用：`projectId` 会回退成资产 ID 或爆款 ID

- **证据**
  - `client/src/studio/StudioWorkspace.tsx:1926-1928`：`projectId = state.draft.projectId ?? state.draft.sourceId`，而 `sourceId` 在其他地方存的是资产 ID（`MainPages.tsx:684`）或爆款 ID `douyin-xxx`（`ContentPages.tsx:2203`、`MainPages.tsx:345`）。
  - 爆款详情页桌面端「提取文案」只做 `patchDraft({ sourceId: video.id })`，不清理旧的 `projectId / sourceAssetId`；命中缓存后的回填也「不动来源归属」（`StudioWorkspace.tsx applyClaimedViralCopy`）。
- **触发**：先在 A 项目工作 → 到爆款详情提取文案（缓存命中或中途失败）→ 回到文案工坊点「提取文案」（无显式来源参数）。
- **影响**：转写的是 A 项目的旧视频（并收取 ASR 费），或者请求 `/api/projects/{爆款ID}/script-from-audio` 得到 404。

### P2-03 任务列表轮询只刷新第一页，「加载更多」出来的任务状态永不更新

- **证据**：`StudioWorkspace.tsx` 静默轮询 effect 每 20 秒调用 `reloadTasks`（只取 `limit: 20` 的第一页），再以 `[...刷新结果, ...旧列表中未刷新的项]` 合并。
- **影响**：翻页加载的较早任务一直停在旧状态（例如一直显示「生成中」），合并后的顺序也会被打乱；生成批次接口整体失败时，只有口播部分被刷新。

### P2-04 上传去重复用不区分用途，也不会自动排队拆解

- **证据**：`server/app/media.py:306-405` `reuse_owned_completed_upload` 只按 `owner + sha256 + size + kind=reference_video` 复用，**不看原上传的 `upload_purpose` 和时长**；复用路径直接返回 `upload_required=False`，前端不再调用 `complete`（`live.ts:1018`），而自动拆解只在 `complete` 中触发（`media.py:631-660`）。
- **影响**：在复刻页重新上传曾经传过的同一视频时，不会自动开始拆解（与「复刻页上传自动拆解」的约定不一致，需要用户手动点）；复用资产继承的是旧的 `upload_purpose`。时长上限目前由前端本地检查和拆解入口兜底，暂未构成越权，但口径脆弱。

### P2-05 爆款导入轮询 120 秒超时后清除幂等键，再点一次会产生重复项目

- **证据**：`ContentPages.tsx:1918-1935` 超时抛出 `ViralImportPollingTimeoutError`；`viralImport.ts:48` 将其判定为「应清除幂等键」；后端每个新幂等键都会新建项目（`server/app/viral_import.py:187-192`）。
- **影响**：服务端导入较慢（排队、转存大视频）时，用户重试一次就多出一个空壳项目和一条导入任务；旧任务稍后完成，但已经没有任何前端在接收它的结果。

### P2-06 会话租约 90 秒即终态：电脑休眠或 WebView 挂起后被强制登出

- **证据**：`customer_session_service.py:395-440`，租约过期返回 `HEARTBEAT_EXPIRED` 且「不会复活」；前端心跳间隔 30 秒，无法覆盖系统休眠、合盖、WebView2 效率模式冻结脚本等场景。
- **影响**：用户合盖再打开即回到登录页，正在等待的拆解、生成、文案轮询都被打断（服务端任务继续执行并扣费，但前端结果要靠恢复逻辑才能找回）。

### P2-07 提交成功后的结果被 `isCurrent()` 静默丢弃

- **证据**：`StudioWorkspace.tsx submitVideoTask` 与 `submitOralTask` 成功返回后，只要草稿的 JSON 指纹有任何变化（`isCurrent()` 为假）就直接 `return`：不关闭弹窗、不提示、不记录 `videoBatchId`。文案提取成功但草稿作用域变化时同样静默返回（`StudioWorkspace.tsx:1990-2004`）。
- **影响**：已经扣费的任务在当前页面「消失」，用户可能再次提交。视频提交由于幂等键没有清空，会命中同一批次；口播或改了参数再提交则会真正重复扣费。

### P2-08 任务中心对「委派项目」里他人提交的批次也展示取消按钮，后端返回「批次不存在」

- **证据**：任务列表按服务端授权范围返回，包含委派项目（`live.ts:961` 的注释）；但 `cancel_generation_batch` 要求 `created_by_user_id == actor.id`，否则返回 404 `BATCH_NOT_FOUND`（`server/app/generation.py:6870-6875`）。
- **影响**：用户看到「批次不存在」这种令人困惑的报错；建议前端按 `created_by` 隐藏按钮，或后端返回 403 并附明确文案。

### P3-01 独立创作的验收限额检查在幂等回放之前执行，与代码注释矛盾

- **证据**：`server/app/independent.py:291-301` 注释写「幂等回放在此之前返回」，实际却先执行 `_enforce_acceptance_generation_limit`，之后才 `_find_independent_batch`。
- **影响**：仅影响配置了验收账号的环境。验收账号网络超时后用同一个键重试，会被「限额 1 条」拒绝，而任务其实已经创建。

### P3-02 爆款文案/详情的并发扣费锁粒度与计费主体不一致

- **证据**：`viral_routes.py:1042-1094` 与 `:1173-1205` 中，`source_id` 按 `wallet_owner` 计算，但 advisory lock 锁的是 `"billing:user:" + actor.id`。
- **影响**：同一母账号下的两个子账号同时首次获取同一条文案或详情，可以同时通过 `_copy_purchased` 检查，结果是重复扣费或撞唯一约束报 500。

### P3-03 成片归档上限 50MB 可能挡住 2K 成片（需数据确认）

- **证据**：`generation_routes.py:859` 规定成片字节数超过 `MAX_UPLOAD_BYTES`（50MB）即抛出 `VideoProbeFailed`，最终映射为 503「请重试」。
- **影响**：如果 2K、15 秒的成片超过 50MB，就永远无法保存到素材库，也就无法发布，而且提示用户「请重试」。

### P3-04 性能：人物库串行加载，项目列表无分页

- `live.ts:745` 对每个人物串行 `await`（每人 3 组签名请求 + 分身、声音列表），首屏加载时间随人数线性增长。
- `GET /api/projects` 不分页返回全部项目，前端 `slice(0, 24)`（`live.ts:521`）：项目多时请求很重，且复刻页「选择已有项目」看不到更早的项目。

### P3-05 爆款详情页没有扣费前确认；402 余额不足未引导充值

与 P1-03 同源。即便资费口径确定为收费，也应在首次进入前给出价格确认，与其他付费动作的「报价 → 确认」口径保持一致。

### P3-06 发布重试不校验账号状态，且会把定时发布变成立即发布

- **证据**：`publish_records.py:449-465` 的 `retry_record` 只检查记录状态为 `failed`，同时把 `scheduled_at` 置空。
- **影响**：账号登录态失效导致的失败，重试后会立刻再失败；原本定时的发布在重试后立即发出。另外，前后端各自用本机时钟校验「至少提前 2 分钟」，卡在边界时会在服务端 422。

### P3-07 代码与注释或文档口径不一致（文档债）

- `script_from_audio.py:97` 注释写「首次扣『获取文案』费」，而 `charge_viral_copy` 的实现是「生产者免费、非生产者首提付费」（2026-10-08 拍板），前端注释则写「交付免费（2026-10-04 拍板）」，三处说法不一致。
- `independent.py:104-113` 把能力全部写死为开放，2026-09-21 文档中的「扩展模式总开关」已不存在，`l2v` 只剩前端硬禁用。
- `generation.py` 取消批次的审计 `metadata.project_id` 对独立创作会写入字符串 `"None"`。
