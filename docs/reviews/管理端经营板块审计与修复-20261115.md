## 一、修复内容（代码，随本 PR 上线）

### M1 卡单核对队列（生产事故级）

**现象**：资金中心→卡单核对页 22,774 条记录全部来自同一个卡单
（generation `388023d4-f420-4239-868e-c2cd0a65591f`，video_768p，
2026-09-30 起，重查 1497 次，0 收口，客户积分被冻结 46 天）。

**根因**：部分唯一索引只护 `state='OPEN'`；条目升级 ESCALATED 后即脱离
冲突目标，扫描器每轮为同一卡单重建新行（新行继承计费行 created_at，
首轮重查即再升级，循环自我放大，约 3 分钟一行）。

**修复**：
- 迁移 `20261115T1900_billing_reconciliation_active_dedupe`：先折叠存量重复
  （每键保留 check_count 最高的一条），再把唯一索引扩到 `OPEN+ESCALATED`；
  DELETE 前拿 `LOCK TABLE ... EXCLUSIVE` 防滚动窗口并发 INSERT 致建索引回滚。
- 扫描器冲突目标同步扩展；ESCALATED 行只刷新证据、不重置状态。
- 重查熔断：`VIDEO_REPLICA_BILLING_RECHECK_MAX_COUNT`（默认 96 次 ≈ 两天），
  只限 ESCALATED（OPEN 不受限，保证升级/自动结算路径畅通）。
- 收口闭环：resolve 端点并入 AdminWriteContract（此前 extra=forbid 会让标准
  adminWrite 信封 422）；队列 UI 修复表头 `<tr>` 双重嵌套导致的列错位，补
  状态筛选、总数、行内收口按钮（409 原文透出）、过期响应丢弃。

**部署后运营动作**：迁移自动折叠 22,774 → 1 条。那个 46 天的老卡单仍需人工
按「下一步」指引走专项对账（核对供应商实况后结算或释放冻结积分）——涉及
真实客户资金，不在本 PR 自动处理。

### M2 成本目录缺配（月度毛利率报废的根因）

**现象**：本月 331 项、历史 1278 项"成本待核对"，今日成本/毛利永远"待核对"，
经营看板近 6 月汇总全表"待核对"。

**根因**：`quality_inspection`（图片及视频质量检查）、`analysis_repair`、
`analysis_repair_deepseek` 三个内部科目计费目录无单价（configured=false，
unit_cost_fen=NULL），运行时 `complete_attempt` 把这些调用记成 UNKNOWN。

**修复**：新 CLI `scripts/backfill_operation_costs.py`（登记 CW-057 清单）——
目录配好单价后运行，按 `usage × unit_cost_fen`（与运行时同口径）批量补记
billing_evidence，同人工单条补录的表与审计；默认 dry-run、`--apply` 才写、
500/批独立提交、并发撞行不回滚整批、幂等。

**运营步骤（上线后执行一次）**：
1. 管理端（或 `PUT /api/control/billing/tariff`）为三个科目配 `unit_cost_fen`
   （建议值见 §三 定价核对表）；
2. `python -m scripts.backfill_operation_costs --service quality_inspection \
   --actor-user-id <管理员users.id> --reason "质检单价已配置，按目录批量补录"`
   先看规模，加 `--apply` 落库；analysis_repair 同法。

### M3 待支付订单无人处理

**现象**：34 笔待支付订单（含 ¥2980，11/7 下单）挂 8 天，只有人工"查单补单"。

**根因**：查单补账/过期关闭的 CLI 挂在 systemd maintenance timer（每日一次），
而生产是 docker compose 部署、**timer 不存在**——兜底从未真正跑过。

**修复**：sweep 进 worker 常驻循环（`VIDEO_RECHARGE_SWEEP_INTERVAL_SECONDS`
默认 600s）：双 provider（wechat_native + zpay）掉单补账（网关确认已付→
幂等入账）+ 过期关闭（**只关本轮网关确认 unpaid 的单**——绝不关闭查单失败
或没轮到查的单，那会把可能的掉单关在门外）；候选页随机轮转防饿死；
autocommit 连接 + 会话级 advisory lock，外呼期间不持事务。

**部署效果**：上线后 10 分钟内第一轮 sweep 跑完，34 笔挂单要么补账、要么按
窗口关闭；此后不再需要人工盯。
